# 앱 네이티브 연결·오류 검수 — 2026-10-09

실제 진입: 루트 `App.tsx` → `src/hybrid/HybridShell.tsx` → 모바일웹. 이전 `src/screens/` 화면은 현재 앱 진입에서 사용하지 않음.

## 수정 내용

| 발견한 오류 | 수정 |
|---|---|
| WebView의 외부 링크 실행 실패가 비동기 예외로 남음 | 실패를 잡고 재시도 안내. 내부 같은 출처 주소는 앱에 유지 |
| 알림 permission/채널/저장/예약 실패가 예외로 남음 | 시작은 알림 상태 미확정으로 계속 진행. 설정 실패와 시험 발송 실패를 구분해 복구 안내 |
| 알림 켜기·끄기 요청이 겹치면 먼저 시작한 요청이 마지막 선택을 덮어쓸 수 있음 | 권한 요청과 설정 저장 직렬화. 마지막 끄기 선택을 보존 |
| 시험 알림 전송 요청만 해도 웹에서 성공 표시 | 실제 OS 예약 성공 뒤 `PREVIEW_NOTIFICATION_RESULT` 반환. 권한 거부/기기 처리 실패 결과 구분. 웹 소비 콜백은 루트 담당 |
| 시험 알림이 실제 목표 조회수 달성 소식처럼 표시 | 제목·내용·타입 모두 시험 알림으로 명시 |
| WebView는 호스트 뒤 `/`를 붙이는데 HTTP 오류 URL은 문자열로 비교 | URL 정규화 후 main-document 오류 비교. 사진 등 하위 자료 오류는 전체 연결 오류로 오인하지 않음 |
| 연결 실패 후 Android 뒤로가기가 이전 웹 상태를 사용 | 로딩 실패 때 뒤로가기 상태 초기화. 재시도 즉시 오류를 지우고 새 WebView 연결 |
| 앱 연결 오류 설명 12px·버튼 13px | 설명 16px/24px, 버튼 14px. 큰 글자·작은 높이에서 재시도 버튼에 닿을 수 있게 오류 영역 스크롤 지원 |

## 검증

- 실제 HybridShell 실행 코드를 모의 OS와 격리 React 상태로 호출한 회귀 검사 15개 통과. 단순 소스 문자열 검사만 한 결과가 아님.
- 정상 알림·권한 거부·채널/저장/예약 실패·동시 요청·시작 실패·공유 실패·외부 링크 실패·Android back/재시도·HTTP/렌더러 종료·iOS URL·브릿지 양방향 이벤트 정리 확인.
- `npm run typecheck` 통과.
- `expo export --platform all`로 Android와 iOS Hermes 번들 생성 통과. 마지막 수정 후 생성물은 `export-final/`.
- Expo 문서는 정확한 SDK57 참조와 WebView/알림 문서를 읽고 적용.
- 사용자 기기 저장소와 관리자 저장소 변경 없음. Git 업로드·유료 빌드·앱스토어 제출 없음.

## 실제 기기에서 남은 확인

현재 Windows에 Android SDK/adb/에뮬레이터와 연결된 실행 세션이 없고 iOS 시뮬레이터는 macOS 필요. 따라서 실제 네이버 앱/브라우저 복귀, OS 공유 시트, 키보드, 안전 영역, 큰 시스템 글자, 알림 허용/거부 화면을 직접 실행한 것으로 취급하지 않음. 위 결과는 네이티브 소스/오류 경로/번들 검사.

원격 조회수 알림은 서버 집계·중복 방지·푸시 토큰·발송 서버가 연결 전. 지금 시험 버튼은 기기 안 로컬 알림. GPS와 향후 챗봇 등 미연결 기능은 이번 오류 수정으로 완료된 기능이 아님.

검수 웹은 현재 `http://127.0.0.1:5210/`. 네이티브 개발 기본값은 기존 5173을 유지하므로 앱에서 이 검수본을 볼 때는 `EXPO_PUBLIC_SPOTLOG_WEB_URL`에 같은 Wi-Fi의 이 PC LAN 주소와 `:5210` 지정 필요. `127.0.0.1`은 실제 휴대폰에서 PC를 가리키지 않음. EAS preview/production은 기존 공개 HTTPS 주소 사용.
