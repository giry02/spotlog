# Spotlog 관리자 검수·서버 인수인계

2026-10-05 · 관리자 검수본 · 실서비스 서버 연결 전

**최신 보완:** 지역·스태프 등록/검수, 전체 원본/미디어, 기존 홈 추천 수정 초안, 운영 DAY·여행기 구성, 공개 신고/반응/번역/등급의 고객 연결을 추가. 개발 검수에서는 공개 투영을 고객과 교환하며 개인 자료는 분리. 실제 서버 연결은 별도. 최신 기능·검증은 [보완 결과](../../execution/ADMIN_WORKFLOW_FIXES_20261005.md), 서버의 양방향 연결 책임은 [고객·관리자 계약](CONSUMER_LINKS.md) 기준. 아래 계획 표의 범위는 유지하되 초기 ‘관리자 전용 자료에만 반영’은 보완 전 상태.

이 문서는 승인된 전체 관리자 계획의 검수 범위와 실제 서버에서 구현할 책임을 구분한다. 검수본의 저장·공개·조치·색인·시험 결과는 관리자 전용 로컬 자료에만 반영된다. 운영 데이터베이스, 회원 인증, 파일 처리, 지도, 맥미니, Flowise, LLM, 번역, 알림을 실제로 연결했다는 의미가 아니다. 최종 실제 검수 결과는 [구현 보고](../../execution/ADMIN_FRONTEND_IMPLEMENTATION_20261005.md)를 기준으로 판단한다.

## 원본과 식별자 규칙

- `placeId`는 실제 장소의 개별 지점이다. `companyId`는 선택적인 회사/브랜드 묶음이다. 같은 상호라도 주소·좌표·지점 ID로 비교한다.
- `mediaId`의 설명과 출처는 미디어 순서가 바뀌어도 함께 이동한다. 영상과 사진 모션을 같은 형식으로 간주하지 않는다.
- 공용 주변 추천 관계에는 랜드마크 `placeId`와 업체 `placeId`만 사용한다. 개인 일정의 `anchorVisitId`는 공용 연결 키가 아니다.
- 개인 일정의 `tripId/dayId/visitId`와 공개 여행기의 `journalId/cardId/commentId`를 구분한다. 같은 장소의 여러 여행기 댓글을 합치지 않는다.
- 모든 변경은 현재 전역 `expectedRevision`을 검증하며, Ops 대상은 별도 `entityRevision`도 검사한다. 중복 억제 키, 운영자, 시각, 사유, 변경 전후 상태를 기록한다. 서버는 요청의 운영자 이름이나 로컬 역할을 신뢰하지 않는다.
- 주소·좌표·종류·영업 상태·추천 조건은 DB 원본이 기준이다. RAG는 승인 설명을 찾으며, 모델은 존재하지 않는 장소·운영 사실·좌표를 생성하지 않는다.
- 원문 삭제·폐업·권리 철회는 원본 후보에서 먼저 차단한다. 색인 제거 실패나 이전 버전 복구가 자료를 다시 허용해서는 안 된다.

## 서버 연결 시 확인할 상태

| 상태 | 고객/운영자에게 표시할 결과 | 서버 연결 확인 |
|---|---|---|
| 검수 샘플 | ‘검수용’ 표시, 관리자 전용 로컬 결과 | 실제 서비스 변경·발송·모델 실행 여부 없음 |
| 미연결 | 연결 전 상태, 자료/집계 완료를 주장하지 않음 | 주소/지도/파일/회원/알림/모델 각각 설정 확인 |
| 빈 결과 | 현재 검색 조건과 다음 등록·조건 변경 행동 | 조회 성공 응답과 빈 items 구분 |
| 조회 실패 | 오류 안내·입력 보존·재조회 | 인증/권한/한도/timeout/5xx 구분 |
| 처리 중 | 작업 대상과 작업 상태 | jobId로 재조회, 브라우저 취소가 worker 중단을 뜻하지 않음 |
| 실제 성공 | 저장된 서버 revision과 작업 결과 확인 | 응답 검증, 작업 완료와 API 접수 구분 |
| 동시 수정 충돌 | 초안 보존·최신 자료 다시 확인 | 409, 기존 공개본/정책/색인을 덮어쓰지 않음 |

검수 자료의 집계값·응답 시간·외부 비용은 합성 예시다. 서버 연결 후에는 실측값, 집계 기간, 수집 시각과 출처를 표시한다. 문의의 답변 기록 저장과 실제 답변 전달, 알림 재시도 접수와 실제 수신, 후보 색인 시험과 실측 품질 결과를 각각 구분한다.

## 실제 소스 구현에 전달할 때

1. 이 검수본을 사용자가 검토하고 수정한 최종 동작을 확정한다. 코드와 문서의 미연결 표시를 함께 전달한다.
2. [API 규격](openapi.json), [DTO 규격](schemas.json), [합성 응답](fixtures.json), 자동 검사와 구현 보고를 같은 버전으로 전달한다.
3. 각 adapter 메서드를 운영 서버에 연결하고 서버 권한·동시성·중복 억제·작업 상태·응답 검증을 확인한다. 전체 검수 snapshot을 운영 서비스의 무제한 데이터 응답으로 사용하지 않는다.
4. 실제 자료 수급·회원 데이터·모델·알림·파일 worker 연결은 각 시스템의 책임자가 실측 증거로 검수한다. 샘플 검사 통과를 실제 서버나 AI 품질 완료로 취급하지 않는다.
5. 고객 챗봇은 기존 검색·추천·생성·수정·승인 저장 계약에 연결하며 이 관리자 구축과 별도로 진행한다.
