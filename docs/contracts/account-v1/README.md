# Spotlog 가입·동의 연결 계약 · 2026-10-08

상태: 로컬 프론트 검수본과 연결용 어댑터 구현. 실제 인증·서버·GPS 검색 연결 전. 사용자 정정: **일반 이메일 가입·로그인이 기본, Google·Apple은 추가 방식**. 운영 주체·주소·이메일 미정. `socialAccountService.ts`는 EMAIL/GOOGLE/APPLE을 모두 처리하는 현재 공통 계약이며, 이전 `accountService.ts`는 호환 시험용으로만 남김.

## 고객 흐름

- 2026-10-08 후속 사용자 요청으로 로컬에서 ID/비밀번호가 채워진 로그인 검수 기능 추가. DEV＋계정API미설정 때만 `reviewAccountService.ts` 사용. 화면에 ‘로컬 검수 계정/실제 서비스 회원 아님’ 표시, sessionStorage에 검수 로그인 여부만 보관. 실제 회원 인증·동의 증빙·메일 발송·소셜 로그인·계정 삭제로 취급하지 않음. 계정API설정 시 실제 어댑터 우선, 공개 빌드에 검수 계정/비밀번호/어댑터 포함하지 않음. [검수 로그인 수정](../../execution/ACCOUNT_LOGIN_REVIEW_20261008.md).
- 첫 방문은 공개 홈. 로그인 전 공개 장소·여행기 조회 유지.
- 비로그인 프로필: 회원 이름·등급·통계·알림 설정 없이 로그인/이메일 가입 제공. 기존 기기 기록은 별도 버튼으로 접근. 회원 프로필: 서버 세션의 이름·가입 방식과 계정 관리/로그아웃 제공. 기기 자료를 회원 자료로 자동 귀속시키지 않음.
- 일반 가입: **1. 약관 동의 → 2. 활동 이름·이메일·비밀번호/확인 입력, 같은 화면에서 인증번호 요청·6자리 입력·가입 완료**. 새 가입에서 별도의 인증 화면으로 이동하지 않음. 이메일 인증 하나만 사용하며 휴대폰 번호·SMS 인증은 요구하지 않음. Google·Apple은 추가 가입 방식 유지.
- 인증번호 요청 이후 입력한 네 항목은 유지하고 잠금. ‘이메일 · 가입 정보 수정’이나 약관 동의 변경 시 프론트의 대기 상태·번호 입력을 초기화하고 다시 요청해야 함. 약관으로 돌아가도 같은 팝업 안의 입력은 유지. 비밀번호는 컴포넌트 메모리에서만 유지하고 기기 저장소·로그에 기록하지 않음.
- 서버가 인증을 확인하고 회원 세션을 발급한 뒤 로그인 완료. 인증 전에는 회원 표시/댓글/응원/공개 권한 없음. 오입력·만료·재발송·이메일 변경은 같은 가입 정보 화면에서 처리. 이미 가입 요청 후 이메일 로그인에서 미인증409를 받은 경우만 별도 인증 복귀 화면 유지.
- 이메일 로그인과 비밀번호 재설정 안내 요청 제공. 현재 서버 미연결 상태에서는 실제 가입·로그인·이메일 발송 완료를 표시하지 않음.
- 실제 웹 연결: Google/Apple 선택 → 서버에서 인증 시작 → 제공자 인증 → 서버 callback → 기존 회원은 로그인, 신규 회원은 `PENDING_SIGNUP` → 정식 약관 동의 → 회원 생성.
- Google·Apple 버튼의 미연결/앱 연결 준비/인증 시작 실패는 로그인 화면에 남아 안내. 회원가입 또는 이메일 인증 화면으로 대신 이동하지 않음. 이메일·비밀번호 입력 유지. 신규 소셜 동의는 서버의 `PENDING_SIGNUP` 확인 후에만 표시.
- 신규 가입은 필수 약관·수집 이용·가입 연령 체크. 선택 마케팅은 기본 해제. ‘필수 항목만 동의’는 선택 항목을 체크하지 않음. 처리방침은 안내 문서로 구분하고 포괄 동의로 취급하지 않음.
- 가입 확인 화면의 동의는 소셜 제공자의 정보 제공 동의와 별개. OS GPS 권한도 별개. Google/Apple 버튼의 공식 로고·브랜드/플랫폼 규격은 실제 인증 활성화 전 최종 적용.
- 위치: 내 위치 주변 검색 선택 → 해당 목적·버전 동의 → 기기 권한 요청 → 1회 위치 사용. 거부·실패 시 수동 지역 선택. 가입 중 GPS 강제 없음.

## 기본 주소와 요청

`VITE_ACCOUNT_ENDPOINT=/api/account` 같은 동일 출처 서버 경로. 설정이 없으면 요청·가짜 회원 생성 없음. 실제 출처와 서비스 포트에 맞춰 연결. 외부 API 키·Apple 서명키·client secret은 프론트 환경변수에 넣지 않음.

| 메서드·경로 | 입력·출력 |
|---|---|
| GET `/social/session` | 기존 경로를 유지한 공통 세션. EMAIL/GOOGLE/APPLE 모두 `GUEST`, `PENDING_SIGNUP + social provider`, `SIGNED_IN + user` 중 하나. `user={id,displayName,email,provider}`. EMAIL 회원은 유효한 이메일 필수 |
| GET `/policies` | 운영자 정보, 최소 가입 연령, 문서 5개, `DRAFT/PUBLISHED`, 위치 기능 활성 상태. HTML 대신 구획별 텍스트 |
| POST `/oauth/google/start` | `{returnTo}` → `{authorizeUrl}`. Google 공식 HTTPS 호스트만 허용 |
| POST `/oauth/apple/start` | 동일. Apple 공식 HTTPS 호스트만 허용 |
| GET/POST `/oauth/{provider}/callback` | 서버 전용. 제공자별 응답을 검증. Apple callback의 POST와 Google 인증 코드 흐름을 반영 |
| POST `/social/signup` | 필수 동의·버전, 선택 마케팅 동의·버전. 신원을 브라우저가 제출하지 않고 서버의 pending session에서 확인 |
| POST `/email/signup` | `{email,password,displayName,consent}`. consent는 소셜 가입과 같은 버전별 동의 구조. 반환 `{state:'VERIFICATION_REQUIRED',email}`. 여기서 가입 완료/회원 세션 발급 금지 |
| POST `/email/verify` | `{email,code}` → 검증된 EMAIL `user`. 6자리·만료·시도 제한·pending 가입은 서버에서 확인. 성공 시 공통 회원 세션 발급 |
| POST `/email/verification/resend` | `{email}` → 204. pending 세션의 이메일 일치 검사와 재발송 간격·시도 제한. 최신 번호만 유효 |
| POST `/email/sign-in` | `{email,password}` → EMAIL `user`＋서버 회원 세션. 잘못된 인증401, 이메일 인증 미완료409. 프론트 저장 토큰 없음 |
| POST `/email/password-reset` | `{email}` → 204. 존재 여부를 드러내지 않는 동일 응답. 짧은 1회 재설정 링크 발송. 링크 검증·새 비밀번호 설정 페이지/API·세션 폐기는 서버 구현 범위로 남음 |
| POST `/sign-out` | `{}`. 서버 세션 종료 |
| POST `/delete` | `{confirmed:true}`. 서버에서 최근 인증·권한·확정 삭제 조건 검사 |

기본 샘플 `fixtures.json` 참조. 프론트 구현 타입 `web/src/socialAccountService.ts`와 약관 모델 `web/src/accountPolicies.ts`가 현재 DTO 기준. 문자열 외 HTML 실행을 허용하지 않음. 잘못된 상태·문서 누락·중복·초안 버전 공개는 오류. 정식 문서는 운영 주체·실제 기간·업체·국가·문의 경로가 확정되어야 공개 상태로 전환.

## 서버 인증·동의 책임

1. Google의 서명·발급자·대상·만료·계정 식별값 검증, Apple 코드 교환·서명·발급자·대상·만료 검증. 프로필 이메일을 계정의 고유 키로 사용하지 않음. Apple 비공개 이메일·일회성 이름 제공·이메일 미제공 처리.
2. 로그인 제공자＋제공자 계정 식별값 → 내부 `userId`. 이메일이 같다는 이유로 자동 계정 병합 금지. 계정 연결은 기존·추가 계정을 각각 확인한 명시적 연결 작업으로 별도 구현.
3. OAuth state·nonce 및 적합한 PKCE/코드 교환, 짧은 pending 세션과 회원 세션 구분, HttpOnly·Secure 쿠키, CSRF와 중복 제출 방지. 임의 외부 return URL 금지. callback에서 액세스/갱신 토큰을 URL로 전달하지 않음.
4. 가입 시 최신 공개 약관 버전과 필수 동의를 서버 재검증. 동의 대상 회원·항목·버전·서버 기록 시각·확인 방법과 철회 이력 보관. 프론트 시각·localStorage·초안 체크를 실제 동의 증빙으로 취급하지 않음. 미동의 pending 계정에 개인 자료 저장 권한을 부여하지 않음.
5. 약관 버전 불일치 `412`(기존 소셜 동의409도 호환): 가입 미완료 유지, 최신 문서 표시 후 재동의. 이메일 로그인409는 미인증 상태로 인증 화면 이동. 인증400/410은 틀린 번호/만료,429는 재시도 제한.401은 로그인 실패/기존 세션 만료를 구분. 실패·취소를 가입 성공으로 처리하지 않음.
6. 이메일 가입은 검증된 비밀번호 해시·가입 pending 세션·인증번호 해시·만료·재시도/발송 제한·중복 가입·계정 존재 노출 방지를 서버에서 구현. 인증 전 회원 자료 생성 금지. 비밀번호와 인증번호는 로컬 저장소·로그·관리자에 기록하지 않음. 같은 가입 팝업의 약관/정보 이동과 번호 요청 중에는 컴포넌트 메모리로만 입력 유지. 팝업 종료·로그인 성공·로그인/다른 가입 방식으로 전환 시 비밀번호 입력 제거.
7. 새 `/email/signup` 요청은 이전 pending 가입·번호를 원자적으로 교체하고 새 이메일·가입 정보·동의 버전에 결합해야 함. 재발송 시 이전 번호를 무효화하고 `/email/verify`에서 서버 pending 세션·최신 번호·이메일·유효 기간·공개 약관 버전을 함께 확인. 프론트의 정보 수정/대기 초기화만으로 서버 번호가 폐기됐다고 취급하지 않음. 중복·오래된 요청 결과로 이전 가입이 확정되지 않도록 서버에서 처리.
8. 위치 이용 기록은 원시 GPS와 구분. 서비스 사업 형태에 따른 위치기반서비스 신고·등록 대상, 확인자료 근거·기간, 보호 담당자·제공·통지 기준은 실제 GPS 연결 전에 확정. 위치 동의 취소와 OS 권한 취소를 각각 처리.

## 다음 실제 구현에 남는 부분

- Google OAuth 프로젝트, Apple Developer의 App ID/Services ID·도메인·redirect URL·서버 키 등록. 기존 모바일 앱에는 시스템 브라우저 인증과 복귀/deep-link 연결이 필요. WebView 내부 로그인은 현재 활성화하지 않음.
- 전역 세션/UI 분기와 callback 복귀 pending 동의 재개는 프론트 반영. 실제 서버 세션·계정별 찜/여행/댓글 저장·집계·권한 및 기기 자료의 명시적 가져오기는 연결 전. 기기 프로필·아이콘·등급을 실제 회원 이름·ID에 자동 합치지 않음.
- 메일 발송 서비스·도메인 설정, 이메일 가입/인증/로그인/재설정 처리, 실제 잠금·정지·세션 폐기. 비밀번호 변경 완료 페이지는 정식 재설정 링크 계약 확정 후 연결 필요.
- 선택 마케팅 철회·실제 발송, 내 위치 검색 화면과 서버 후보 조회 연결, 위치 동의 저장·철회. 이번 UI의 위치 미리보기는 실제 주변 검색이 아님.
- 국내 초기 검수안 만14세 이상과 글로벌 국가별 연령·보호자·법적 근거·국외 처리 절차 확정. 단순 연령 체크만으로 모든 국가의 요구를 충족했다고 취급하지 않음.
- 원본 GPS 전송 목적·수신자·파기 시점, 수탁업체·국가·동의/로그의 세부 보존 기간. 사용자 휴지통 달력6개월을 회원·위치·보안 로그 전체에 적용하지 않음.
