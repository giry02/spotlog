# AI·백엔드 협업 묶음 · v1 초안

2026-09-23 · 로컬 작업 · 실서비스 연결 전

**백엔드 개발자는 요청·결과 규격부터 구현, AI 담당자는 같은 시험 문장으로 Jev와 맥미니 모델을 비교.** 화면은 현재의 간단 생성 유지. 이 묶음은 협의 가능한 첫 계약이며 실제 서버 구현·AI 성능 검증 완료를 뜻하지 않음.

## 바로 나눠서 할 일

| 담당 | 시작 작업 | 끝났다는 기준 |
|---|---|---|
| 백엔드 개발자 | 계약 검토 → 회원 권한·placeId·자료 버전 → 초안/저장 API | 샘플 요청에 같은 구조 응답, 타인 자료·오래된 저장 차단 |
| 사용자 / AI 담당 | 맥미니에 묶음 복사 → 기존 Flowise 확인 → 로컬 해석 시험 → Jev 비교 | 100개 실제 결과 파일·오답 목록·전체 생성 시간 확보 |
| 함께 | 지역 1곳의 사용 허가된 장소 자료 선정 | 랜드마크·식당·숙박·좌표·출처를 실제 검수한 30~50곳 |
| 프론트 | 검증된 서버 어댑터 연결 | 입력 보존·DAY/식사 순서·실패 안내·최종 저장 확인 |

지역 자료 수집과 맥미니 설치는 이번 묶음에 포함되지 않음. 시험 카탈로그의 `fixture-*` 장소는 가상 자료이며 운영 DB로 옮기지 않음.

## 오프라인 검사

저장소 루트에서 실행. Python 3.10 이상과 `jsonschema` 필요. 이번 Windows 환경에서는 기존 설치본 사용. 맥미니에서는 별도 가상환경에 준비. 제품 의존성에 추가하지 않음.

```sh
python docs/contracts/ai-v1/validate.py
node docs/contracts/ai-v1/frontend-fixtures.mjs
python docs/contracts/ai-v1/evaluate.py 실제결과.jsonl
```

첫 명령은 묶음의 형식·정답 일관성·샘플 연결 검사. 두 번째는 현재 프론트 생성기·응답 검증기로 성공 샘플 재생성. 세 번째는 실제 모델 결과를 받아 채점. 어느 명령도 외부 AI를 호출하지 않음.

실제결과 한 줄: `{"id":"KO-001","prediction":정규화결과객체,"latencyMs":실측전체시간,"stageMs":{"classification":실측시간},"run":{"path":"jev-local","model":"실제모델버전","concurrency":1,"warm":true}}`. 실패한 요청도 `prediction:null`, `error:"timeout"` 등으로 남김. `latencyMs`는 요청 시작부터 검증된 초안 또는 최종 실패까지, `classification`은 조건화 완료까지. 시간 미측정 시 필드 생략. 예상 정답을 복사한 파일은 성능 결과가 아님.

개발용 70개·보류 평가용 30개로 구분. 같은 묶음의 보류 문장은 간단한 누수 방지용이며, 출시 전에는 새 고객 표현으로 별도 블라인드 평가 필요. 모델·프롬프트 수정 후 보류 정답으로 반복 튜닝하지 않음.

## 협의 후 고정할 값

- 1~7일·최대 랜드마크 30곳/전체 방문 60개: 현재 프론트 범위에 맞춘 v1 한도.
- 음식 기본 포함·카페 요청 시 포함·2일 이상 숙박 포함: 현 샘플 동작을 기준으로 한 **초기 정책 제안**, 고객에게 새로 확정받은 정책 아님.
- API 경로·시간 제한·모델 선택·정확도 목표·대형 보완 최대 1회: 구현 시 합의할 값. 비용·속도 보장 없음.
- UI 직접 선택 출처, 서버 revision, 구조화된 부분 결과: 프론트 연결 시 추가 작업. 현 로컬 검증기를 그대로 서버 정답 판정기로 쓰지 않음.
