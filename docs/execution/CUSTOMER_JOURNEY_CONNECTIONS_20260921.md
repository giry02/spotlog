# 고객 여정별 상세 연결도

최신 모델 정책(2026-09-21): **소형 모델 기본 · 대형 LLM은 미해결 부분만 보완**. 일정 계산·검증은 우리 서버, 모델 호출은 Flowise 경유. 데이터 부족·지도 장애는 대형 호출 대상에서 제외. 간단 생성 우선·챗봇 향후 추가 유지. [상세 호출 기준](AI_MODEL_CASCADE_20260921.md)이 아래의 단일 생성형 모델 설명보다 우선.

2026-09-21 · 목표 연결안 · 실제 서비스 연결 전 · 내부/외부 연결 명칭 구분

[FigJam 상세 연결도](https://www.figma.com/board/8IageUvocd3SaddRKOoCGi?node-id=15-379)

기존 개념도·기술 상세도 유지. 같은 보드에 세 번째 도면 추가. 전체 문구 메모체.

최신 적용 순서: **AI 간단 생성 우선 연결 → 챗봇은 향후 추가**. 초기 고객 여정에서 챗봇을 필수 관문으로 두지 않음. ‘AI 간단 생성’의 입력 글을 외부 생성형 AI가 인식하고 바로 완성 일정 초안 제공. 기존 7단계·도면 링크 유지.

## 순서와 연결

가로: 고객 여정 · 세로: 고객 화면 → 처리·연결 → 결과·저장

| 단계 | 고객 행동 | 처리·연결 | 결과·다음 전달 |
|---|---|---|---|
| 01 가입·로그인 | 가입 방식 선택 · 프로필 설정 · 로그인 | 내부 화면 → 인증 연동·Spotlog 서버 → 회원 확인 | 회원 ID·프로필·세션 → 개인 데이터 접근 |
| 02 발견·장소 탐색 | 장소·사진·영상·여행기에서 관심 장소 확인 | 초기: 우리 서버 → 장소 DB·공개 콘텐츠 조회. 향후: 별도 챗봇에서 문장으로 장소 추천 요청, 공통 검색 기능 호출 | 장소 카드·사진·위치 · 다음 단계에 placeId 전달. 초기 대화 세션 불필요 |
| 03 찜하기 | 마음에 드는 장소 찜 · 저장 목록 확인 | 내부 화면 → Spotlog 서버 → 회원 ID와 장소 ID 연결 · 중복 방지·해제 | 내 저장 장소 목록 · 같은 placeId로 재조회 |
| 04 AI 간단 생성 | 글 입력 또는 ‘저장 장소로 추천’ · 필요한 간단 조건만 보완 · 완성 초안 확인 | 우리 서버 → 자체 운영 Flowise·외부 생성형 AI가 글의 지역·기간·취향·식사/숙박 조건 인식 → 허가된 후보·근거 조회 · DAY·식사·숙박 구성 · 서버에서 지역·예약·ID 검증 | 완성 초안 → 선택 수정·저장 승인 → 비공개 내 여행 · tripId·visitId·버전. 초기 채팅 화면 없이 진행 |
| 05 상세 여행 다듬기 | DAY·순서 조정 · 음식점·숙소 추가/교체 · 부분 재생성 | 초기: 상세 화면 조작 → 우리 서버·DB, 부분 재생성은 같은 AI 기능 호출 → 서버 검증 · 내부 후보·외부 네이버 검색 · 지도·지원 경로. 향후 대화형 수정 추가 | 변경 확인 → 내 여행 저장 · 식사 전후 장소 연결 · 예약 숙소 유지 · 새 버전 |
| 06 여행기 등록 | 내 여행에서 여행기 시작 · 글·사진 추가 · 공개 범위 선택 · 미리보기 | 사진 → 우리 파일 저장소 · 우리 서버에서 소유권·공개 범위 확인 · 내 여행과 별도 기록 | 공개 여행기 · journalId·장소 카드 ID·사진 연결 · 비공개 원본 일정 유지 |
| 07 추천·스레드 | 공개 여행기 추천 목록 · 장소 카드 좋아요·댓글·답글 | 우리 서버 → 공개 가능한 여행기 조회 · 카드별 반응·댓글 저장 · 본인 수정/삭제 권한 확인 | 여행기 ID + 카드 ID별 스레드 · 다른 고객의 찜으로 순환 |

순환: 공개 여행기의 관심 장소 찜 → 03 저장 목록 → 04 나만의 AI 여행 생성.

직접 진입: 저장할 장소를 먼저 고르지 않아도 04 AI 간단 생성에 글·지역·기간으로 바로 요청 가능. 02·03은 선택 경로이며 필수 선행 절차 아님.

## 두 AI 진입점의 적용 순서

| 구분 | 진입·처리 | 공통 기능 |
|---|---|---|
| 초기 · AI 간단 생성 | 기존 입력창에 ‘부산 1박 2일, 맛집 포함, 숙소 제외’처럼 글 입력 → 조건 인식 → 완성 초안. 필수 조건이 부족할 때만 기존 지역·기간 등에서 보완 | 장소 조회·허가 설명 검색·일정 생성·검증·명시적 저장 |
| 향후 · 챗봇 인입 | 별도 대화 화면에서 추천 여행지 질문 → 장소 카드·찜 또는 일정 생성. 대화 세션·문맥 이어가기·대화형 수정 추가 | 초기 기능 재사용. 챗봇 추가 이후에도 간단 생성 유지 |

- 저장 장소는 선택한 장소를 기준으로 추천하는 기존 모드 유지. 일반 간단 생성은 글과 지역 조건으로도 진입 가능
- 초기부터 날짜·예약·음식점·숙소를 일일이 고르는 단계 추가 금지. 세부 선택은 생성 후 상세 수정에서 처리
- 맥미니 Flowise는 화면 뒤 실행 도구. 초기 간단 생성에서 활용 가능하며 챗봇 공개를 선행 조건으로 두지 않음
- 초기 요청 단위 처리에는 다중 턴 대화 세션 불필요. 입력·초안 복원과 저장 요청 중복 방지는 계속 적용
- 기존 대화형 연결안은 향후 확장 참고안. 최초 연결 순서는 이 문서와 전체 11장 목차의 최신 결정 우선

## 공통 연결 기준

- 내부 화면: React 웹 + Expo WebView 앱 · 모든 개인 데이터 요청에서 서버 권한 확인
- 내부 서버·DB: 신규 구축 · 로그인 제공자 미정 · 회원·장소·여행·반응의 기준 데이터 관리
- 자체 운영 도구: 기존 맥미니 Flowise · AI 모델·챗봇 화면 아님 · 초기에도 외부 AI와 내부 조회 도구 연결 가능 · 실제 Spotlog 연결 전
- 외부 생성형 AI: 초기 입력 글의 조건 인식·일정 생성, 향후 대화 문맥·답변 확장 · 기존 외부 모델 연결 있음, 정확한 제공자·모델 미확인
- 외부 임베딩 AI: 허가 설명·검색 문장을 검색용 숫자로 변환 · 제공자 미정 · 우리 서버에서 API로 호출 예정
- RAG: 허가 설명 → 우리 서버 → 외부 임베딩 AI → 우리 DB 검색 색인 · 장소 ID로 설명과 DB의 이름·좌표 연결
- API: 내부/외부 서비스의 호출·연결 방식. 별도 AI나 솔루션 이름 아님. ‘우리 서버 → 외부 임베딩 AI · API 호출’처럼 대상·방향과 함께 표시
- 음식점·숙소: 요청에 따라 처음부터 초안에 포함 · 생성 후 후보 선택·교체는 선택 작업
- 외부 네이버 Maps: 지도 표시·지원 자동차 경로 · 외부 네이버 API HUB 검색: 수정 단계의 업체 후보 조회
- 외부 검색 결과: 내부 장소 DB·RAG 자동 적재 제외 · 실제 연동 시 허용 범위에 맞춰 연결
- 사진: 서버 업로드 권한 → 우리 파일 저장소 → 실제 파일·소유권 확인 → DB에 사진 연결 정보. 외부 저장소 공급자 미정, 파일 데이터는 우리 서비스에서 관리
- 공개: 비공개 개인 동선과 공개 여행기 분리 · 여행기 등록·공개는 선택
- 스레드: Spotlog의 랜드마크·업체 카드별 댓글·답글 · 최신 댓글 위, 답글은 해당 댓글 아래
- 최신 여행·예약·권한: DB 기준 · 향후 챗봇의 대화 이력은 요청 맥락으로만 사용
