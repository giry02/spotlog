# 일반 가입 · 같은 화면 이메일 인증 · 2026.10.08

사용자 요청: 약관 확인 후 이름·이메일·비밀번호·비밀번호 확인을 입력하고, 같은 화면에서 인증번호를 받아 가입 완료. 해외 이용자를 고려해 문자 인증 대신 이메일 인증 하나로 구성. 로컬 검수본 반영, Git 업로드·공개 사이트 배포 없음.

## 적용한 흐름

| 단계 | 화면·행동 |
|---|---|
| 1. 약관 동의 | 필수 연령·이용약관·수집 이용 체크, 선택 이메일 소식 수신 기본 해제. 필수 동의 후 ‘동의하고 다음’ |
| 2. 정보·이메일 인증 | 활동 이름·이메일·비밀번호·확인 입력. 그 아래 이메일 인증 영역에서 ‘인증번호 받기’ |
| 번호 요청 후 | 같은 화면과 네 입력 유지, 입력 잠금. 서버가 반환한 이메일로 보낸 6자리 번호 입력·재발송 |
| 가입 완료 | ‘인증하고 가입하기’. 서버가 확인한 회원 응답과 세션 후에만 회원 화면으로 전환 |
| 정보 변경 | ‘이메일 · 가입 정보 수정’으로 잠금 해제. 대기 상태·기존 입력 번호 초기화, 새 번호 요청 필요 |
| 약관 재확인 | 같은 팝업 안의 입력 유지. 동의를 수정하면 대기 상태·번호 입력을 초기화하고 다시 요청 |

휴대폰 번호·SMS 가입 절차 없음. 일반 이메일 가입·로그인이 기본이며 Google·Apple은 추가 방식 유지. 이미 인증 대기인 고객이 이메일 로그인에서409를 받는 복귀용 인증 화면은 유지; 새 가입에서 추가 화면으로 이동하지 않음.

비밀번호는 같은 팝업의 컴포넌트 메모리에서만 유지. 팝업 종료·로그인 성공·로그인/다른 방식 전환 시 제거. 비밀번호·인증번호를 기기 저장소·로그·관리자 자료에 기록하지 않음. 기기 찜·여행·댓글·프로필과 관리자 검수 저장소 변경 없음.

## 실제 연결에 남는 부분

실제 서버 회원 인증·pending 가입·메일 발송·번호 만료/시도/발송 제한·정식 약관·운영 정보는 연결 전. 현재 운영자/주소/문의 이메일은 사용자 확인에 따라 미정이며 정책은 초안. ‘동의하고 다음’은 화면 검수 가능, 실제 번호 요청과 가입은 연결 및 정식 정책 준비 전 차단.

기존 API/DTO 유지: `/email/signup` → `VERIFICATION_REQUIRED`, `/email/verification/resend`, `/email/verify` → 확인된 회원. 새 가입 요청 시 서버가 이전 pending·번호를 원자적으로 교체해야 하며, 재발송은 최신 번호만 유효. 번호 검증은 서버 pending·이메일·가입 정보·동의 버전과 결합. 프론트가 대기 상태를 초기화한 것만으로 서버 번호까지 폐기된 것으로 취급하지 않음. [백엔드 연결 계약](../contracts/account-v1/README.md).

변경 파일: `web/src/AccountSheet.tsx`, `web/src/account-privacy.css`, DEV 검수 화면 `web/tests/account-state.tsx`. 기존 비로그인/회원 분기·전역 세션·기기 자료 분리·GPS 별도 선택 기준 유지.
