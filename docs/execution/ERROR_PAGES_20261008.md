## 실제 연결한 동작

- `error.html?type=...`: 독립 진입점. 요청 확인/이용 조건은 이전 화면,401은 기존 계정 로그인,403/404는 홈, 서비스/연결 오류는 다시 시도 제공. 홈·직접 링크의 이전 화면 버튼은 앱 루트로 복귀. 임의 외부 referrer로 돌아가지 않음.401로그인 성공/이미 확인된 회원은 기존 계정·화면으로 복귀하며 요청 자동 실행 없음.
- 앱의 알 수 없는 해시 주소는404, 잘못된 퍼센트 인코딩은400. 찾을 수 없는 여행/여행기/추천/편집ID와 빈 상세ID는404. 정상 화면의 기존 하단 메뉴·저장 동작 유지.
- `404.html`: 정적 호스트용 별도 빌드. 쿼리type과 관계없이404안내 유지. 중첩된 없는 주소에서도 `BASE_URL` 기준 홈 이동. GitHub Pages 배포 후 기본404파일로 사용 가능.
- `CustomerErrorBoundary`: 하위 고객 화면 렌더 오류에500페이지. 다시 시도 시 하위 화면 다시 구성, 홈 이동 가능. API 비동기 실패·이벤트 오류·초기 모듈 로드 전체를 모두 잡는 경계로 취급하지 않음. 원시 오류/스택과 고객 요청을 화면에 표시하거나 수집하지 않음.
- `AccountProvider`: 실제 세션 조회 실패의 응답 종류만 보관. 프로필에 공통 오류 인라인 안내와 수동 조회 재시도. 미연결을 네트워크 끊김으로 단정하지 않음. 기존401세션 해제·회원/기기 구분 유지.
- 가입·로그인·인증·댓글·여행 저장에서 처리한 실패는 기존 입력과 함께 안내. 모든API실패를 오류 페이지로 강제 이동하지 않음. 새 결제·구독·자동 재시도 기능 없음;402는 이용 조건 확인 안내만 제공. 신고/관리자 화면 변경 없음.

기존 CSS 토큰과 공통Button 사용. 설명16px·상태/버튼14px·제목22px·버튼44px 이상. 작은 화면 내부 스크롤·내용 줄바꿈, 접근 가능한 버튼 이름과 화면 제목 포커스/브라우저 제목 제공. 지원되지 않는type은404, 임의값을HTML로 출력하지 않음. 확인되지 않은 고객센터 연락처 생성 없음.

## 백엔드·배포 전달

페이지를 열었다는 사실은 서버에서 해당HTTP오류가 실제 발생했다는 의미가 아님. `error.html` 직접 조회는 일반200응답이며type으로 안내를 선택. 별도 서버는 상태코드·권한·재시도 제한을 올바르게 반환하고 화면 단위 조회 실패에공통ErrorPage를 사용. 쓰기 실패는 입력 보존·명시적 재시도 유지. 정적 호스트는 실제없는주소에404.html을HTTP404로 반환.

고객 전용 공개 범위에 `error.html`·`404.html`과 연결 소스를 포함하고 관리자 파일은 기존대로 별도 유지. 이번 작업은 공개/Git반영 전.
