## 우선 적용

기존 AI 여행 만들기의 간단 입력 유지. 원하는 여행을 글로 작성하면 생성형 AI가 조건을 인식하고, 실제 장소 후보로 완성 초안 제안. 저장한 장소로 추천받는 방식도 유지.

간단 입력 → 우리 서버 → 외부 Jev 조건 판별 → 서버 조건 검증 → 우리 DB·RAG 검색 → 우리 서버 일정 구성·계산 → 맥미니 소형 LLM 설명 → 서버 검증 → 완성 초안 → 상세 수정·저장

최신 모델 정책: **Jev 판별 · 소형 설명·미분류 해석 · 대형은 소형 실패 부분만 보완**. 필요한 입력·근거가 충분한 모델 해석·표현 실패만 대형에 전달하고 동일 검증 후 병합. 데이터 부족·지도 장애·불가능한 조건은 별도 대응. [호출 기준·부분 수정·모델 위치](AI_MODEL_CASCADE_20260921.md) 적용.

- 최초 화면: 요청 글 + 기존 지역·기간·여행 속도·이동수단 선택 + 저장 장소 활용
- 글로 바로 생성 가능. 찜·날짜·음식점·숙소 후보 선선택은 필수 아님
- 음식점·숙박 포함 여부와 제외 조건은 입력 요청에 맞춰 처리
- 결과: DAY·방문 순서·오전/점심/오후/저녁/숙박 역할 표시. 식사는 앞뒤 방문 장소와 연결
- 날짜·예약 시간·업체 교체는 생성 후 내 여행 상세에서 설정
- 닫기·실패 후 입력과 정상 초안 유지. 최종 저장은 사용자 선택으로 확정
- 초기에는 채팅 화면·다중 턴 대화·대화 이력 저장 불필요. 핵심 누락 조건만 기존 입력 필드에서 보완

## 글을 인식하는 예

입력 예: “부산 2박 3일, 맛집 포함하고 숙소는 빼줘. 많이 걷지 않게.”

| 인식 대상 | 구조화한 조건 |
|---|---|
| 지역·기간 | 부산 · 3일 |
| 음식점 | 일정에 포함 · 점심/저녁과 앞뒤 방문에 배치 |
| 숙박 | 추천·일정 배치에서 제외 |
| 여행 속도 | 걷기 부담이 적도록 후보·방문 수·거리 조절 |
| 정확한 출발 날짜 | 미입력 허용 · DAY 1~3으로 먼저 생성 |

정해둔 의미·포함/제외는 외부 Jev가 먼저 판별. 미분류·DAY별 예외 등은 원문과 정상 판별값을 보존해 소형 LLM으로 필요한 부분만 해석. 대형 LLM은 근거 있는 소형 실패만 보완. 맥미니 임베딩 AI는 허가된 설명과 요청의 의미 검색용 숫자 변환 담당. 모델과 한국어 품질은 실제 평가 후 확정.

입력문에서 확인한 조건은 기존 선택 항목과 결과 요약에 반영. 화면 기본값이 글의 명시 조건을 덮지 않게 처리. 사용자가 직접 바꾼 선택은 최종 조건으로 사용하되, 글과 충돌하는 경우 생성 전 같은 입력 화면에서 충돌 항목만 안내. 지역을 알 수 없는 경우 기존 지역 선택으로 보완. 불필요한 설문 단계 추가 제외.

## 내부에서 공통으로 만들 부분

| 공통 기능 | 우선 간단 생성 | 향후 챗봇 |
|---|---|---|
| 요청 해석 | 현재 입력문·명시 선택·저장 장소 | 현재 발화 + 필요한 대화 맥락 |
| 장소 조회 | 지역·거리·종류·순위·허가 설명 검색 | 같은 조회 기능 호출 |
| 일정 생성 | 실제 장소 ID 후보로 DAY·식사·숙박 구성 | 같은 생성 기능 호출 |
| 결과 검증 | 장소 ID·권역·예약·권한·최신 버전 확인 | 같은 검증 기능 호출 |
| 확정 저장 | 초안 확인 후 내 여행 저장 | 대화 결과를 같은 초안 화면에서 확인 후 저장 |
| 수정 | 상세의 DAY·방문·업체 선택으로 변경 | “둘째 날 점심만 변경”을 수정 요청으로 변환 |

공통 요청 데이터: 입력문, 확정 조건, 선택한 저장 장소 ID. 기존 여행 수정이면 tripId·버전·대상 DAY/visitId 추가. 회원·소유권은 서버에서 확인.

공통 응답 데이터: 인식한 조건, DAY별 방문·식사·숙박, 실제 placeId, 추천 근거, 미확인 항목, 초안 ID. 화면 진입 방식과 무관하게 같은 구조 사용. 구체 필드·경로는 백엔드 구현 시 확정.

Flowise는 맥미니에서 운영하는 AI 실행·도구 연결 소프트웨어. 챗봇 화면이나 AI 모델 자체와 별개. 초기에도 우리 서버가 Flowise를 호출해 간단 생성 처리 가능. 실제 운영 전 기존 흐름·모델·인증·접속 안정성 확인 필요.

## 향후 챗봇 추가

고객의 대화 입력 → 챗봇용 대화·맥락 처리 → 같은 우리 서버의 검색·생성 기능 → 장소 카드 또는 일정 초안

- 대화로 추천 여행지 탐색 → 관심 장소 찜
- “이 장소들로 2박 3일 만들어줘” → 기존 간단 생성과 같은 일정 초안
- “둘째 날 점심만 바꿔줘” → 해당 DAY·방문만 변경안 제안
- 대화 세션, 맥락 요약, 응답 스트리밍, 대화 실패·재시도 처리는 이 단계에서 추가
- 대화 이력은 보조 맥락. 최신 일정·예약·권한은 매번 우리 DB에서 확인
- 초기 간단 생성은 계속 사용 가능. 챗봇 완성을 초기 AI 출시의 선행 조건으로 두지 않음

## 구현 순서와 완료 기준

1. **간단 입력 연결**: 기존 입력·저장 장소 유지, 생성 요청·로딩·실패·초안 보존 연결
2. **조건 인식·후보 조회**: 지역·기간·식사·숙박·제외 조건 인식, 실제 DB ID 후보·허가된 RAG 근거 조회
3. **일정 생성·검증**: 완성 DAY 흐름 반환, 권역 혼합·없는 장소·확인하지 않은 경로 시간 차단
4. **상세 수정·저장**: 식사 앞뒤 방문과 숙박 역할 확인, 필요한 부분 수정, 사용자 선택 후 저장
5. **안정화 후 챗봇 확장**: 기존 생성 결과·데이터 규격 유지, 대화 진입·맥락 처리만 별도 연결

검수 사례: 글만으로 3일 생성 / 저장 장소로 생성 / 숙박 제외·음식점 포함 / 핵심 지역 누락 / 여러 권역의 저장 장소 / 후보 부족 / 생성 실패 후 재시도 / 상세 수정 후 저장 / 뒤로 가기·모달 닫기 후 복원.
