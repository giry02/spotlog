# 관리자 서버 응답 오류 안내 수정

공개 관리자 첫 조회에서 ‘관리자 API 응답이 JSON 형식이 아니에요’ 표시 재현. `admin.html`은 HTTP200이나 `/api/admin/v1/me`는 연결할 서버가 없어 HTTP404·HTML 페이지 반환. 관리자 응답 처리에서 HTTP 실패보다 자료 해석을 먼저 시도해 서버 미연결을 자료 형식 오류로 표시한 원인.

## 수정

- HTTP 실패는 상태를 먼저 구분. 404는 관리자 서버 연결 주소·설정 확인, 5xx는 서버 일시 장애·재시도 안내.
- 오류 응답이 HTML·일반 글·빈 내용이어도 원래 HTTP 상태 유지.
- 정상 상태 응답의 자료 해석 실패는 자료 읽기 안내. 파서·HTML 원문 노출 제외.
- 유효한 업무 오류의 코드·문구 유지. 객체로 잘못 온 오류 값은 기본 안내로 처리.
- 401·403은 본문을 읽기 전에 기존 인증·권한 차단 적용. 서버 확인 세션과 유효한 자료가 있어야 작업 화면 진입.

공개 범위는 관리자 `repository.ts`의 통신 처리 함수와 회귀 시험·이력 문서. 별도 로컬 관리자 개편과 오프라인 기능 포함 안 됨. 고객 앱 빌드 `customer-DS7NtBsI.js` 유지. 새 관리자 빌드 `admin-DAVsUwCH.js`.

## 검수

- 새 회귀 시험7개와 공개 범위 전체525개 자동 검사 통과.
- 독립 공개용 웹 타입 검사·빌드 성공, 기존 관리자 매뉴얼53화면 게시 유지.
- DEV에서404/503 HTML·200 HTML/잘못된 자료·401/403·빈 응답·업무 오류·복구 후 권한 상실·재시도 검수209개 통과.
- 독립 production 정적 배포본에서도 같은209개 확인 통과, JS예외0. 실제 인증 응답과 유효한 자료를 준 경우에만 복구되는지, 이후 권한 실패 시 다시 편집이 차단되는지 확인.
- 격리된 브라우저에서 고객/관리자 저장 자료 보존, 인증 전 편집·역할 전환 차단 확인.

실제 관리자 서버는 연결 전. 이 변경은 연결·응답 안내 수정이며 실제 회원 인증·서비스 DB 연결을 완료하는 작업과 구분. GitHub Pages에서 운영 자료를 관리하려면 관리자 인증·자료 API를 제공할 서버 연결 필요.

공개 재현과 검수 근거는 로컬 `artifacts/admin-json-20261017/`에 보관. Git·Pages 완료와 실제 공개 확인은 이후 실행 기록에 추가.
