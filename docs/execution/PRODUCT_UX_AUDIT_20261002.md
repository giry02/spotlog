# Spotlog 화면과 간편 여행 생성 검수

후속: 사용자 ‘변경해’ 승인으로 지적한 생성 범위·글씨·상단 중복을 로컬 반영. 최신 동작과 실측 결과는 [수정 보고](PRODUCT_UX_FIXES_20261002.md) 참고. 아래는 수정 전 검수 기록.

2026-10-02 기준. 검수 대상은 `C:/Users/Giry/Documents/Spotlog`의 통합 로컬 프론트, 주소는 `http://127.0.0.1:5210/`. 공개 사이트와 실제 소스 구현 대화창의 작업본은 이번 검수 대상과 구분.

핵심 저장·DAY 담기·AI 초안 생성은 간단하게 동작. 먼저 보완할 문제는 **여러 지역의 저장 장소를 짧은 여행 하나로 합치는 자동 생성**, 작은 기능 글씨와 옅은 안내, 내 여행 상단의 반복 정보. 큰 기능을 더 넣기보다 이 세 부분을 정리하는 편을 권장.

이번 작업은 화면 실조작과 기획 검토. 제품 소스·스타일 가이드·공개 화면을 변경하지 않았고, 아래 보완안을 실제 구현 대화창으로 승인된 요구사항처럼 전달하지 않음.

## 검수 범위와 확인 결과

Windows의 Edge 브라우저 자동화로 320·390·460px 폭에서 기본 화면 33개와 사용 흐름 48개 상태를 확인. 별도 새 브라우저 저장소에 기존 장소 12곳을 UI로 저장해 목록·기간 팝업·생성 결과 3개 상태를 추가 확인. **이 84개 상태에서 문서의 가로 넘침, 로드 완료된 이미지의 깨짐, JavaScript 예외는 발견되지 않음.** 자동 생성 결과의 품질은 별도 문제를 발견했으므로 이를 전체 기능 합격으로 해석하지 않음.

추가로 터치 입력을 모의한 사진 좌우·장소 위아래·7일 DAY 가로 넘김, 390×480px의 AI 입력/결과, 키보드 Tab/Escape와 입력 복원, 세 화면의 글자·줄 높이 200% 확대를 확인. 확대 화면도 문서 가로 넘침은 없었으나 실제 기기 글자 확대의 인증이나 모든 항목의 잘림 검증을 의미하지 않음. Android Chrome 실기기·주소창·실제 키보드는 미검수.

## 1 자동 생성의 지역 범위

재현: 사진에서 동백섬·해운대해수욕장, 제주 4곳, 서울숲, 안목해변, 경주 4곳을 저장 → 저장 화면의 **전체** 상태 → **바로 만들기** → **1박 2일 · 바로 만들기**.

결과: `서울 · 강원 · 경북 · 부산 · 제주 1박 2일 여행`이 생성됨. DAY 1은 서울숲 → 안목해변 → 대릉원 → 첨성대 → 월정교 → 동궁과 월지. 기간 팝업에 전체 12곳이라고 표시되지만, 생성 전에 지역을 좁히는 기능이나 이 조합의 장거리 이동을 확인하는 절차는 없음.

**우선 수정 대상으로 판단.** 가로 넘침이나 실행 오류가 없어도 ‘저장해서 쉽게 쓸 수 있는 여행’이라는 서비스 목적을 충족하지 못함. 실제 경로 API 연결을 기다리지 않고 프론트에서 생성 범위를 명확히 할 수 있음.

권장안:

- 이미 지역을 선택한 저장 목록에서는 그 지역을 그대로 사용. 같은 지역을 다시 묻지 않음.
- ‘전체’에 여러 지역이 있으면 기존 **여행 기간 선택** 팝업 안에서 이번 여행에 쓸 지역과 장소 수를 함께 표시. 새 화면이나 연속 팝업을 만들지 않음.
- 기본 지역을 제안하더라도 선택된 지역·제외되는 장소 수를 명확히 표시. 사용자에게 알리지 않고 임의로 일부 장소만 저장하지 않음.
- 여러 지역을 함께 여행하는 선택은 선택 사항으로 구분. 실제 이동 확인 전에는 짧은 기간에 가능한 여행처럼 확정하지 않음.

## 2 폰트와 버튼

전체 글자를 키울 필요는 없음. 여행기 읽기 본문, AI 입력, 일반 팝업 입력과 장소 이름은 16px로 확인. 작은 글씨는 주로 기존 페이지의 안내·메타와 일부 조작 버튼에 남아 있음. 현재 스타일 가이드는 기존 화면의 서로 다른 역할과 예외도 기록하므로, 작은 값이 있다는 이유만으로 모두 구현 오류라고 단정하지 않음.

| 역할·예시 | 실측 | 판단과 권장안 |
|---|---:|---|
| 여행기 읽기 본문 | 16px | 유지 |
| AI 문장·일반 입력·선택값 | 16px | 유지. 초기 입력을 축소하거나 복잡한 폼으로 되돌리지 않음 |
| AI 결과/내 여행 장소 이름 | 16px | 유지 |
| 주요 팝업 제목 | 20px | 유지 |
| 주요 팝업 행동 / 보조 행동 / 닫기 | 약48 / 36 / 44px 높이 | 현재 문서에 있는 역할별 규격과 일치. 모든 버튼을 52px로 통일할 이유 없음 |
| 홈 브랜드 설명·AI 생성 안내 | 11px | 이용 방법을 읽는 문장은 13~14px 검토 |
| 홈 AI 안내 윗줄 | 9px | 장식 문구를 줄이거나 의미 있는 안내는 12px 이상 검토 |
| 저장 카드 ‘여행에 담기’·‘DAY 1에 담기’ | 11px | 핵심 조작이므로 기존 보조 버튼 기준인 12px 검토. 버튼을 크게 만들기보다 글씨만 역할에 맞춤 |
| 주변 업체 종류 탭 | 11px | 맛집/카페/숙소는 선택 항목이므로 12px 검토 |
| 저장 카드 방문 시간·운영 확인 | 11px | 실제 결정에 필요한 정보는 12px 이상 검토 |
| 카드의 길게 읽는 설명 | 일부 11~12px | 짧은 메타와 구분해 13~14px 검토 |
| 사진 출처·지역/DAY 일부 메타 | 11px | 기존 예외. 본문·버튼 기준으로 무조건 확대하지 않음 |
| 작은 영문 장식·일부 수량 | 8~10px | 장식은 낮은 우선순위. 실제 이용 판단에 필요한 수량은 12px 검토 |

작게 느껴지는 데는 색도 영향을 줌. 홈 AI 안내 `지역·기간·취향을 적고 여행 초안을 받아보세요.`는 11px이며 흰 바탕의 `rgb(139,139,134)`로 대비 약3.42:1. 브랜드 부제는 약3.49:1. 이처럼 평평한 바탕에서 직접 확인한 설명은 색을 진하게 하는 보완이 필요. 이미지·그라데이션 위 텍스트의 실제 대비는 이번 단순 색상 계산에서 확정하지 않음.

일반 텍스트 대비 참고는 [WCAG 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). WCAG가 모든 글자에 공통 최소 픽셀 크기를 정하는 것은 아니며, 12/14/16px 권고는 내부 역할 기준과 실제 화면을 함께 보고 정한 제안. [글자 확대](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)와 [조작 영역](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)도 글자 크기와 별도로 확인해야 함.

실제 Windows 표시 글꼴도 확인. CSS는 `DM Sans, Pretendard, ...` 순서지만 홈 설명과 여행기 본문 한글은 **맑은 고딕**, 영문은 DM Sans로 렌더링됨. Pretendard를 별도 제공하지 않는 현재 구성에서 기기별 한글 모양이 달라질 수 있음. 이는 16px 선언이 다른 픽셀로 바뀌었다는 뜻은 아님. 글꼴을 강제로 교체하기보다 Android·Mac의 실제 화면과 비교 후 별도 결정할 항목.

근거: `platform-results.json`, `screen-results.json`, `flow-results.json`과 [기존 스타일 가이드](../STYLE_GUIDE.md).

## 3 레이아웃의 복잡도

### 내 여행은 목록에 빨리 도달하도록 보완

390px 화면의 AI 생성 여행은 표지 → DAY 탭 → DAY 설명 → 여행 중 안내/일정 조정 → 지도 버튼 뒤에 첫 장소가 나옴. 첫 카드가 화면의 약575px부터 시작. 320px에서는 여백과 줄바꿈이 더해져 목록이 더 늦게 나타남.

DAY 탭에는 날짜 미정 여행의 `DAY 1`이 위·아래로 반복되고, 상단에도 같은 여행 제목이 다시 표시됨. 항목 자체는 단순하지만 함께 쌓이면 현장에서 쓰는 화면이 길어짐.

권장안은 **개인 일정에 한정**해 중복 DAY 표기와 설명을 줄이는 것. 실제 출발 날짜가 있을 때는 DAY+날짜를 유지. 표지 축소 또는 접기, 안내/일정 조정/지도 도구의 정리는 다음 단계의 검수 후보. 승인된 여행기 읽기 화면과 홈 표지를 함께 바꾸지 않음. [현재 내 여행](../../artifacts/product-audit-20261002/private-ai-390.png).

### 장소 안내는 카드보다 소개가 앞서는 문제

지역 안내의 첫 장소 사진은 390px에서 약622px부터, 320px에서는 약722px부터 표시됨. 하단 메뉴는 770px부터여서 좁은 화면에서는 첫 장소의 이름·저장 행동을 보려면 먼저 스크롤해야 함.

큰 소개 문구를 줄이고 기존 검색·지역 선택을 가까이 묶는 국소 보완을 권장. 홈의 큰 소개를 같은 규칙으로 일괄 변경하지 않음. [320px 지역 안내](../../artifacts/product-audit-20261002/places-guide-320.png).

### AI와 주변 업체 팝업은 현재 방식 유지

최초 AI 입력은 사용자 확인을 거친 문장+4개 조건 구성을 유지. 음식점·숙박 후보는 완성 결과와 수정에서 다루는 방향이 맞음. 테스트 문장으로 부산·2박3일·여유롭게가 자동 반영되고, 음식점·숙박·카페 요청을 포함한 샘플 결과가 바로 표시됨. 이 확인은 로컬 규칙과 등록 자료의 동작이며 일반적인 한국어 AI 인식률을 증명하지 않음.

AI 결과의 종류 배지는 구분이 잘 됨. 내 여행에는 종류를 회색 글씨로 표시하므로, 기존 결과의 아이콘+배지를 작은 형태로 재사용하는 안을 검토할 만함. 모든 카드에 버튼을 더 넣는 방식은 권장하지 않음.

390×480px의 짧은 화면에서는 AI 결과 상단의 제목·설명·DAY와 저장 버튼이 대부분의 높이를 사용해 첫 동선을 보려면 스크롤해야 함. 버튼은 조작 가능하지만 결과 설명을 더 짧게 하는 개선 여지는 있음. 실제 모바일 키보드 동작과는 구분.

빠르게 화면을 이동할 때 이전 저장 안내 토스트가 다음 팝업에 잠시 남아 후보 설명 위에 보이기도 함. 클릭을 막는 오류는 재현하지 않았으나 새 맥락으로 이동하면 이전 안내를 정리하는 보완 후보. 사진의 기존 회색 배경 띠 문제는 이번 화면에서 재현되지 않음.

## 4 한 번의 조작 기준

아래 횟수는 버튼 선택 수. 문장을 타이핑하는 시간, 페이지까지 이동하는 비용, 선택 기간을 바꾸는 조작은 별도. 선택 DAY·기준 랜드마크가 정해진 상태의 반복 행동과 최초 여행 설정을 구분해야 함.

| 이용 행동 | 실측 횟수 | 판단 |
|---|---:|---|
| 사진에서 장소 저장 | 1 | 적합 |
| 선택한 DAY에 카드 담기 | 1 | 적합. 매 장소마다 팝업을 다시 열지 않음 |
| 저장 화면에서 기본 기간으로 바로 생성 | 2 | 방식 진입 → 기존 기간 확정. 기간 변경 시1회 추가 |
| 저장 화면에서 한 장소를 수동 배치 후 생성 | 4 | 방식 → 기간 확정 → 카드 담기 → 생성. 추가 장소는 같은 DAY에1회씩 |
| AI 입력 팝업에서 문장 작성 후 저장까지 | 2 | 초안 만들기 → 내 여행 저장. 홈에서 팝업을 여는 행동은 별도1회 |
| 랜드마크에서 주변 식당 담기 | 2 | 주변 업체 → 후보 담기. 열린 후보에서는1회 |
| 방문 완료 | 2 | 장소 메뉴 → 완료. 간결한 카드와 편의성 사이 개선 여지 |
| 음식점 한 곳 교체 | 4 | 메뉴 → 교체 → 후보 선택 → 확정. DAY·지역 재입력 없음 |
| 여행기 전체 언어 선택 | 1 | 직전 수정 검수에서 확인. 단락별 번역 선택 제거 |

핵심 저장·담기·간단 생성은 기준에 부합. 전체 서비스가 문자 그대로 모든 행동1회인 상태는 아님. 삭제·교체의 확인은 필요한 조작이므로 횟수만 줄이지 않음. **여행 중 자주 쓰는 완료는 현재/다음 장소 요약에 작은 직접 행동을 두는 안**이 적합. 이를 위해 모든 카드에 완료/교체/공유 버튼을 늘리지는 않음.

## 5 추가 기능의 우선순위

| 순서 | 제안 | 최소 범위 | 연결 필요 |
|---|---|---|---|
| 먼저 | 생성 범위·글씨·상단 중복 보완 | 위1~4의 기존 기능 정리 | 프론트에서 우선 처리 가능. 실제 이동 가능성은 서버 경로 검증 필요 |
| 다음 | 홈에서 최근 내 여행 이어가기 | 진행 기록이 있을 때만 작은 `내 여행 이어가기` 진입. 해당 DAY·방문을 바로 열기 | 같은 기기는 기존 로컬 상태 재사용. 다른 기기는 계정 동기화 필요 |

| 후속 | 동행자에게 일정만 공유 | 여행기를 쓰지 않고 DAY·장소를 읽기 전용으로 전달 | 실제 공유는 서버 연결 필요 |

후보 비교와 동행자 공유는 [09/30 기획 검토](PRODUCT_FEATURE_REVIEW_20260930.md)의 후속 제안을 재평가한 것. 방문 완료·한 곳 교체·경고 수정은 [09/30 로컬 검수본](TRIP_USABILITY_REVIEW_20260930.md)에 이미 구현되어 있어 신규 기능으로 다시 제안하지 않음. 오프라인 보기와 제보도 기존 후속안이며 이번에는 우선순위를 올리지 않음.

추천 적용 순서는 **여러 지역 자동 생성 보완 → 작은 기능 글씨/안내 색 보완 → 내 여행 상단 간결화 → 최근 여행 진입/업체 비교**. 최초 AI 입력 항목을 추가하거나 새 메뉴를 만드는 방향보다 현재 동작의 품질을 높이는 방향.
