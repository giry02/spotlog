# 맥미니 로컬 AI 가능성 판단 · 조건 추출 중심

2026-09-23 · 사용자 질문에 대한 기술 검토 · 설치·실측 전 제안

## 판단

현재 간단 생성의 지역·기간·여행 속도·이동수단 인식과 등록 장소 검색은 로컬 소형 모델로 우선 검증할 만한 범위. 맥미니 RAM 64GB는 4B·9B 양자화 모델과 소규모 검색 DB를 시험하기에 메모리 측면에서 여유 있는 조건으로 판단. 칩·OS·문맥 길이·동시 요청·개발 도구 사용량을 확인하기 전 응답 시간이나 실제 고객 처리량은 확정하지 않음.

전체 여행 품질을 필드 네 개의 추출 정확도로 판단하지 않음. 식사 앞뒤 방문, 숙박 거점, 이동 가능성, 예약 보존, 장소 데이터 품질은 별도 구현·검증 대상.

## 작업별 담당

| 작업 | 처리 방식 |
|---|---|
| 고객이 화면에서 직접 선택한 네 항목 | 확정된 값으로 서버 검증·조회. 재해석용 AI 호출 생략 가능 |
| 고객 글에서 같은 항목·포함/제외 인식 | 짧은 로컬 소형 모델 호출, 고정 출력 형식, 원문 근거·미입력 상태 포함 |
| 장소명·지점·주소·좌표·순위·종류 필터 | 원본 DB·별칭·ID 조회. 모델이 원본 값이나 ID를 생성하지 않음 |
| 조용한 분위기·바다 전망 등 설명 검색 | 실제 설명·태그를 근거로 로컬 임베딩·의미 검색 적용 |
| DAY·동선·점심/저녁·숙박 배치 | 서버의 일정 규칙·거리/경로·시간 계산. 데이터 미확인 표시 |
| 추천 이유 | 검증된 근거의 짧은 설명. 초기에는 정해진 문장 조합도 가능 |

선택 필터만 다루는 첫 연결은 원본 DB 검색으로 시작 가능. 의미 검색은 자유로운 취향을 설명 자료에서 찾을 때 추가. 기존 UI의 글 입력·저장 장소 추천·완성 초안 우선 원칙 유지.

예시 입력: 부산 2박 3일, 렌터카로 여유롭게. 식당 포함하고 숙소는 빼줘.

예시 조건: 부산 / 2박·3일 / 여유롭게 / 자동차 / 식당 포함 / 숙소 제외. 이후 장소 ID·좌표·순위는 원본 DB에서 조회하고 일정 배치는 코드로 처리.

숫자·박/일 환산은 코드에서 검증. 입력에 없는 값은 미입력으로 반환. 글의 명시 조건을 기본 선택값이 덮지 않도록 하고, 사용자 선택과 충돌할 때 해당 조건만 확인.

## 로컬 모델 시험안

- 기존 9B 우선 제안에 **조건 추출용 4B 비교** 추가. Qwen3.5 4B와 9B를 같은 한국어 자료로 각각 평가해 한 모델 선택. 매 요청 4B→9B→외부 모델 연쇄 호출안 아님.
- Ollama 배포의 Q4_K_M 다운로드 크기: 4B 약 3.4GB, 9B 약 6.6GB. 실행 RAM 수치가 아니며 OS·문맥·동시 요청·DB·개발 도구 메모리 추가 필요.
- 언어 모델은 문장→조건 변환을 우선 평가. 짧은 출력과 제한된 문맥, 직접 응답 모드부터 비교. 긴 사고 과정·전체 장소 DB를 매번 입력하는 방식은 초기 범위에서 제외.
- JSON Schema로 출력 형태 제한 가능. 형식이 맞아도 부정·기간·장소 의미가 틀릴 수 있어 의미 검증 별도.
- 기존 Flowise 재사용. 로컬 실행은 Ollama, 의미 검색 추가 시 Qwen3 Embedding 0.6B와 PostgreSQL/pgvector 후보 유지.
- M시리즈 Apple GPU 지원과 Intel CPU 실행의 차이를 확인. Ollama 공식 macOS 요구는 Sonoma 14 이상.

근거: [Ollama 4B](https://ollama.com/library/qwen3.5:4b), [9B](https://ollama.com/library/qwen3.5:9b), [구조화 출력](https://docs.ollama.com/capabilities/structured-outputs), [macOS](https://docs.ollama.com/macos).

## Jev와 비교

- TypeSafe Jev는 선택·점수·참/거짓 등 범위가 정해진 판단에 맞는 후보. 지역/기간의 지원 목록, 여행 속도, 포함/제외처럼 답의 범위가 정해져 있으면 적용 검토 가능.
- 자유로운 업체명·예약 장소 같은 값은 후보·문자열 구간을 먼저 찾고 선택하게 하거나 별도 추출기 필요. 공식 자료도 후보 추출 후 선택 방식을 설명.
- 소개문 생성·정확한 날짜/거리 계산을 Jev 하나에 맡기지 않음. 한국어는 자체 평가 필요: 공식 모델 문서는 영어에서 가장 좋은 정확도를 설명하고 다른 언어의 동일 성능을 보장하지 않음.
- 공식 확인 경로는 TypeSafe의 외부 호스팅 API. 공개된 로컬 배포·모델 다운로드 안내는 확인하지 못했으므로 Jev 자체가 맥미니에서 실행된다고 표시하지 않음. 별도 계약 제공 여부는 미확인.
- 따라서 맥미니 내부 실행이 목표라면 다운로드 가능한 로컬 소형 모델부터 평가. Jev는 같은 한국어 평가집으로 성능·비용·연결 의존성을 비교할 선택지이며 필수 도입 아님.

근거: [Jev 기본 형식](https://docs.typesafe.ai/primitives), [공식 연결 방법](https://docs.typesafe.ai/introduction/quickstart), [언어 지원](https://docs.typesafe.ai/models), [현재 한계](https://docs.typesafe.ai/model-jaggedness/jev-1.13), [후보 값 선택](https://docs.typesafe.ai/cookbooks/pre_parsed_value_extraction_cookbook).

## 실제 채택 시험

1. 사람이 정답 조건을 적은 한국어 문장 100개 준비. 기존 20~30개 시작 평가집을 확대하는 제안.
2. 기본 요청, 오타·구어체, 미입력, 글/선택 충돌, 부정·포함/제외, 특정 지점, DAY별 부분 수정 포함.
3. 4B·9B 각각 조건별 정확성, 전체 조건 일치, 불필요한 추측·추가 질문, 응답 형식 검사.
4. 잘못된 장소 ID·좌표 생성, 명시 제외 위반은 별도 실패로 기록. 모델 확신 점수만으로 통과시키지 않음.
5. 동시 생성 1건부터 3건·5건으로 늘려 지연·대기·메모리 측정. 프론트 개발 도구를 함께 켠 상태도 확인.
6. 시험 데이터와 분리한 문장으로 재확인하고 모델·프롬프트·버전 고정. 외부 대형 보완은 실제 모델 실패가 누적된 뒤 기존 정책대로 연결.

개발·검수 서버로 맥미니 우선 사용 가능하다는 판단. 실제 상시 운영은 부하·절전/재시작·회선·백업·장애 대응을 확인한 후 결정. 지도 등 외부 연결이 포함된 전체 서비스의 오프라인 동작을 의미하지 않음.

현재 범위: 공식 문서 조사와 판단 기록. 모델 설치·맥미니 접속·한국어 정확도/속도 실측·제품 코드·Git·배포 변경 없음.
