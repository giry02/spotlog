# 고객 프론트 업로드 · 2026-10-06

사용자 요청: ‘관리자 제외하고 올려’. 기존 전체 로컬 백업 `b0b623aaacbf6835cdbfea96dfadbc3bddfc6081`을 바탕으로 고객 프론트 최신 변경만 독립 브랜치 `codex/customer-frontend-20261006`에 반영.

## 포함

- 공개 여행기·댓글·작성자·장소·사진 신고 버튼과 신고 팝업, 사유/중복 접수/실패 처리. 개발 환경에서는 기기 검수 접수, 실제 신고 API 연결 전에는 서비스 성공으로 표시하지 않음.
- 공개 여행기·홈 추천·샘플 댓글 자료를 고객 공용 모듈로 정리. 공개 반응·출처·영어 검수 설명·등급 기준을 고객 화면에 사용하는 연결부.
- 개인 여행 복사/여행기 생성 시 원본 공개 작성자 ID를 이어받지 않는 보완. 기존 개인 메모·예약·동선과 공개 신고 자료 분리.
- 고객용 공용 DTO `publicServiceTypes.ts`: 고객 코드에서 관리자 폴더 타입 참조 제거. 관리자 화면 없이 TypeScript/Vite 빌드 가능.
- 관련 고객 검사와 기존 고객 프론트 전체 코드/사진/문서/네이티브 셸은 기존 백업을 기준으로 유지.

## 제외

- `web/admin.html`, `web/src/admin/`, 관리자 CSS·검수 그림·관리자 테스트·계약·검수 문서.
- 관리자 추가용 Vite 다중 진입점, 관리자 스타일 가이드/인수인계 수정, FigJam 관리자 수정 자료, AI/RAG 계획 문서의 미업로드 변경.
- 서버·인증·DB·AI·사진 업로드 연결과 공개 사이트 배포. 실제 소스 구현 대화로 자동 전달하지 않음.

## 확인

- 관리자 소스/진입점이 없는 독립 작업본에서 `npm --prefix web run build` 성공. 생성 결과에 관리자 HTML/JS/CSS 없음.
- 고객 공용 자료·신고 API 검증·개인 자료 비노출·등급·여행 복사·폰트 등 **40검사 통과**.
- 격리 Edge: 320/390/460px × 홈/여행기/장소 사진/내 여행/저장 **15화면**에서 가로 넘침·깨진 이미지·브라우저 예외 없음. 공개 여행기 신고 사유 선택→로컬 검수 접수 확인.
- 기존 통합 로컬 작업본 TypeScript 검사 성공. 관리자 원본과 사용자의 실제 저장 데이터 유지.

## 실행

`npm ci` → `npm --prefix web run dev`. 웹 빌드는 `npm --prefix web run build`.

실제 신고 연결은 `VITE_REPORT_ENDPOINT`에 같은 서비스의 경로를 지정. 서버가 아직 없으면 개발 검수와 실제 접수를 구분하며, 운영 빌드는 연결 전 상태로 유지. 신고/공개 자료 형식은 `web/src/publicServiceTypes.ts`, 전송·응답 검증은 `web/src/reportService.ts` 참조. 모델/API 키를 프론트에 넣지 않음.
