# 휴지통·삭제 복구 사용자 흐름

최종 반영: 2026-09-19 · **보관 기간 6개월 확정** · 로컬 프론트 구현, 서버 연결 전

사용자는 4주차 남은 항목과 3차 프론트를 로컬에서 이어서 구현하도록 요청했다. 보관 기간의 최초 답변인 1개월을 **6개월**로 정정했으므로 최종 답변을 적용한다. JSON 파일 백업·복구 메뉴는 만들지 않는다. GitHub 업로드나 공개 반영은 이번 범위가 아니다.

## 1. 대상과 진입

- **개인 일정과 여행기 한 건 전체**를 각각 관리한다. 개인 일정에서 만든 여행기를 지워도 원래 일정은 유지되고, 일정 삭제도 연결된 여행기를 함께 지우지 않는다.
- 소유한 개인 일정/여행기 상세의 메뉴에서 ‘휴지통으로 이동’을 선택한다.
- ‘글·사진·DAY 일정이 함께 6개월 동안 보관됩니다’ 안내와 해당 제목을 확인한 뒤 이동한다. 공개 여행기는 공개 목록과 공유 경로에서도 숨겨지고 비공개로 복원된다는 설명을 추가한다.
- ‘내 여행 → 휴지통’에서 다시 찾는다. 내 여행 목록이 비어 있어도 휴지통 진입은 유지한다.
- 개별 DAY·방문·글·사진 편집은 기존 변경 취소 흐름을 사용한다. 북마크 해제는 휴지통 대상이 아니다.

## 2. 6개월의 정확한 기준

| 항목 | 동작 |
|---|---|
| 보관 시작 | 삭제가 저장된 시각 |
| 보관 종료 | 한국 시각 기준 달력 6개월 후 같은 일자·시각 |
| 종료 월에 같은 날짜가 없음 | 그 달의 마지막 날짜로 조정. 8월 31일 → 이듬해 2월 28일, 윤년이면 29일 |
| 시간대 변경 | 종료 시각을 UTC로 저장하고 화면에는 한국 시각(KST)으로 표시. 기기 시간대를 바꿔도 종료일이 변하지 않음 |
| 종료 순간 | 보관 종료 시각부터 복원 불가. 정확히 같은 시각에 누른 복원도 거절 |
| 목록 | 보관 기간이 남은 내 항목만 최근 삭제 순으로 표시 |

6개월을 180일로 대체하지 않는다. 삭제 시각과 종료 시각을 한 기록에 함께 저장한다. 프론트의 현재 로컬 시연은 기기 시계를 이용한다. **실서비스의 삭제·만료 판정과 모든 권한 검사는 서버 시계를 기준으로 해야 한다.**

## 3. 목록과 항목 상세

휴지통은 기존 하단 모달을 재사용한다. 목록·선택 항목·영구 삭제 확인은 하나의 모달 안에서 전환한다. 키보드 포커스, 뒤로 가기, 닫기는 기존 BottomSheet 동작을 따른다.

- 목록: 내 여행/여행기 구분, 제목, 지역, 여행 기간, 정확한 보관 종료 일시.
- 상세: 제목, DAY 수, 장소 수, 삭제 일시, 보관 종료 일시.
- 행동: ‘복원’, ‘영구 삭제’. 영구 삭제는 별도 확인 단계를 거친다.
- 빈 상태: ‘휴지통이 비어 있어요. 삭제한 내 여행과 여행기는 여기서 다시 찾을 수 있어요.’
- 완료: 복원·삭제 결과 안내. 복원 후 ‘여행 보기’로 바로 돌아갈 수 있다.
- 같은 화면을 계속 열어 둔 동안에도 1분마다 보관 상태를 갱신하고, 복원 버튼을 누르는 순간 정확한 만료 시각을 다시 확인한다.

## 4. 복원 규칙

삭제 당시 기록 전체에 삭제 표시를 함께 보관한다. 별도의 복사본을 만드는 방식이 아니다.

- 기존 여행 ID, DAY ID, 방문 ID, 카드 ID를 유지한다.
- 제목·본문·대표 사진·첨부 사진·캡션·DAY 순서·담은 장소·예약 고정·메모·연결 정보를 유지한다.
- 저장 목록의 북마크나 다른 여행에 담은 같은 장소는 변경하지 않는다.
- **모든 복원은 비공개다.** 공개 여행기의 `PUBLISHED` 상태는 `PLANNING`으로 돌아온다. 계획 중·여행 중 상태는 유지한다.
- 저장된 편집 초안 역시 비공개로 조정하여 초안을 이어 쓸 때 자동 공개되지 않는다. 초안의 작성 내용은 그대로 보존한다.
- 이미 복원된 항목에 다시 요청하면 새 여행을 만들지 않는다.
- 복원 뒤 다시 삭제된 기록에 예전 삭제 화면에서 요청하면 상태 변경 안내와 함께 중단한다.

## 5. 영구 삭제와 만료

영구 삭제는 선택한 **한 항목**에만 제공한다. ‘글·사진·DAY 일정을 다시 복원할 수 없다’는 확인과 취소 버튼을 제공하며, 최초 버전에는 휴지통 전체 비우기를 넣지 않는다.

현재 로컬 구현은 영구 삭제를 확인하면 해당 여행 기록 한 건을 제거한다. 같은 사진을 쓰는 다른 여행, 저장한 장소, 원본/복사 여행을 함께 제거하지 않는다. 외부 이미지 파일이나 공유 이미지 자산을 직접 삭제하지 않는다.

만료한 기록은 일반 화면 및 휴지통 복원 목록에서 제외하고 복원을 차단한다. **로컬 앱 시작 시 만료 기록을 물리적으로 지우는 정리 작업은 실행하지 않는다.** 실서비스에서는 서버 정리 작업이 만료 기록을 제거하고, 사진 파일은 다른 기록에서 사용하는지 확인한 뒤 정리한다. 서버 장애 복구용 백업 보존 기간은 이 사용자 휴지통의 6개월과 별도다.

## 6. 예외와 저장 실패

| 상황 | 처리 |
|---|---|
| 삭제·복원·영구 삭제 저장 실패 | 기존 목록과 선택 항목을 유지하고 다시 시도 안내 |
| 중복 누름 | 진행 중 요청 차단, 기존 ID로만 복원 |
| 이미 복원됨 / 영구 삭제됨 | 중복 기록을 만들지 않고 현재 상태 안내 |
| 보관 기간 만료 | 복원 거절. 목록에서도 제외 |
| 다른 소유자 | 목록에서 제외하고 작업 거절 |
| 삭제 정보 손상 | 일반 목록에 다시 노출하지 않고 복원/영구 삭제 거절 |
| 사진 일부 로드 실패 | 사진 파일을 복구했다고 보장하지 않음. 기록과 사진 참조는 보존 |

프론트의 `isMine`과 로컬 소유자 키는 계정 인증이 아니다. 서버 연결 후 사용자 토큰과 소유권을 서버에서 검사하며, 서버 휴지통에 있는 기록에 편집·발행·신규 댓글을 허용하지 않는다.

## 7. 구현 파일과 검증

- `web/src/tripTrash.ts`: 달력 6개월, 기록 이동/복원/영구 삭제, 만료·중복·소유자·이전 삭제 상태 검사.
- `web/src/TripTrashSheet.tsx`: 이동 확인, 목록, 상세, 복원, 영구 삭제 확인, 실패 상태. 한국어/영어 문구.
- `web/src/trip-trash.css`: 기존 하단 모달, 36px 소형 행동 및 14/12px 안내 역할 재사용.
- `web/tests/tripTrash.test.mjs`: 월말·윤년·한국 시각 경계, 만료 직전/정각, 개인 일정/여행기 분리, 공개 및 편집 초안 비공개 복원, 원본 불변·ID 보존, 중복/오래된 요청, 소유권, 공유 사진 유지, 손상 기록 비노출.

단위 검증은 실제 서버 인증·여러 기기 경쟁·서버 자동 삭제나 실제 Android 뒤로가기 검증을 대신하지 않는다. 최종 화면 검수와 App 연결 상태는 이번 4주차/3차 결과 리포트에서 별도로 기록한다.
