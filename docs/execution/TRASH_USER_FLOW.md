# 휴지통·삭제 복구 사용자 기획안

작성일: 2026-09-15 · 상태: 검토용 기획안 / 휴지통 미구현

사용자는 실제 서비스 기능을 구현하고, JSON 파일 백업·복구 메뉴는 제외하되 휴지통은 서비스 기능으로 검토하도록 요청했다. 아래 진입 위치·대상·보관 기간·복원 상태는 제안이며 아직 확정된 정책이 아니다.

## 1. 사용 목적과 첫 적용 범위

실수로 지운 내 여행을 앱 안에서 찾아 되살린다. 파일 다운로드나 업로드 없이 같은 계정으로 다른 기기에서도 이용한다.

| 사용자의 행동 | 제안하는 처리 | 사용자가 다시 찾는 곳 |
|---|---|---|
| 내 여행·여행기 전체 삭제 | 여행 한 건을 휴지통에 보관. 소유한 비공개 초안·복사 여행·공개 여행기 포함 | 내 여행 → ⋯ → 휴지통 |
| 편집 중 DAY·글·사진·담은 장소 삭제 또는 이동 | 기존 2차 계획의 ‘마지막 변경 취소’로 복구. 초기 휴지통 목록에 개별 조각을 섞지 않음 | 현재 여행 편집 화면의 실행 취소 |
| 저장한 장소의 북마크 해제 | 저장 목록에서만 해제. 내 여행에 담은 방문은 유지 | 장소를 찾아 다시 저장 |
| 다른 사람의 여행기 보기 | 삭제·복원 권한 없음. 내 계정으로 복사한 여행만 관리 | 해당 없음 |

첫 휴지통은 **여행 전체 복구**에 집중한다. 개별 DAY·사진의 장기 보관까지 필요한지는 별도 결정한다. 편집 실행 취소의 종료·저장·다른 여행 전환 시 범위는 P2-07에서 따로 정의하며, 휴지통의 30일 보관과 같은 것으로 안내하지 않는다.

## 2. 삭제부터 다시 찾기까지

1. **내 여행 상세 → ⋯ → 여행 삭제.** 현재 전체 삭제 행동을 이 위치로 정리한다.
2. 기존 하단 팝업으로 확인한다. 제목은 ‘이 여행을 휴지통으로 옮길까요?’, 본문은 ‘글·사진·DAY 일정이 함께 보관됩니다. 30일 안에 복원할 수 있어요.’이다. 버튼은 ‘취소’와 ‘휴지통으로 이동’이다. 공개 여행이면 ‘공개 목록과 공유 링크에서도 숨겨집니다.’를 덧붙인다.
3. 이동 성공 후 내 여행 목록으로 돌아간다. 해당 여행은 목록·공개 검색·지도 일정·프로필 여행 수에서 제외한다. 실패하면 원래 화면과 여행을 유지한다.
4. ‘휴지통으로 옮겼어요’와 ‘실행 취소’를 잠깐 표시한다. 안내가 사라져도 휴지통에서 복원할 수 있다.
5. 나중에 **하단 내 여행 → 상단 ⋯ → 휴지통**으로 들어간다. 메뉴에 보관 중인 여행 수를 표시한다. 내 여행 목록이 비어 있어도 ⋯와 휴지통에 접근할 수 있어야 한다.

공개 상태는 휴지통 이동 성공과 함께 서버에서 숨긴다. 이미 다른 사용자가 복사한 독립 여행이나 그 사용자의 저장 기록을 함께 삭제하지 않는다. 원본 공유 링크에는 ‘볼 수 없는 여행입니다’만 표시하고 휴지통의 제목·사진을 노출하지 않는다.

## 3. 휴지통 화면과 복원

| 화면 요소 | 표시·동작 |
|---|---|
| 상단 | 뒤로가기, ‘휴지통’, 보관 중인 여행 수 |
| 고정 설명 | ‘삭제한 여행은 30일 동안 보관됩니다. 기간이 지나면 복원할 수 없습니다.’ |
| 여행 목록 | 최근 삭제 순. 기존 여행 커버·제목·지역·여행 기간, 삭제일, 남은 보관 기간 표시 |
| 여행 선택 | 하단 팝업에서 제목·DAY 수·장소 수·삭제일·보관 종료일과 ‘복원’, ‘영구 삭제’ 제공 |
| 복원 진행 | ‘복원 중…’, 중복 누름 차단. 완료되기 전 목록에서 제거하지 않음 |
| 복원 완료 | 휴지통 목록에서 제거하고 ‘내 여행에 복원했어요’와 ‘여행 보기’ 표시 |
| 비어 있음 | ‘휴지통이 비어 있어요. 삭제한 여행은 이곳에서 다시 찾을 수 있어요.’ |

**복원 내용:** 삭제 당시 여행 제목·본문·대표 사진·첨부 사진·DAY 순서·담은 장소·방문별 메모와 연결 정보를 함께 되살린다. 새 여행을 복제하지 않고 기존 여행을 복원해 중복을 만들지 않는다. 저장 목록의 북마크 상태나 다른 여행에 담은 동일 장소는 변경하지 않는다.

**공개 여부 제안:** 보관 후 복원한 여행은 비공개로 돌아온다. 삭제 전 공개 여행이라면 복원 팝업에 ‘비공개로 복원됩니다. 내용을 확인한 뒤 다시 공개해 주세요.’를 먼저 표시한다. 계획 중·여행 중 상태는 유지하되 발행 상태는 비공개 초안으로 전환한다. 삭제 직후 ‘실행 취소’ 역시 이 규칙을 따르며 공개 여행에는 ‘비공개로 복원’이라는 행동명을 사용한다.

## 4. 보관 기간과 영구 삭제 제안

- 보관 기간은 **삭제 성공 시점부터 30일**을 제안한다. 서버 시각을 기준으로 하며 다른 기기에서 열어도 동일한 종료일을 표시한다. 30일은 서비스 정책 제안이지 이미 확정된 운영·법적 기준이 아니다.
- 24시간 미만이면 ‘오늘 삭제 예정’과 종료 시각을 표시한다. 사용자가 복원을 누르는 순간에도 서버에서 기한을 다시 확인한다.
- 영구 삭제는 해당 여행을 선택한 팝업에서만 제공한다. 제목·사진·DAY를 되살릴 수 없다는 확인을 거친다. 최초 버전에는 일괄 선택·휴지통 전체 비우기를 넣지 않는다.
- 기간 만료 후에는 복원할 수 없고 정리 작업이 데이터를 제거한다. 사진은 다른 여행에서 사용하는지 확인해 공유 중인 파일까지 삭제하지 않는다. 비공개 사진은 단순 주소 추측으로 열리지 않게 처리한다.
- 운영 서버의 장애 복구용 백업은 별도 영역이다. 사용자 휴지통에서 복구 가능한 기간과 서버 백업 보존 기간을 같은 것으로 약속하지 않는다.

## 5. 반드시 설계할 예외 상태

| 상황 | 사용자에게 보이는 결과 |
|---|---|
| 목록 로딩 실패 | ‘휴지통을 불러오지 못했어요’와 재시도. 빈 목록으로 오해하게 하지 않음 |
| 삭제·복원·영구 삭제 실패 | 현재 항목을 유지하고 실패 안내·재시도 제공 |
| 다른 기기에서 이미 복원함 | 중복 생성하지 않고 ‘이미 복원된 여행입니다’와 여행 보기 제공 |
| 다른 기기에서 영구 삭제함 / 보관 기간 만료 | 복원을 중단하고 사유를 안내한 뒤 목록을 갱신 |
| 로그아웃 / 다른 계정 | 로그인 필요 안내. 다른 계정의 여행과 휴지통 기록은 노출하지 않음 |
| 여행 첨부 사진 일부를 불러올 수 없음 | 여행은 열고 해당 사진 자리에 안내. 모든 사진을 정상 복원했다고 표시하지 않음 |
| 장소의 현재 운영 정보가 바뀜 | 사용자가 쓴 여행 기록은 유지. 최신 업체 정보와 기록 당시 정보의 차이를 표시 |

## 6. 화면과 서버의 협업 범위

**2차 프론트:** 삭제 확인, 내 여행의 휴지통 진입, 목록·빈 화면·항목 팝업, 복원·영구 삭제·실패·중복 상태를 같은 사용자 흐름으로 구현한다. 시연 자료도 이 흐름을 재현하며 개발용 JSON 업로드 메뉴를 만들지 않는다. 기존 편집 실행 취소와 자동 임시 저장은 각각 P2-07·P2-02에 남긴다.

**백엔드:** 계정 소유권 확인, 휴지통 이동·목록·복원·영구 삭제, 보관 종료 시각, 공개 노출 차단, 사진 보존·정리를 담당한다. 삭제 상태와 내용은 함께 저장하며 두 기기에서 동시에 요청해도 한 번만 반영한다. 휴지통에 있는 여행으로 신규 댓글·일정 편집 요청을 받지 않는다.

기획을 확인한 뒤 P2-07에 연결한다. 기존 일정 6행 표는 유지한다. 종전 ‘마지막 변경 취소’의 예상 2작업일이 서버 휴지통 전체 구현까지 포함한 확정 공수라고 해석하지 않는다.

## 7. 고객 확인 시 보여줄 시나리오

1. 3일 여행을 삭제하고 즉시 실행 취소해 DAY·글·사진·장소가 돌아오는지 확인한다.
2. 여행을 삭제하고 화면을 닫았다가 내 여행의 휴지통에서 찾아 복원한다.
3. 공개 여행을 삭제하면 공개 목록·공유 링크에서 숨겨지고 복원 뒤에는 비공개로 돌아오는지 확인한다.
4. 북마크 해제는 휴지통에 들어가지 않고 내 여행의 방문도 지우지 않는지 확인한다.
5. 복원 실패, 기간 만료, 다른 기기의 복원, 영구 삭제 취소·성공을 각각 확인한다.

검토할 핵심 정책은 **여행 전체만 보관할지, 30일로 할지, 복원 후 비공개로 할지**다. 화면 제작 전에 이 세 항목을 확인한다.
