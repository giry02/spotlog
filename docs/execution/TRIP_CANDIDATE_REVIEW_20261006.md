# 여행 후보 담기 · 내 여행/여행기 분리

2026-10-06 · 로컬 검수본 반영. GitHub 업로드·공개 배포 없음. 관리자 변경 없음.

## 고객 흐름

저장한 랜드마크 → 여행 기간/DAY 설정 → 여행 준비 저장 → 랜드마크의 주변 업체에서 여러 후보 담기 → 마지막 확인 → 한 곳씩 확정 → 내 여행 완성 → 필요하면 별도 여행기 작성.

- 새 여행/저장 장소 담기로 만든 일정은 `planStage: DRAFT`로 보관. 글이나 사진 작성 없이 준비 가능.
- 음식점·카페는 DAY＋랜드마크 방문＋종류별 후보 묶음. 점심·저녁 등 기존 시간대가 있으면 시간대도 구분.
- 숙소는 숙박일별 후보 묶음. 2박으로 후보를 담으면 해당 두 밤의 후보로 보관하며 각 밤에서 독립 선택.
- 담기 직후 팝업 유지. 여러 음식점·카페·숙소를 비교하고 ‘후보 담기 완료’로 복귀.
- 후보는 실제 방문 목록·지도·방문 완료 수에 포함되지 않음. 기기 로컬 저장으로 닫기·새로고침 후 복구.
- 마지막 확인에서 묶음마다 한 곳 선택. 한 후보만 있으면 기본 선택, 여러 후보는 직접 선택. ‘이번 후보는 제외’ 가능. 후보 자체를 빼는 버튼도 제공.
- 기존 일정이 있으면 기본값은 현재 장소 유지. 예약 고정 숙소는 변경 불가. 다른 밤과 기존 점심/저녁은 보호.
- 완료 시 선택한 곳만 실제 방문으로 반영, `planStage: READY`, 후보 목록 비움. 제외한 곳은 실제 일정이나 여행기에 들어가지 않음.
- 후보 확인 전 ‘여행기로 기록’과 AI 일정 조정은 잠금. 이미 생성된 AI 완성 초안의 간단 저장 흐름은 유지. 후보 선택을 AI 최초 입력의 필수 단계로 추가하지 않음.
- 준비 중 여행 복사는 후보·DAY·랜드마크 연결 ID를 새 여행 기준으로 재발급. 원본 유지.
- 다른 DAY로 옮긴 랜드마크의 음식점/카페 후보는 따라 이동. 제거된 랜드마크·숙박일 후보는 정리.

## 내 여행과 여행기

- 내 여행 화면: `내 여행 / 내 여행기` 두 탭. 기본은 내 여행.
- 내 여행 안에서 `여행 준비 중 / 내 여행 일정` 구분. `purpose: PLAN`만 표시.
- 내 여행기는 `purpose: JOURNAL` 및 이전 작성 기록. 기존 작성본을 개인 일정으로 강제 전환하지 않음.
- 프로필의 내 여행기·작성자 관련 여행기에도 개인 일정 제외.
- 여행기 작성은 별도 ID와 원본 여행 연결을 가진 비공개 초안. 내 여행을 덮어쓰지 않으며 후보·개인 메모·예약 고정·방문 진행 기록 제외.

## 구현 연결 기준

| 항목 | 계약 |
|---|---|
| 준비 상태 | 개인 여행의 `planStage: DRAFT / READY`; 기존 값 누락 일정은 사용 가능한 기존 일정 유지 |
| 후보 묶음 | `businessCandidates: TripCandidateGroup[]` · `id/dayId/anchorVisitId/kind/slot/selectedId/options` |
| 후보 장소 | `options[].place`는 장소 정보 스냅샷, `options[].fixed`는 선택 시 예약 고정 의사 |
| 실제 방문 | 선택 확정 전 `days[].places/blocks`에 후보를 넣지 않음 |
| 숙소 기준 | DAY별 한 곳. 다른 랜드마크에서 담아도 같은 숙박일의 후보로 합침 |
| 공개 자료 | 후보·준비 상태는 개인 PLAN에만 허용. JOURNAL/공개 payload에 넣으면 로컬 저장 계약도 거부 |
| 원본/복사 | placeId는 유지, 개인 여행/DAY/방문/후보 묶음 ID는 복사별 발급 |

서버 연결 시 후보 저장·최종 확정 모두 소유권/현재 여행 revision 확인 필요. 확정 명령을 원자적으로 처리하고 중복 실행 방지. 최신 예약 고정·장소 공개/영업/권리 상태를 서버에서 재확인. 최종 확정 후 여행기 작성은 별도 명령 유지. 현재 서버 권한 검증·다중 기기 동기화는 미연결.
