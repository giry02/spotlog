## 1. 권장 출발 구성

| 위치 | 구성 | 맡는 일 | 상태 |
|---|---|---|---|
| 고객 웹·앱 | 기존 Spotlog 화면 | 간단 입력, 초안 확인, 선택 수정·저장 | 시제품 있음 |
| 백엔드 담당 환경 | Spotlog 서버·서비스 DB | 계정, 장소 원본, 좌표·추천 기준, 일정 구성·검증·저장, 네이버 연결 | 신규 구축 |
| 외부 TypeSafe | Jev | 의도·정해둔 조건·포함/제외 판별. 우리 서버에서 호출 | 신규 시험 제안, 한국어·속도 미측정 |
| 맥미니 64GB | 기존 Flowise | 조건 해석·검색·설명 모델 호출 실행 | 기존 설치, 버전·Flow 확인 필요 |
| 맥미니 64GB | 별도 PostgreSQL + pgvector | 승인된 설명과 검색 벡터, 검색용 장소 메타데이터 | 로컬 구축 제안 |
| 맥미니 64GB | AI 연결 서비스 | 백엔드 전용 요청·응답 규격, 인증, 버전·오류 정리 | 신규 구현 제안 |
| 맥미니 64GB | 로컬 임베딩 모델 | 설명·검색문을 의미 검색용 숫자로 변환 | Ollama 등을 후보로 검증, 미설치·미선정 |
| 맥미니 / 외부 AI 제공자 | 소형 언어 모델 / 예외 대형 모델 | 로컬 설명·Jev 미분류 해석 / 외부 실패 부분 보완 | 로컬 모델 후보는 13절, 장비·품질 검증 후 채택 |

RAG 저장·검색을 맥미니에 두는 것과 언어 모델을 맥미니에서 실행하는 것은 별개. 후속 사용자 질문에 따라 로컬 소형 언어 모델도 13절의 후보로 먼저 시험하는 안을 추가. 기존 외부 모델 연결은 비교·예외 보완 자산으로 활용. 칩·한국어 품질·지연을 측정한 뒤 동일 요청 규격으로 로컬 기본 모델 채택 여부 결정.

임베딩도 반드시 외부 서비스일 필요 없음. 로컬 임베딩을 먼저 시험하되 모델은 한국어 검색 평가 후 선택. 외부 언어 모델을 사용하면 해당 요청문과 선택된 근거는 외부로 전송됨. ‘RAG 로컬 운영 = 모든 AI 처리가 PC 안에서만 수행’으로 표시하지 않음.

Flowise는 Postgres/pgvector 적재·검색 연결을 제공. pgvector는 로컬 설치와 Docker 배치 지원. 따라서 기존 PostgreSQL 계열 설계안과 연결하기 쉬운 출발안. 백엔드의 DB 제품을 강제로 확정하는 결정은 아님. [Flowise Postgres](https://docs.flowiseai.com/integrations/langchain/vector-stores/postgres), [pgvector](https://github.com/pgvector/pgvector)

## 2. 담당을 먼저 나누기

|---|---|---|---|
| 장소 기준정보 | placeId 발급·원본 DB·주소/좌표·상태·순위 규칙 | 필요한 설명·태그·검색 조건 정의 | 같은 ID를 사용하는 공통 샘플 |

| RAG | 승인 자료 내보내기·변경/삭제 알림 | 문서 정리·임베딩·색인·검색·평가 | 버전 있는 자료 묶음 |
| 입력 해석 | 요청 인증, 명시 선택과 문장 충돌 검증 | 지역·기간·취향·포함/제외 인식 | 인식 조건·누락 항목 |
| 일정 구성 | DAY·방문 순서·식사·숙박 조합, 이동·예약 검증 | 후보별 근거·설명, 요청 의미 반영 | 완성 초안과 미확인 구간 |
| 대형 보완 | 호출 사유·횟수·변경 범위 판정, 재검증 | Flowise에서 해당 부분만 모델 호출 | 기존 정상 일정 보존 |
| 화면 연결 | 프론트용 API, 계정별 저장, 서버 버전 | 요청/결과 화면·오류·초안 보존 연결 | 현재 간단 생성 UI 유지 |
| 운영 | 서비스 서버·통신·상태 감시 | 맥미니·Flowise·검색 DB·색인 복구 | 장애 시 담당·연락·복구 절차 |

일정 조합 코드는 백엔드 서버가 최종 실행·검증하는 기준. 이 역할을 AI 담당에게 옮길 경우에는 계약과 코드 소유를 먼저 명시. 양쪽이 같은 일정 계산기를 따로 만들지 않음.

## 3. RAG에 넣는 것과 원본 DB에 두는 것

| 자료 | 기준 원본 | 검색·응답 방법 |
|---|---|---|
| 이름·지점·주소·좌표·업종·운영 상태 | 백엔드 장소 DB | 정확한 조건 조회. 최종 카드·지도는 원본 DB에서 확정 |
| 자체 순위·추천 규칙 | 백엔드 추천 데이터 | 해당 지역·업종·기준 버전으로 정렬. 의미 검색 점수를 인기 순위로 사용하지 않음 |
| 장소 특징·분위기·방문 팁·검수된 소개 | 허가된 원문 + 맥미니 검색 색인 | 취향과 의미가 맞는 근거 검색 |
| 영업시간·휴무·가격 등 변하는 정보 | 출처·확인일이 있는 원본 필드 | 최신성 확인. 오래된 소개 문장에서 현재 사실을 확정하지 않음 |
| 사용자 찜·예약·개인 일정 | 계정별 백엔드 DB | 해당 요청에 필요한 내용만 전달. 공용 RAG에 일괄 적재하지 않음 |
| 네이버 검색 결과 | 기존 외부 검색 연결 기준 | 화면 조회와 내부 허가 자료를 구분. 공용 RAG로 자동 적재하지 않음 |

예: ‘주안반점’의 특정 지점은 하나의 placeId. 그 지점의 이름·주소·좌표·추천 기준은 원본 DB, 같은 ID에 붙은 승인된 소개는 RAG. 이름만으로 다른 지점을 자동 합치거나 모델 학습으로 좌표·ID 매칭을 해결하지 않음. 이 예시는 실제 업체 정보·특징을 생성한 것이 아님.

회사/브랜드 companyId는 선택적 조직 연결. 지도상의 장소는 placeId, 일정에 한 번 방문하는 항목은 visitId. 같은 가게를 두 번 방문하면 placeId는 같고 visitId는 다름.

## 4. 최초 자료 규격

처음에는 한 권역·장소 약 30~50곳으로 검색을 검증하는 안을 제안. 랜드마크·식당·카페·숙소를 함께 준비. 이후 기존 초기 연결안의 약 100곳까지 확대. 수량은 고객 확정 범위나 전국 서비스 완료 기준이 아님.

| 자료 묶음 | 필수 정보 |
|---|---|
| 장소 | placeId, companyId(없으면 null), 이름·별칭, 종류, 지역 코드, 주소, 위도·경도 또는 null, 검수/운영 상태, placeVersion |
| 추천 기준 | placeId, 적용 지역/종류, 점수 또는 순서, 기준명·버전·산정 시각. 실제 기준이 없으면 빈 값 |
| 원문 설명 | documentId, placeId, 주제, 본문, sourceId, 원문 위치, 확인일 또는 null, documentVersion, 공개·사용 가능 상태 |
| 사용 범위 | 검색 색인 허용, 모델 입력 허용, 화면 표시 허용, 권리 근거, 만료·철회 상태 |
| 변경 목록 | 증가하는 변경 순번, 대상 ID, 변경/삭제/비활성 구분, 버전, 적용 시각 |
| 묶음 표지 | schemaVersion, catalogVersion, 생성 시각, 포함 ID 목록, 내용 해시 |

백엔드가 완성되기 전에도 두 사람이 같은 샘플 자료 파일을 공유해 시작 가능. 초기 ID를 합의해 백엔드에 그대로 가져올 수 있도록 함. 별도로 만든 임시 ID가 있으면 실제 연동 전에 명시적으로 매핑. 이름을 ID로 사용하거나 각자 다른 ID를 발급하지 않음.

개발용 파일 전달은 협업 도구. 사용자 서비스에 JSON 백업/복구 메뉴를 추가하는 계획이 아님.

## 5. 문서를 검색 자료로 만드는 기준

1. 승인된 장소·원문·권리 자료 수신 → ID·필수값·내용 해시 검사.
2. 한 장소의 한 주제씩 정리. 소개 / 분위기 / 방문 팁 등으로 나누고 서로 다른 지점 정보를 한 조각에 섞지 않음.
3. 짧은 설명은 그대로 사용. 긴 설명만 의미가 끊기지 않는 범위로 분할. 첫 실험값은 약 300~600토큰, 겹침은 필요한 문맥에만 사용. 모델의 입력 제한과 한국어 검색 결과로 조정.
4. 각 조각에 chunkId, documentId·버전, placeId, 지역·종류, 언어, 출처·권리, 확인일·활성 상태 부착.
5. 임베딩 생성 → pgvector 저장. 사용 모델·정확한 버전·차원·전처리·분할 규칙을 embeddingProfile로 기록.
6. 검수 후 검색에 사용할 색인 버전 전환. 실패한 새 색인으로 정상 버전을 덮어쓰지 않음.

등록 문서와 질문은 같은 임베딩 모델·차원·전처리 규칙 사용. 모델을 바꾸면 새 색인에서 재임베딩·평가 후 전환. 서로 다른 모델의 벡터를 같은 공간에서 비교하지 않음. [Ollama 임베딩](https://docs.ollama.com/capabilities/embeddings)

설명 조각에 들어간 문장을 도구 실행·권한 변경 명령으로 취급하지 않음. Flowise에는 허용된 조회 도구만 연결하고, 원문에서 발견한 명령으로 임의 SQL·저장·삭제를 실행하지 않음.

## 6. 고객 요청 한 번의 처리 순서

1. 고객: 기존 AI 간단 생성에 글 입력. 저장 장소 추천도 같은 입구 사용.
2. 백엔드: 로그인·선택 장소 소유권 확인 → 원문·선택 출처 보존 → 외부 Jev에 판별 질문 묶음 전달.
3. Jev: 의도·지역·기간·속도·교통·포함/제외 판별. 미분류·복합 요구만 맥미니 소형 모델로 추가 해석하고 원문·추가 요구 보존.
4. 백엔드: 명시 선택·누락·충돌 검사 → 서비스 DB에서 해당 지역·종류·좌표·상태에 맞는 허용 후보 조회.
5. 맥미니 RAG: 허용 후보 ID 안에서 정확명·별칭 검색 + 취향 의미 검색. placeId·근거 조각·문서 버전 반환.
6. 백엔드: 최신 장소·추천 기준·근거 버전을 다시 확인 → DAY·식사·숙박·방문 순서 구성. 지도/경로는 별도 검증.
7. 맥미니 소형 모델: 확정 후보·일정·허용 근거로 짧은 추천 설명 작성. 모델 처리 실패만 기존 대형 보완 정책 적용.
8. 백엔드: 형식·ID·지역·제외·예약·근거 검사 → 프론트에 완성 초안 반환.
9. 고객: 상세에서 필요한 부분 수정 → 명시적으로 저장. 모델은 여행 DB에 직접 저장하지 않음.

RAG 점수만으로 지역·거리·예약 제약을 넘지 않음. 검색 결과가 없으면 등록 자료가 없거나 적합한 근거가 없다고 반환. 대형 모델의 외부 지식으로 업체를 채우지 않음. 미확인 이동 시간은 빈 값으로 반환하고 ‘미확인’ 표시.

## 7. 두 개발자가 합의할 내부 요청·응답 v1

아래 이름·경로는 신규 구현 제안. 현재 실행 중인 API가 아님. 브라우저는 우리 백엔드만 호출하고 Flowise ID·키·PC 주소를 직접 사용하지 않음.

기본 판별은 백엔드 내부 Jev 어댑터가 외부 서비스에 호출. 아래 /internal/ai/interpret는 미분류 부분의 맥미니 추가 해석 및 로컬 단독 비교 시험용. 모든 요청에서 Jev와 소형 해석을 중복 호출하지 않음. Jev 응답·선택지·미입력/미분류 상태를 공통 조건 규격으로 정규화하고, 한국어 질문·평가집은 AI 담당과 합의.

| 연결 | 백엔드 → 맥미니 | 맥미니 → 백엔드 |
|---|---|---|
| 미분류 해석 /internal/ai/interpret | requestId, schemaVersion, 원문, 미분류 부분, 정상 판별·명시 선택, 변경 가능 범위, deadline | 해당 부분 조건 변경 제안, 입력 근거, needsInput, 모순/해석 실패 코드 |
| 근거 검색 /internal/rag/search | requestId, query, 허용 placeId 목록, 지역·종류, 언어, 자료 버전, 결과 개수 제한 | placeId, chunkId, documentId·버전, excerpt, sourceId, indexVersion, 검색 점수 종류, 빈 결과 사유 |
| 설명 /internal/ai/explain | 검증된 후보·DAY·visitId, 시간대, 허용 근거, 관련 원문, 변경 가능 범위 | visitId별 짧은 이유, evidenceIds, 확인 불가 항목, 모델 실패 코드 |

상태 공통안: ok / needs_input / insufficient_data / stale_data / unavailable / invalid_result. 원인과 재시도 가능 여부를 구분. null과 빈 목록의 의미, 시간 제한, 요청 중복·취소·버전 불일치 처리도 같이 합의.

대형 모델 보완은 백엔드가 실패 코드·근거·호출 한도를 판정한 뒤 같은 내부 기능에 제한된 보완 요청으로 전달. 기본 Flowise가 임의로 계속 대형 호출하지 않음. 기존 요청당 최대 1회는 초기 제안 정책이며 동일하게 적용.

프론트로 반환할 최종 초안은 백엔드가 조립: draftId·버전, 인식 조건, DAY별 방문, placeId·visitId·종류·시간대·순서·연결 방문, 숙박일/예약 고정, 추천 이유·근거, 미정 구간. 이름·주소·좌표·사진은 최신 서비스 DB에서 붙임.

기존 web/src/aiPlanner.ts의 catalog 전체·author·로컬 sourceVersion은 샘플용 입력. 이를 그대로 신뢰하는 공개 서버 API로 만들지 않음. 서버가 사용자와 후보를 결정하고 revision을 발급. 현재 AI 프론트의 요청/응답 문서에는 이전 긴 입력 폼 설명도 남아 있으므로 최신 간단 생성 기준으로 계약을 함께 갱신해야 함.

Flowise Prediction API는 맥미니 내부에서 사용할 실행 인터페이스. Spotlog 규격을 받는 얇은 연결 서비스가 Flowise 응답을 검사·변환하면 Flow 수정과 모델 교체가 백엔드·프론트에 덜 전파됨. [Flowise Prediction](https://docs.flowiseai.com/using-flowise/prediction)

## 8. 데이터 변경·삭제 기준

- 원본은 백엔드 DB와 승인 원문. 맥미니 검색 DB는 재생성 가능한 파생 자료.
- 초기에는 버전 있는 자료 묶음으로 동기화. 이후 변경 순번(cursor) 기반 증분 조회·삭제 목록으로 교체.
- 중복 수신은 같은 ID·버전·내용 해시로 덮어쓰기 또는 생략. 실패한 동기화는 체크포인트를 넘기지 않음.
- 좌표·순위만 변경되면 최종 원본 조회에 반영. 임베딩 입력 본문이 바뀌지 않았다면 재임베딩 불필요.
- 설명이 변경되면 해당 문서 조각만 다시 생성. 삭제·비활성·권리 철회는 검색 즉시 차단하고 캐시·색인에서도 제거.
- 백엔드가 요청 시 전달하는 허용 ID·문서 버전과 RAG 응답을 재검사. 갱신되지 않은 근거는 답변에 사용하지 않음.
- 색인 지연·마지막 성공 시각·실패 수 표시. 서비스에 허용할 지연과 만료 기준은 정보 종류별 합의.
- 사진은 원본 이미지 전체를 벡터 DB에 넣지 않음. 장소 ID·자산 ID·허용된 설명으로 연결.

## 9. 백엔드와 AI를 병행하는 순서

| 단계 | 백엔드 개발자 | 사용자 · AI 담당 | 같이 확인할 것 |
|---|---|---|---|
| 착수 | 장소·문서 ID와 서버 응답 형식 정의 | 요청 예시·필요 메타데이터·성공 기준 정의 | 규격 v1·같은 샘플 30~50곳 |
| 독립 개발 | 장소 DB·조회·저장·권한 구현 | 맥미니 검색 DB·문서 분할·임베딩·Flowise 조건 인식 | 실제 서버 없이 같은 샘플로 양쪽 검사 |
| 첫 접속 | 얇은 내부 호출·승인 자료 내보내기부터 제공 | 조건 1건·근거 검색 1건 응답 | 전체 백엔드 완료 전에 왕복 1건 성공 |
| 기능 연결 | 후보 선별·일정 조합·지도·결과 검증 | 식사/숙박 요청·근거 설명·소형/대형 정책 | 고객 입력 → 완성 초안 → 저장 |
| 안정화 | 변경/삭제 동기화·시간 초과·저장 중복 방어 | 검색 평가·색인 복구·동시 요청 측정 | 삭제 반영·PC 중단·재시도·기존 일정 보존 |

매주 화요일 협업 확인안: 같은 요청·같은 자료 버전으로 결과 비교, 이번 변경 필드 공유, 다음 왕복 연결 1건 선정. 계약 변경은 문서와 예시를 먼저 함께 갱신. 기존 날짜별 고객 보고 범위와 개발 완료 목표는 별도 유지.

백엔드 완성 후 처음 AI를 붙이는 방식은 피함. 장소 조회·자료 전달·내부 호출의 최소 연결을 먼저 열고, 이후 계정·댓글·사진 기능 개발과 AI 품질 작업 병행.

## 10. 평가 기준

처음에는 실제 요청 20~30개와 기대 조건·허용 후보·근거를 사람이 작성. 평가 수량은 시작점 제안. 모델 자신의 ‘정확도/확신’만 성공 판정으로 사용하지 않음.

| 구분 | 대표 사례 | 합격 판단 |
|---|---|---|
| 조건 | 부산 2박 3일·카페 제외·식당 포함·숙소 제외 | 명시 조건 누락·반전 없이 구조화 |
| 검색 | 특정 지점 이름, 별칭, 가족/조용함 등 실제 근거가 있는 표현 | 기대 장소·근거의 상위 결과 포함률 측정, 금지 ID 0건 |
| 자료 없음 | 미등록 지역·특징·식당 | 근거 부족 반환, 허구 장소·좌표 0건 |
| 최신성 | 업체 비활성·설명 수정·권리 철회 | 이전 근거로 새 답변 생성하지 않음 |
| 일정 | 점심 앞뒤 방문, 마지막 날 숙박 제외 요청, 예약 유지 | 검증된 장소·DAY·식사·숙박 관계 보존 |
| 부분 수정 | 둘째 날 점심만 교체 | 다른 DAY·고정 예약 변경 0건 |
| 모델 보완 | 근거 충분한 소형 해석 실패 / 데이터 부족 | 앞의 경우만 대형 허용, 호출 사유·횟수 기록 |
| 장애 | PC 종료·네트워크 끊김·Flowise 오류·늦은 응답 | 기존 일정·입력 보존, 명확한 실패 상태 |
| 성능 | 동시 1건부터 증가, 같은 자료·문장 사용 | 평균/p95 지연·메모리·검색 품질·호출 비용 기록 후 한도 결정 |

소형과 대형을 포함한 생성 속도·동시 사용자 수는 장비·모델·문맥 길이·네트워크 측정 전 보장하지 않음. RAG 검색 품질과 최종 일정 품질은 별도 측정.

## 11. 일반 PC 운영의 경계

개발·고객 검수용은 맥미니 로컬 구성을 우선 제안. 실제 운영까지 같은 PC를 쓸지는 사용자 확인과 부하 시험 후 결정.

- 외부 백엔드는 인증된 사설 연결/VPN 등을 통해 맥미니의 AI 연결 서비스에 접근. 구체 방식은 양쪽 네트워크 확인 후 선택.
- 브라우저에 PC/Flowise 키를 주거나 DB·임베딩·Flowise 편집 화면을 그대로 인터넷에 공개하지 않음.
- Flowise 편집기 로그인과 개별 Flow 호출 인증을 각각 점검. 공식 문서상 Flow 호출은 별도 키 설정이 필요할 수 있음. [Flow 접근 제어](https://docs.flowiseai.com/configuration/authorization/chatflow-level)
- Docker 등을 사용할 경우 Postgres 영구 저장 볼륨·재시작 정책·버전 고정. DB, 원문, Flow 내보내기, 임베딩 규칙의 백업과 실제 복구 시험.
- 24시간 서비스에 사용하면 절전·재부팅 후 자동 기동, 전원·회선·상태 감시, 장애 담당 필요. PC가 꺼지면 AI 생성은 중단될 수 있으므로 백엔드는 저장 목록·기존 여행을 계속 제공.
- PC 장애를 대형 모델로 자동 우회하지 않음. RAG 근거에 접근할 수 없는데 외부 모델이 대신 사실을 만드는 구조 금지.
- 초기 설치 전 확인: 칩/연식, macOS, SSD 여유, Flowise 버전·설치 방식·기존 Flow·모델, 상시 운영 여부. 정확한 모델·설치 방법은 이 확인 후 고정.

## 13. 로컬 소형 언어 모델 추천

2026-09-21 공식 모델 배포·실행 문서 확인. 추천은 Spotlog 용도에 대한 첫 평가 후보이며 실제 맥미니 벤치마크 결과가 아님.

**첫 시험 조합: Ollama + Qwen3.5 9B Q4_K_M + Qwen3 Embedding 0.6B + PostgreSQL/pgvector + 기존 Flowise.** Ollama는 모델 실행 도구, Flowise는 모델·검색 호출 흐름을 연결하는 도구. 둘 다 AI 모델 이름은 아님.

| 용도 | 후보·정확한 태그 | 현재 배포 파일 크기 | 선택 기준 |
|---|---|---:|---|
| 기본 언어 모델 · 우선 시험 | Qwen3.5 9B · qwen3.5:9b · Q4_K_M | 약 6.6GB | 짧은 한국어 요청의 조건 추출·허용 근거 기반 설명. 모델 크기와 역할 범위상 첫 기준으로 제안 |
| 다른 계열 비교 | Gemma 4 12B · gemma4:12b · Q4_K_M | 약 7.6GB | 같은 한국어 요청·같은 근거로 정확도·말투·형식·지연 비교. 상시 함께 구동할 필수 구성 아님 |
| 품질 보강 비교 | Qwen3.5 27B · qwen3.5:27b · Q4_K_M | 약 17GB | 9B가 반복 실패하고 더 큰 모델이 실제 평가에서 개선될 때 비교. 9B→27B→외부 모델의 3단계 연속 호출안 아님 |
| 의미 검색용 임베딩 · 우선 시험 | Qwen3 Embedding 0.6B · qwen3-embedding:0.6b · Q8_0 | 약 639MB | 다국어 검색용. 일정 설명을 작성하는 모델과 구분. 0.6B로 평가 후 필요할 때 4B 비교 |

파일 크기는 RAM 요구량이 아님. 실행 중에는 문맥·KV 캐시·병렬 요청·OS·DB·Flowise 메모리가 추가로 필요. 64GB에서 후보를 시험할 여지는 있지만 처리량·동시 고객 수·지연을 보장하지 않음. M시리즈이면 Apple GPU 활용 가능, Intel Mac은 Ollama 기준 CPU 실행만 지원. 현재 문서의 macOS 요구는 Sonoma 14 이상. 장비 칩과 OS 확인이 모델 크기 확정보다 우선. [Ollama macOS](https://docs.ollama.com/macos)

배포 정보: [Qwen3.5 9B](https://ollama.com/library/qwen3.5:9b), [Qwen3.5 27B](https://ollama.com/library/qwen3.5:27b), [Gemma 4 12B](https://ollama.com/library/gemma4:12b), [Qwen3 Embedding 0.6B](https://ollama.com/library/qwen3-embedding:0.6b). 모델 계열의 대형 버전 벤치마크를 9B·12B 성능으로 인용하지 않음. 추천 이유는 업무 범위와 배포 크기에 따른 판단이며 한국어 정확도 우열은 아직 미측정.

### 첫 실행 설정의 기준

- 텍스트 조건 추출과 짧은 설명부터 사용. 사진 분석·음성·대화 기록 전체 입력은 초기 필수 범위에서 제외.
- 짧은 입력과 소량 근거에 맞춰 8K 문맥·동시 생성 1건부터 시험하는 안. 모델 최대 문맥을 그대로 켜거나 64GB를 전부 모델에 할당하지 않음. 수치는 초기 시험값이며 실제 근거 길이에 따라 조정.
- 조건 추출은 장시간 추론을 기본 요구하지 않음. Qwen의 직접 응답 모드와 추론 모드를 같은 평가집에서 비교해 선택. 추론 내용은 프론트 결과로 전달하지 않음. [Qwen3.5 9B 모델 카드](https://huggingface.co/Qwen/Qwen3.5-9B)
- JSON Schema로 지역·기간·포함/제외·needsInput 등 출력 구조 제한. 형식 준수와 의미 정확성은 별개로 검사. [Ollama 구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)
- Flowise 기존 버전이 선택 모델·구조화 출력·직접 응답 설정을 실제로 전달하는지 확인. 지원이 부족하면 내부 연결 서비스에서 Ollama를 호출하고 같은 계약으로 Flowise에 연결. 단순 JSON 출력 프롬프트만으로 검증 완료 처리하지 않음.
- 임베딩은 Qwen 모델의 query instruction 규칙 확인, 문서/질문의 역할별 전처리를 고정. 0.6B의 최대 1024차원과 실제 출력 차원 대조. 문서와 질문은 같은 모델·버전·차원 사용. [Qwen3 Embedding 모델 카드](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)
- 태그의 자동 최신 변경에 의존하지 않고 검증한 모델 digest·양자화·실행 도구 버전·설정을 기록.
- 대량 자료 임베딩은 고객 요청 처리와 작업 시간을 나누거나 작업 수를 제한. DB 검색, 임베딩, 언어 모델 응답 시간을 각각 측정.

### 로컬 기본 + 외부 대형의 실행 경계

평상시: 맥미니 소형 모델로 조건 인식·허용 근거 설명. 임베딩과 검색 DB도 로컬이면 이 경로의 문장 처리를 로컬에서 수행 가능.

예외: 충분한 자료가 있으나 해석·표현 실패로 판정되고 정책 한도가 남은 경우에만 서버 승인 후 외부 대형 모델에 실패 부분·필요 근거 전송. 자료 부족·지도 장애·PC 중단은 대형 보완 대상 아님. 대형 호출 시 외부로 나갈 정보와 로그를 구분.

모델 학습부터 시작하지 않음. 첫 단계는 원본 장소 정리 → RAG 검색 품질 → 조건 인식 → 일정·설명 검증. 자체 미세조정은 이 과정의 실제 실패 유형이 누적된 뒤 별도 판단.
