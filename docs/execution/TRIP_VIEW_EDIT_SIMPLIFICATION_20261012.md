# 내 여행 작성·보기·수정 간결화 · 2026.10.12

사용자 지적: 완성한 일정을 계속 등록 화면처럼 봐야 해서 불편. 자동 방문 줄이기는 중요한 방문을 판단할 근거가 부족하므로 제거. 등록 화면의 여행 안내·일정 조정·지도3개 버튼을 줄일 것.

## 반영

| 상태 | 화면·동작 |
|---|---|
| 일정 등록·수정 | 장소 담기와 상단 **완료** 중심. 여행 안내·일정 조정·지도 도구행 제거. 지도·방문 진행·여행기 버튼은 작성 중 숨김 |
| 완료 후 보기 | DAY별 방문 목록부터 표시. **수정**을 눌렀을 때만 장소 추가·주변 후보·DAY 관리 노출. 지도 버튼은 DAY제목과 같은 행 |
| 장소 상세 | 보기에서는 사진·소개·주소·방문 상태·지도 확인. 메모/시간 입력·삭제는 숨김. ‘이 장소 수정’으로 명시 전환 |
| 순서 변경 | 카드마다 위/아래 버튼을 나열하지 않고 장소 수정 창에 모음 |
| 미완성 보존 | 수정은 기기에 자동 보관하되 완료 전에는 DRAFT. 닫기·새로고침 시 이어서 수정. 완료 저장이 실패하면 편집 화면과 이전 자료 유지 |
| 여러 업체 후보 | 완료에서 기존 마지막 확인으로 연결. 묶음마다 직접 한 곳을 고른 뒤 보기로 전환. 창만 닫았을 때는 완성 처리하지 않음 |
| 여행 중 | 실제 방문 기록이 있거나 여행 중인 경우 완료·길찾기·다음 방문 유지. 새 계획에0/n진행 버튼줄을 바로 노출하지 않음 |

상단 중복 뒤로 버튼1개 제거. 기존132px표지·DAY목록·사진/시간·여행/여행기 구분·별도 공개·예약 고정·수동 장소 수정/삭제 유지. 개인 일정 완료는 **내 여행 저장**이며 공개 발행은 별도 여행기 기능. 고객 자동 방문 줄이기 컴포넌트·스타일과 진입점 제거. 초기 AI 간단 생성과 직접 한 곳 교체/수정은 유지.

완료 전 편집 내용은 개인 일정의 초안으로 보관하는 방식. 완성본·초안의 별도 서버 버전 관리는 실제 서버 연결 후 적용할 계약 범위이며 이번에 공개 게시 서버를 만든 것이 아님.

## 실제 저장 오류도 보완

직전 음식점·카페만 구성하기와 관련해, 기존 기기 저장 검증이 주변 후보 기준을 LANDMARK로만 제한하는 불일치 재현. 독립 식당에 카페 후보를 담으면 화면상 후보 생성은 됐지만 실제 저장소 저장이 거부됐음.

저장 검증을 현재 후보 규칙과 맞춤: LANDMARK 또는 독립 FOOD/CAFE/SHOP 허용. 연결된 하위 업체·숙소 기준, 잘못된 DAY·공개/여행기·권한없는 자료는 거부. 숙소의 다른 숙박 DAY 관계와 고정 예약 보존. 실제 repository 저장→새로고침→백업/복원 검사로 확인. 이전 독립 fixture는 별도 저장을 사용해 이 불일치를 드러내지 못했으므로 실제 저장소 검사4개 추가.
