# 2차 구현 내용과 확인 링크

2026-09-15 · 로컬 구현 · GitHub 업로드/서비스 활성화 없음

최신 댓글 보완: 장소 댓글 최신순, 답글 작성순, 수정 위치 유지. 기존 프로필 아이콘을 댓글/답글/좋아요 목록에 연결했으며 내 과거 댓글에도 현재 아이콘이 표시된다. 최신5202는 `week2-ui3`. [검수와 보관](PHASE_2_PLACE_COMMENTS.md).

후속 디자인 보정: 사용자 예시에 맞춰 주변 업체 버튼을52→36px, 개인 일정 내 보조 버튼을40px로 줄이고 카드 여백을 정리했다. 현재5201/5202는 주차별 기능을 유지한 보정본이다. [보정 내용·적용 순서](PHASE_2_UI_REFINEMENT.md).

최신 소통 위치 정정: 좋아요·댓글은 여행기의 랜드마크·식당·카페·숙소 **장소 카드 안**에만 표시한다. 글/사진 블록의 반응 버튼은 제거했다. 댓글의 답글·수정·삭제는 아이콘으로 바꿨다. [정정 내역과 최신2주차 보관본](PHASE_2_PLACE_COMMENTS.md).

저장한 랜드마크로 개인 동선을 만들고 주변 업체를 담는 흐름, 별도 여행기 작성과 카드 소통을 구현했다. **휴지통 보관 정책은 미확정이며, 실제 Android 기기 검수와 서버 연동까지 완료했다는 뜻은 아니다.**

## 1주차에 보여줄 내용

| 기능 | 확인할 동작 |
|---|---|
| 저장으로 내 여행 만들기 | 저장한 랜드마크 선택 → 기간 선택 → 글 없이 DAY별 일정 생성 |
| 개인 동선 화면 | 날짜별 랜드마크 목록, 저장한 장소 추가, 기본 순서 변경 |
| 주변 업체 담기 | 랜드마크의 ‘주변 업체’ → 맛집/카페 후보 → 담기 한 번으로 해당 장소 다음에 삽입 |
| 자동 저장 | 새로고침 후 여행·DAY·업체 순서 유지. 실패하면 기존 일정 유지 |
| 여행기와 구분 | 새 개인 일정은 동선 중심으로 열고 기존 작성 기록은 보존 |

이 상태를 먼저 별도 보관했다. 1주차 화면에는 이후 2주차 기능이 섞이지 않는다.

## 2주차에 추가한 내용

| 기능 | 확인할 동작 |
|---|---|
| 업체 검색·상세 | 현재 랜드마크와 지역을 유지한 이름 검색. 같은 하단 모달에서 상세를 보고 돌아오면 검색어와 목록 위치 유지 |
| 직접 등록·저장 | 업체명과 주소로 개인 장소 등록. 좌표가 없으면 ‘위치 미확인’. 장소를 저장하면 다른 여행에서도 선택 가능 |
| 숙소 | 숙박일·연박·예약 고정 선택, 선택한 밤만 교체, 다음 DAY 출발지 연결. 고정 숙소는 해제 전 다른 업체로 바꾸지 않음 |
| 일정 편집 | 여행 이름·출발일 변경, DAY 추가·복사, 장소와 연결 업체의 DAY 이동·복사, 업체 독립 방문 전환, 선택 메모·시간 |
| 복사·되돌리기 | 전체 개인 일정/하루/방문을 독립 복사. 마지막 변경 취소로 이전 DAY와 순서 복구 |
| 지도와 목록 | 동일 방문 번호와 선택 상태 연결. 핀을 누르면 해당 카드로 이동. 좌표 미확인 장소 제외. 경로 요청 실패·시간 초과·재시도 |
| 별도 여행기 | 개인 일정에서 별도 비공개 여행기 생성. 개인 메모·이동 메모·예약 고정을 자동 복사하지 않으며 이후 일정 변경과 작성 기록을 분리 |
| 작성 중 복구 | 글·사진·블록·선택 DAY 보관, 새로고침 후 복구, 직전 편집 되돌리기/다시 실행. 발행본은 최종 저장 전까지 유지 |
| 사진 여러 장 | 카드당 최대 8장, 사진별 설명·순서·삭제·여행기 표지 선택. 읽기 화면에서 좌우 넘김·PC 드래그·키보드 지원 |
| 기록의 DAY 이동 | 장소와 연결한 글/사진을 함께 이동. 글/사진만 다른 DAY로 옮기면 장소 연결 해제. 카드 이동은 동일 댓글, 복사는 새 댓글 공간 |
| 장소 카드 소통 | 랜드마크·식당·카페·숙소 카드 안의 좋아요/목록, 댓글·답글·수정·삭제 표시·신고 선택, 댓글 더 보기, 장소 카드별 입력 보관. 글/사진 블록과 여행 전체 댓글에서 구분 |
| 미리보기 | 글·사진·장소 순서를 보고 공개 범위를 선택해 저장. 공개 선택은 현재 로컬 미리보기임을 명시 |
| 하단 모달 보완 | 메뉴에서 설정/이동 모달로 전환할 때 바로 닫히던 오류 수정. 입력 굵기, 배경, 긴 내용의 내부 스크롤 확인 |

## 검증 결과

- 자동 검사 **94개 통과**, 웹 타입 검사와 빌드 통과.
- 저장 장소 → 당일 일정 → 주변 식당 담기 → 새로고침 후 순서 유지.
- DAY 추가, 숙소 상세 → 숙박일 → 예약 고정, 다음 DAY 출발지 연결.
- 출발일 적용, 검색 결과 없음 → 직접 등록, 좌표 미확인 업체의 지도 제외.
- 직접 등록한 업체 저장 → 주변 모달의 저장 목록 재사용.
- 검색 → 내부 상세 → 브라우저 뒤로가기 후 검색어·목록·초점 유지.
- 랜드마크와 업체 2곳을 다른 DAY로 이동 → 취소 → 기존 DAY/방문 순서 복구.
- 개인 일정과 여행기 분리, 글 작성, 사진 2장 첨부·설명·순서 변경 → 새로고침 후 복구.
- 사진 갤러리 키보드 이동과 실제 마우스 드래그, 사진 카드의 좋아요·댓글·답글과 재열람.
- 지도 번호와 카드 선택의 양방향 연결. 자동차 참고 경로를 실제 도보 시간으로 표시하지 않음.
- 320/390/460px의 일정·주변 업체·장소 메뉴·DAY 이동·댓글·미리보기 등을 검사. 일반 입력 16px/400, 검사한 화면/모달의 가로 넘침 0. 390×400px은 짧은 화면 검사이며 실제 Android 키보드 검사와 구분.
- 자동 검사는 복사 ID/연결, 발행본과 초안 분리, 저장 실패 시 원본 보존, 개인 업체 저장의 원자성, 댓글 권한·답글 보존, 기존 작성 날짜 보존을 포함함.

검수 자료: `artifacts/phase2-local-20260915/`. 소스 체크포인트는 제품·검사·문서를 포함하며 검수 스크린샷은 별도 로컬 자료다.

## 남은 결정과 실제 연동

1. **휴지통:** ‘내 여행 → 휴지통 → 복원/영구 삭제’, 개인 일정/여행기 개별 복원, 공개 여행기는 비공개 복원안을 질문한 상태다. 30일 보관 또는 기한 없이 보관 중 답변이 필요하다. 정책 확정 전 기존의 복구 불가 여행 전체 삭제 버튼을 제거했다. DAY/방문/본문 변경 취소는 구현했다. [기획안](TRASH_USER_FLOW.md).
2. **네이버·백엔드:** 업체 검색은 내부 예시/직접 등록 자료다. 실제 네이버 API, 업체 ID 매칭 서버, 순위/영업 정보, 계정, 사진 서버, 다중 사용자 댓글·신고 전달은 연결 전이다.
3. **앱 검수:** 실제 Android Chrome/WebView의 터치·키보드·뒤로가기와 기기 재실행은 실기기에서 추가 확인해야 한다.
4. **공개 전 성능:** 지도와 메인 화면 묶음의 빌드 크기 경고가 남아 있다. 운영용 로딩 성능 최적화와 실제 콘텐츠 수급은 별도 점검한다.

숙박 DAY 복사 시 숙박 다음 날을 함께 추가하고 새 날짜의 예약 고정은 해제해 재확인을 안내한다. 이미 예약한 원래 숙박일은 유지한다. 숙박 출발 DAY를 지울 때는 먼저 이전 밤 숙소 연결을 정리하도록 안내한다.

## 주차별 보관과 나중에 적용할 순서

- 기준: 1차 백업 `a123166932b8231119569bde6524bbecd7d2c85f`.
- 로컬 보관: `.git/spotlog-phase2/week1/`, `.git/spotlog-phase2/week2/`.
- 각 폴더: `manifest.json`(기준/트리), `changes.patch`(해당 주차 차이), `source.zip`(그 시점 전체 소스), `site/`(화면 빌드).
- **1주차 패치는 기준 커밋 위에, 2주차 패치는 1주차 위에 순서대로 적용**한다. 전체 소스 압축본과 구분한다. 1주차 보관본은 덮어쓰지 않았다.
- 커밋·브랜치 업로드·서비스 적용은 아직 수행하지 않았다. 적용 지시를 받으면 1주차 상태를 먼저 올리고 이후 2주차 차이를 올릴 수 있다. 휴지통 정책 확정 후 수정분은 추가 체크포인트로 보관한다.
- 코드 롤백과 기록 호환성은 별도다. 새 카드 댓글/개인 업체 저장 항목은 구버전에서 읽지 못할 수 있으므로 실제 롤백 전 데이터 사본과 호환성을 확인한다. 이번 주차별 검수 주소는 저장 공간을 분리했다.
- 공개 브랜치, 1차 GitHub 백업, 선택한 전체 일정 6행 표는 유지했다.
