# Spotlog 20주안 휴일 검토

검토일: 2026-09-15 · 상태: 비교용, 일정 변경 미확정

**기존 2027-02-02 목표의 [20주안](FIRST_RELEASE_20_WEEK_BASELINE.md)은 그대로 보관한다.** 이 문서는 휴일을 제외한 가용 시간과 가용 시간을 보충하는 경우를 비교한다.

## 현재 날짜를 유지할 때

09/15는 기존 산정과 같이 착수일로 별도 처리하고 09/16부터 계산한다. 토·일과 확인된 공휴일에는 작업하지 않는 기준이다.

| 단계 | 현재 일정 | 주수 × 5일 | 휴일 제외 가용일 | 줄어드는 평일 |
|---|---|---:|---:|---:|
| 1차 프론트 | 2026-09-15~2026-09-29 | 10일 | **8일** | 2일 |
| 2차 프론트 | 2026-09-30~2026-10-13 | 10일 | **8일** | 2일 |
| 3차 프론트 | 2026-10-14~2026-10-27 | 10일 | **10일** | 0일 |
| 백엔드 | 2026-10-28~2026-12-01 | 25일 | **25일** | 0일 |
| AI·RAG | 2026-12-02~2027-01-05 | 25일 | **23일** | 2일 |
| 앱 연결·출시 | 2027-01-06~2027-02-02 | 20일 | **20일** | 0일 |
| **전체** | **2026-09-15~2027-02-02** | **100일** | **94일** | **6일** |

프론트 6주는 가용 26일이고, 그중 1차와 2차가 각각 8일이다. AI/RAG의 5주는 달력상 유지됐지만 성탄절과 신정 때문에 가용 시간은 23일이다. 백엔드 5주는 25일, 마지막 4주는 20일이다.

이는 주수에 평일 5일을 곱한 참고 용량과 비교한 수치다. 실제 작업에 반드시 100인일이 필요하다고 측정한 결과는 아니며, 주개발 기간의 가용 평일과 담당자별 총 공수도 다르다. 따라서 6일 차이가 곧 확정 지연은 아니다. 다만 2주를 10평일로 생각해 기능을 배정했다면 1·2차 각각 2일이 부족하다.

## 각 단계에 주수 × 5평일을 확보하는 비교안

단계별로 10·10·10·25·25·20평일을 확보하고 다음 가용일에 바로 이어서 시작하는 가정이다. 보고는 화요일에 하되 단계 종료·인계까지 반드시 화요일로 미루지는 않는다.

| 단계 | 확보할 가용 평일 | 휴일 제외 순차 일정 |
|---|---:|---|
| 1차 프론트 | 10일 | 2026-09-15 착수 / 09-16 작업 시작~2026-10-01 |
| 2차 프론트 | 10일 | 2026-10-02~2026-10-19 |
| 3차 프론트 | 10일 | 2026-10-20~2026-11-02 |
| 백엔드 | 25일 | 2026-11-03~2026-12-07 |
| AI·RAG | 25일 | 2026-12-08~2027-01-13 |
| 앱 연결·출시 | 20일 | 2027-01-14~2027-02-12 |
| **전체** | **100일** | **2026-09-15 착수~2027-02-12** |

계산상 마지막 작업일은 **2027-02-12(금)**이고 이후 화요일 보고 기준은 **02-16(화)**이다. 02/02에 달력 날짜 6일만 더하는 방식은 맞지 않는다. 공휴일과 주말을 제외해 기간을 늘리면 02/08·02/09 설 연휴도 새로 포함되므로 보충할 평일이 총 8일이 된다.

02/16은 종료 결과를 보고할 수 있는 다음 화요일이지, 앱 심사 승인을 보장하는 오픈 날짜가 아니다. 매 단계의 종료도 화요일에 맞추고 그 뒤에만 다음 작업을 시작한다면 위 표보다 추가 시간이 생긴다.

## 판단

- 현재 20주·02/02안은 보관한다. 프론트 1·2차의 가용 8일과 AI/RAG 23일 안에 범위가 맞는지 확인할 기준으로 사용한다.
- 기간을 온전한 평일 수로 확보하는 비교안은 02/12 계산 종료·02/16 화요일 보고다. AI/RAG에는 25평일을 배정하며 기간을 줄이지 않는다.
- 팀 휴가·연말 휴무·임시공휴일·자료 지연·추가 기능·심사 보완은 이번 달력 계산에 포함하지 않았다. 주말/휴일 근무로 차이를 메우는 전제도 없다.
- 이 검토만으로 현재 보관 일정을 교체하거나 02/16을 새 납기로 확정하지 않는다.

09/15에도 기능 작업을 하루 온전히 수행하는 가정을 쓰면 현재 안의 가용일은 95일이고 100평일 확보 비교안은 02/11 종료가 된다. 기존 표와 일관되게 이번 본문은 09/15 착수 별도 기준을 유지했다.

이번 작업은 일정 보관과 휴일 비교 문서 작성이며 실제 개발·공개를 실행하지 않는다.
