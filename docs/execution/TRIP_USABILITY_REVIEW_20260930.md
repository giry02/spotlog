# 내 여행 사용·수정 기능 로컬 검수본

2026-09-30. 상태: 로컬 구현·개발 검수 완료, 사용자 화면 검수 대기. 사용자 확정 후 실제 소스 구현 대화창에 넘길 검수본. 이번 변경은 GitHub·공개 사이트에 반영하지 않음.

작업 순서: 이 대화창에서 기존 검수본 구현 → 사용자 확인·수정 → 확정 기능·화면·데이터 기준을 실제 구현에 인수인계. 앞서 실제 구현 대화창에 전달한 추가 기능 실행은 보류로 정정. 실제 구현 작업본에 남은 추가 기능 초안은 이후 승인된 검수본과 대조할 대상이며 이번 화면 반영과 별개.

## 확인 주소와 사용 순서

- [기존 로컬 사이트 · 내 여행](http://127.0.0.1:5210/#trips). 여행을 열고 장소의 `…` 메뉴에서 조작.
- [바로 조작하는 격리 검수 화면](http://127.0.0.1:5210/tests/trip-usability.html). 식당·카페·예약 고정 숙소·시간 부족 구간을 준비한 DEV 전용 화면. 업체·주소·좌표는 검수용 가상 데이터, 사진은 검수용 도형. 실제 사용자 저장소와 제품 데이터는 사용하지 않음. 저장 실패는 자동 검사에서 별도로 재현.

| 기능 | 조작 | 결과 |
|---|---|---|
| 방문 진행 | 장소 `…` → 미방문/완료/건너뛰기 | 원래 카드·순서 유지. 표시와 다음 미방문 장소 안내. 되돌리기 가능 |
| 이어서 방문 | 진행 요약 → 이어서 방문/길찾기 | 같은 DAY의 남은 장소 확인·네이버 길찾기. 새로고침 뒤 선택 DAY·방문 복원 |
| 한 곳 교체 | 음식점·카페 `…` → 이 장소만 다른 곳으로 교체 | 같은 종류·지역 후보 → 선택 → 이곳으로 교체. DAY·순서·시각·랜드마크 연결 유지 |
| 경고에서 수정 | DAY 지도 → 구간 확인·수정 | 앞 장소 체류시간, 다음 방문 시각, 다른 DAY 이동, 식당·카페 후보 교체로 연결 |

완료·건너뛰기는 일정 삭제와 구분. DAY를 모두 확인하면 남은 방문이 있는 DAY로 이어가기. 모든 담긴 방문을 처리하면 전체 확인 완료 안내. 미방문으로 되돌릴 수 있음.

교체 확인 전·취소·저장 실패 때 원래 업체 유지. 같은 DAY의 중복 후보와 현재 업체는 선택 불가. 새 업체로 교체할 때 이전 업체의 개인 메모·예약 관련 속성·완료 기록을 옮기지 않음. 확인 화면에서 안내하고 마지막 변경 취소로 되돌릴 수 있음. 기존 숙소 예약 고정·연박 처리 유지.

실제 경로·운영 정보의 확인 완료를 약속하지 않음. 시간 부족은 추정으로 표시. 도보 시간과 위치 미확인은 별도 코드로 표시. 좌표 미확인 방문을 건너뛰어 앞뒤 장소의 시간 충돌을 확정하는 비교는 하지 않음.

## 화면 기준과 검수 결과

기존 커버·DAY 줄·사진·카드·주변 업체 버튼을 유지. 320px에서 카드 행동 줄에 완료 아이콘을 추가하면 주변 업체 버튼이 줄바꿈되는 문제가 있어, 방문 상태 조작은 기존 장소 메뉴에 모음. 완료/건너뛰기 상태만 카드에 표시.

- 수정 전/후 동일 검수 데이터, 320·390·460px 비교. 커버230px·사진56px·장소명16px 유지.
- 새 메뉴 보조 버튼36px·12px/700, 일반 입력16px/400. 새 기능 범위에서만 CSS 적용.
- 화면30개 상태: 초기/진행/장소 메뉴/교체 목록/확인/실패/지도 경고/경고 수정/전체 방문 확인. 가로 넘침과 브라우저 실행 오류0건.
- 실제 조작: 완료·건너뛰기·취소·새로고침, 식당·카페 교체, 교체 취소/저장 실패/확정/되돌리기, DAY 변경 뒤 마지막 변경 취소, 경고에서 시간 수정, 남은 DAY 연결·전체 방문 확인.
- 별도 터치 에뮬레이션: DAY 복사 후 진행 기록 초기화·선택 DAY 재접속, 실제 App의 저장소 읽기와 지도 경고→DAY 이동 연결, 320px 영어 메뉴·교체 확인. 실제 Android/iOS 실기기 검수와 구분.
- 자동 검사264개 통과, 타입 검사·웹 빌드 통과. 빌드의 기존 대용량 번들 안내는 남음.

근거: `artifacts/trip-usability-20260930/unit-results.txt`, `ui-results.json`, `integration-results.json`, 수정 전·후 PNG. 원본 변경 전 파일은 같은 폴더의 `before/`에 보존. 검수 전용 비교 서버는 최종 확인 후 종료, 본 사이트5210 유지.

## 데이터와 실제 구현 인수인계 기준

검수본은 기존 로컬 저장소를 사용. 실제 API/DTO의 확정안은 아님.

| 항목 | 검수본 처리 | 실제 구현에서 맞출 기준 |
|---|---|---|
| 방문 진행 | 개인 Journey의 `travelProgress`에 DAY/현재 방문 및 visitId별 done/skipped·기록 시각 | 회원 소유 tripId+visitId. 공용 Place에 상태를 쓰지 않음. 서버 시각·버전·권한·계정별 동기화 합의 |
| 미방문 | 상태 기록 없음 | 상태 초기화/취소 규격 합의 |
| 복사·생성·공개 | 새 방문ID, 완료 기록 초기화. 여행 복사·여행기 생성에서 전체 진행 정보 제외 | 복사와 공개용 DTO에 개인 진행 정보 섞이지 않도록 검사 |
| 장소 교체 | 같은 visitId·DAY·순번·시간·앵커, placeId와 사진/소개 변경. 이전 메모/방문 상태 초기화 | 원자적 교체, expectedVersion·중복 요청·실패 복구, 유지/초기화 필드 합의 |
| 경고 | code·visitId·fromVisitId·근거 상태·출처·가능한 행동 | 안내 문구만 보내지 않고 대상 방문/구간 ID와 actions 반환. 실제 경로 미확인 표시 유지 |
| 이동 위치·되돌리기 | DAY/현재 방문 커서 이동은 마지막 실질 변경 취소를 무효화하지 않음 | 서버 저장 순서·버전 충돌 규칙으로 옮겨 구현. 로컬 JSON 비교를 서버 충돌 제어로 그대로 쓰지 않음 |

같은 장소를 여러 DAY에 방문하면 visitId가 달라 별도 기록. 방문을 이동하면 기록 유지, 복사하면 새 방문의 기록 없음. 삭제·교체 이후 남지 않은 방문의 진행 정보 정리. 일정에 속한 시각과 업체에 속한 정보는 구분.

현재 검수본은 로컬 단일 프로필 기준. 실제 회원 인증·기기 간 동기화·실시간 운영 정보·실제 도보/대중교통 경로·AI 업체 추천은 서버 단계에서 연결. 맥미니 AI/RAG 구축 작업은 이번 범위에 포함하지 않음.
