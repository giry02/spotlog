## 한 장에 포함한 구성

| 영역 | 구성 | 역할·상태 |
|---|---|---|
| 내부 고객 화면 | React 웹 · Expo WebView 앱 | 기존 시제품. 발견·찜·AI 간단 생성·내 여행·여행기·카드 댓글. 초기에는 간단 생성에 실제 AI 연결, 챗봇은 향후 별도 진입점 |
| 내부 관리자 | 장소·업체·콘텐츠 검수 화면 | 신규 구축. 허가 자료 등록·중복·좌표·출처·추천 기준 검수 |
| 서비스 접속 | 도메인·HTTPS·요청 전달 | 호스팅 선택 예정. 특정 API Gateway 제품이나 별도 마이크로서비스 도입 확정 아님 |
| 내부 Spotlog 서버 | 인증·권한·회원·여행·검색·검증·저장 | 신규 구축. API는 연결 방식. 조회 도구·자료 등록·RAG 검색·업로드 권한을 같은 서버의 역할로 표현 |
| 자체 운영 연결 도구 | 맥미니 Flowise | AI 모델·챗봇 화면 아님. 초기 간단 생성에도 외부 AI·내부 조회 도구 연결용으로 재사용 가능. Spotlog 연결·주소·버전·Flow·인증·운영 배치 확인 전 |
| 기본 소형 언어 모델 | 입력 조건 해석·근거 기반 설명. 향후 대화에도 재사용 | 외부 API 또는 자체 운영 평가 후 선택. 정확한 제공자·모델 미선정 |
| 예외 외부 대형 LLM | 미해결 조건·DAY·항목·설명만 보완. 같은 근거·검증, 통과한 일정 보존 | 외부 API. 제공자·모델 미선정. 서버 판정 후 Flowise 경유 |
| 내부 DB | PostgreSQL + PostGIS + pgvector | 신규 구축 권장안. 회원·장소·순위·여행·사진 연결 정보·허가 설명 색인. 대화 기록·세션은 향후 추가 |
| 우리 파일 저장 영역 | 사진 저장소 · 외부 제공자 미정 | 신규 구축. 우리 사진 원본·접근 권한 관리, 이를 운영할 외부 저장소 서비스 선택 예정 |
| 외부 임베딩 AI | 허가 설명·검색 문장을 검색용 숫자로 변환 | 제공자 미정. 생성형 AI와 별도 모델 선택, 우리 서버에서 API로 호출 예정 |
| 외부 지도 서비스 | NAVER Maps | 지도 표시·지원 자동차 경로·주소 조회 연결 예정. 현재 MapLibre/OSM 시제품 |
| 외부 업체 검색 서비스 | NAVER API HUB 검색 | 사용자 요청에 따른 외부 업체 후보 조회. Maps와 별도 서비스 |
| 자료 | 자체·업체·허가된 공공자료 | 공급 범위·권리 확인 후 서버 등록·검수 |
| 운영 | 호스팅·로그·백업·삭제 작업 | 신규 구성. 운영 제공자·배치 미정 |

## 주요 연결

- 고객·관리자 화면 → 서비스 접속 → Spotlog 서버
- Spotlog 서버 → PostgreSQL: 조회·소유권 확인·검증 후 저장
- 초기 AI 간단 생성 → 우리 Spotlog 서버 → 자체 운영 Flowise → 소형 언어 모델: 지역·기간·취향·음식점/숙소 요청 인식
- 우리 DB·RAG → 서버 일정 구성·계산 → 소형 설명 → 서버 검증. 소형 모델의 실패 부분만 대형에 전달 → 같은 검증 후 병합
- 데이터 부족·지도 실패·불가능한 조건: 추가 확인·조회 재시도·부분 결과. 대형 모델로 없는 사실 생성 금지
- 향후 챗봇 → 우리 Spotlog 서버: 대화 세션·필요한 이력을 조건으로 정리 → 같은 장소 검색·일정 생성·검증·저장 기능 호출
- Flowise 조회 도구 → Spotlog 서버 → 장소 DB·의미 검색: 확인된 후보·근거 반환
- Flowise 초안 → Spotlog 서버 검증 → 화면 미리보기 → 사용자 저장 요청 → DB
- 우리 Spotlog 서버 → 외부 네이버 Maps: API로 자동차 경로·주소 조회
- 우리 Spotlog 서버 → 외부 네이버 API HUB 검색: API로 업체 후보 조회
- 고객 화면 → NAVER Maps SDK: 지도 표시. 화면 직접 연결은 도면 C 메모에 별도 표시
- 서버 업로드 권한 발급 → 고객 화면 → 사진 저장소: 직접 업로드
- 업로드 완료 → 서버 확인 → DB: 사진 소유권·파일 연결 정보 기록
- 허가 자료 → 서버 등록·검수 → 장소 DB
- 허가 설명 → 우리 서버 → 외부 임베딩 AI: API로 검색용 숫자 변환 요청 → 우리 서버 → 같은 장소 ID로 pgvector 색인
- 검색 문장 → 우리 서버 → 외부 임베딩 AI: API로 검색용 숫자 변환 요청 → 우리 서버 → pgvector 검색 → 관련 장소 ID로 DB 결합

## 초기와 향후의 경계

- 초기 입력: 기존 요청문·지역·기간·속도·이동수단·‘저장 장소로 추천’ 유지. 자유 문장에서 조건을 인식하고 부족한 필수 조건만 간단 필드에서 보완
- 초기 결과: 요청에 맞춰 DAY·방문·식사·숙박을 갖춘 초안 → 상세에서 선택 수정 → 명시적 저장. 날짜·예약·식당·숙소 후보 사전 선택 강요 없음
- 초기 통신: 요청 단위 실행. 화면 입력·초안 보존은 필요하지만 다중 턴 채팅 세션·대화 메모리는 필수 아님
- 향후 추가: 챗봇 화면·사용자별 대화 세션·질문 이어가기·대화형 부분 수정. 기존 간단 생성은 계속 제공, 별도 추천·생성 엔진 중복 구축 없음
- Flowise 재사용: 초기 실행 순서를 연결하는 자체 운영 도구로 활용 가능. Flowise 활용 시점과 챗봇 공개 시점 분리

## 도면 읽는 기준

- 색상: 화면 / 서버·연결 도구 / 데이터 / 외부 연결 구분. 색상과 별도로 내부·자체 운영·외부 명칭 표시
- API: 연결 방식. AI·일반 서비스의 종류나 내부/외부 소속을 뜻하지 않음. 대상 이름·연결 방향과 함께 표기
- AI 역할: 소형은 의도 이해·근거 기반 설명, 대형은 조건부 부분 보완, 임베딩 AI는 검색용 숫자 변환. 실제 일정 계산·검증·저장은 우리 서버
- Flowise: 맥미니에서 자체 운영하는 연결 도구. AI 모델·챗봇 화면·외부 모델 제공자 아님
- 우리 사진 저장소: 우리 파일을 보관하는 논리 영역. 외부 저장소 공급 서비스와 구분, 제공자 미정
- 상태: 기존 시제품 / 기존 도구 재사용 / 신규 구축·연결 예정 문구로 구분
- 화살표: 호출·조회 방향. 응답은 역방향, Flowise 조회 도구는 서버로 되돌아오는 연결
- PostGIS·pgvector: PostgreSQL 확장. 별도 서비스 DB 세 개로 분리하지 않음
- 장소 ID·주소·좌표·순위: 우리 DB 기준. RAG는 허가된 설명을 찾는 기능
- 네이버 검색 결과: 내부 DB·RAG 자동 적재선 없음
- 인증: 서버의 공통 책임. 외부 인증 제공자 선택 전
- 내 여행: 비공개 개인 일정. 여행기 공개는 별도 선택
