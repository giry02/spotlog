## 변경한 사용자 흐름

요청 입력 → 하루 흐름이 있는 초안 → 바로 저장 또는 ‘일정 수정’.

초기 결과에서 업체를 일일이 고르는 영역을 제거했다. 식당·카페·숙소 후보 검색과 개인 업체 등록은 명시적으로 수정을 선택했을 때만 열린다. 기존 디자인의 장소 행·하단 팝업·버튼 역할을 재사용한다.

| 내용 | 이번 동작 |
|---|---|
| 요청 해석 | 식사/카페/숙박 포함·제외와 예약 표현을 샘플 규칙으로 반영 |
| 기본값 | 일반 여행은 점심·저녁 포함, 카페는 명시 요청 시, 2일 이상은 숙박 제안. 관광지만/제외/예약 요청이 우선 |
| 하루 흐름 | 오전 → 점심 → 오후 → 저녁 → 숙박. 식사에는 앞뒤 랜드마크를 표시 |
| 도착·출발 | 지정한 첫날 도착/마지막 날 출발 범위 밖의 식사 구간은 제외 |
| 업체 선택 | 같은 지역의 등록 업체를 기준 랜드마크의 직선거리로 고른다. 같은 날 점심·저녁에 같은 업체를 자동 중복 추천하지 않음 |
| 자료 부족 | 업체가 없으면 시간대의 ‘장소 미정’을 남김. 가짜 업체·좌표를 생성하지 않음 |
| 예약 숙소 | 확인 가능한 예약 숙소는 고정. 이름을 모르면 ‘예약한 숙소 이용’ 구간으로 남기고 새 호텔을 추천하지 않음 |
| 식사 수정 | 선택한 DAY와 점심/저녁을 유지해 교체. 다른 식사·다른 DAY·숙박은 보존 |
| 직접 등록 | 수정에서만 사용. 이름·주소와 DAY/기준 장소/시간대를 보존. 좌표 없는 개인 업체는 위치 미확인 |
| 지역 | 저장 장소가 여러 지역이면 지역 선택을 요구. 선택 밖 장소는 미배치 사유와 함께 대안에 보존 |
| 초안 | 닫기·재진입과 기기 저장을 유지. 이전 생성 기준 초안은 입력·선택을 보존하고 재생성 안내 |
| 실제 저장 | 시간대와 미정 구간도 내 여행에 저장. 완료 초안은 다시 중복 저장하지 않음 |
| 복사·이동 | 새 DAY/방문 ID와 미정 구간의 참조를 맞추며, 다른 DAY로 옮긴 방문의 오래된 시간대는 해제 |
| 여행기 전환 | 개인 계획용 시간대·미정 구간 정보를 제거해 여행기와 분리 |

랜드마크를 제외할 때 연결된 예약 숙소까지 자동 삭제되는 문제를 추가로 발견해 예약 숙소는 유지하고 연결만 해제했다. 사라진 랜드마크를 가리키던 미정 구간 참조도 정리했다.

## 직접 확인한 예

로컬 홈 → AI 여행 만들기에서 `제주 1박 2일, 바다를 보고 맛집도 넣어줘. 카페는 빼줘.` 입력:

1. DAY 1 오전 협재해수욕장
2. 점심 수우동 — 협재 방문 후, 오설록 방문 전
3. 오후 오설록 티뮤지엄
4. 저녁 — 등록 후보 부족으로 미정
5. 숙박 제주신화월드 메리어트

이것은 등록 샘플에서 생성한 결과다. 운영 여부·음식 제한·도로 이동 가능성을 실제 검증한 추천이 아니다. 후보가 적어 미정이 생기는 상황을 감추기 위해 새 업체를 추가하지 않았다.

수정에서 저녁 구간을 선택하고 기존 등록 식당을 명시적으로 고르자 저녁 위치에만 추가됐다. 팝업을 닫아 다시 열었을 때도 남아 있었고, 내 여행에 저장한 8개 방문에서도 점심·저녁·숙박 순서가 일치했다. 동일 업체의 점심/저녁 사용은 이 명시적 수정에서만 선택한 테스트다.

`관광지만 짜줘. 식당 넣지 마, 카페 추천하지 마.`는 업체 없이 랜드마크만 생성했다. `숙소 이미 예약.`은 새 호텔을 넣지 않고 기존 예약 구간을 남겼다. 마침표가 있는 짧은 예약 표현도 브라우저 검수에서 발견해 보완했다.
