| 새 여행 입력 | 지역·선택 장소·기간·제목·선택 출발일을 검증된 로컬 초안으로 보관. 닫기·새로고침 후 복원. 직접 해제한 장소는 자동으로 다시 선택하지 않음. 생성 저장에 성공하면 해당 입력 초안 정리 |

| 숙소 후보 | 첫 담기에서 숙박일 확인. 같은 팝업에서 같은 기간의 다른 숙소는 목록에서 한 번 담기. ‘숙박일·기간 변경’으로 다른 밤·기간 지정. 예약 고정은 별도 확인 화면을 거침 |

## 관리자

| 항목 | 수정한 동작 |
|---|---|
| 목록 필터 | 지역·검색·공개 상태를 먼저 표시. 종류·담당 직원·검수 상태는 추가 필터. 필터 초기화 한 번으로 작업 지역을 유지한 채 나머지 조건 해제 |
| 장소 상세 | 상세 진입 시 목록 필터를 요약으로 접음. 담당/검수 정보도 현재 상태 요약에서 펼침. 장소명·주소·종류를 기본 정보 상단에 배치. 1024px에서도 주요 입력 두 열 유지 |
| 지역 관리 | 운영 현황에서 지역 관리 탭으로 직접 이동 |
| 담당 검수 | ‘내 담당 자료 → 검수 이어하기’에 현재 운영자와 확인 필요 필터 전달. 공개 자료의 수정 검수도 포함하도록 공개 상태를 초안만으로 제한하지 않음 |
| 실패 작업 | 알림 실패·수급 실패를 구분하고 해당 탭의 실패 목록으로 이동. RAG 갱신 실패는 색인 작업의 실패 필터로 이동. 처리 후 비어 있는 목록에는 빈 상태 안내 |
| 화면 간 전달 | 현재 메뉴에만 바로가기 동작을 전달. 숨겨 둔 다른 메뉴가 동작을 소비하거나 다른 대상 ID를 적용하지 않도록 화면별 선택 대상을 보관 |
| 기존 업체 자료 | 이전 마스터 갱신을 완료한 기기에도 새 지역 업체18곳을 별도 갱신 버전으로 추가. 기존 수정·공개본·삭제 이력·사용 조건 유지. 반복 실행 시 중복 추가 없음 |

자료 수 비교: 신규 자료를 제외한 이전 검수 저장소89개 → 추가 반영107개. 카탈로그 원본101개＋별도 검수 샘플6개. 운영자가 이미 삭제한 항목은 이 개수보다 적을 수 있으며 삭제 이력이 우선. 실제 서비스 DB 등록과 공개는 별도 연결 단계.

1440×1000 기준 장소명 입력 시작 위치 약1000px → 681px, 종류 입력 약905px → 774px. 1024px에서는 장소명709px·종류802px로 주요 입력과 하단 작업 버튼이 겹치지 않음.
