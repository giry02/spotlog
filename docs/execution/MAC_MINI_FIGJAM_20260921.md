## 배치·표현

- 기존 00~10 우측 빈 공간에 3개 도면 추가. 원본 도면 삭제 없음.
- FigJam 기본 도형·텍스트·연결선으로 작성. 각각 수정 가능.
- 한 상자에 처리 하나, 제목과 짧은 역할·주고받는 자료 분리.
- 색상: 파랑은 우리 서비스 처리, 보라는 로컬 AI, 초록은 데이터·저장, 주황은 외부 서비스, 회색은 향후·안내.
- 11번 양방향 화살표는 요청·응답. 12·13번은 왼쪽에서 오른쪽, 위에서 아래 순서.
- AI 연결 서비스·Flowise·Ollama는 연결·실행 도구. 언어 AI·임베딩 AI와 별도 명칭 사용.
- 큰 흐름과 실패 정책을 다른 구역으로 분리. 긴 정책 문단을 처리 상자 안에 넣지 않음.

## 유지한 연결 기준

- 서비스 서버·DB 신규 구축. 회원·권한·원본 장소·주소·좌표·순위·여행의 기준은 서버.
- 맥미니 RAM 64GB와 기존 Flowise만 사용자 확인. 칩·OS·설치 방식·네트워크·실제 상시 운영 여부 미확인.
- 로컬 소형 모델 Qwen3.5 9B, 임베딩 Qwen3 Embedding 0.6B, Ollama, PostgreSQL+pgvector는 첫 시험안. 채택·설치 완료 표기 아님.
- 맥미니 검색 DB는 서비스 원본 DB와 별도. 같은 placeId와 문서 버전으로 연결.
- 맥미니 소형 LLM이 조건 해석·허용 근거 설명 담당. 서버가 검증·후보 제한·최신 좌표/순위 결합·DAY/식사/숙박 계산. Jev는 선택 비교 후보로 분리.
- 고객 글 또는 저장 장소로 간단 생성 우선. 완성 초안을 먼저 보여주고 상세 수정은 선택.
- 외부 대형 모델은 근거가 충분한 모델 실패에만 서버 승인 후 부분 보완. 같은 검증 통과 후 병합.
- 자료 부족·지도 실패·PC 중단은 대형 모델로 사실을 만들어 해결하지 않음.
- 네이버 지도 표시, 서버 경로·주소 조회, 업체 검색은 별도 연결. 외부 검색 결과의 DB·RAG 자동 적재 제외.
- 내부 규격 3개는 제안: 조건 인식, 근거 검색, 설명. 실제 배포 경로 아님.
- 챗봇은 향후 화면 추가. 동일 생성·검색·검증·저장 기능 재사용.
- 맥미니는 고객 여행을 직접 저장하지 않음. 최종 저장과 소유권 검증은 서비스 서버.
