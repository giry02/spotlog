# 로그인 경로 교정 · 바로 로그인하는 로컬 검수 계정 · 2026.10.08

사용자 지적: 간편 로그인에서 바로 가입 화면으로 넘어감, 이메일 로그인도 비활성이라 확인할 수 없음. 후속 요청: ‘아이디 패스워드 넣어놔 바로 로그인하게’. 명시적 요청에 따라 기존 실제 인증 연결 기준과 별도로 **로컬 검수 로그인** 추가. 작성 시점에는 로컬 검수만 진행. 이후 사용자 Git 업로드 요청에 따른 반영 범위는 `CUSTOMER_FRONTEND_UPLOAD_20261008.md` 참고.

## 바로 확인

[프로필 열기](http://127.0.0.1:5210/#profile) → 로그인 → 미리 채워진 이메일 로그인 버튼 한 번. 성공하면 팝업을 닫고 ‘검수 여행자’ 화면으로 복귀.

| 구분 | 검수 값 |
|---|---|
| 이메일/ID | `demo@spotlog.test` |
| 비밀번호 | `SpotlogDemo123!` |
| 화면 표시 | 로컬 검수 계정 · 실제 서비스 회원 아님 |
| 로그인 복원 | 같은 탭의 새로고침 후 유지 |
| 로그아웃 | 검수 로그인 여부 제거, 비로그인 화면 복귀 |

이 값은 공개된 검수용 입력이며 실제 서버의 회원·인증 정보가 아님. 탭 sessionStorage에는 ‘signed’ 표시만 저장, 이메일·비밀번호·권한 토큰 저장 없음. 저장소 사용 불가 시 해당 화면 메모리로만 유지. 실제 계정 자료로 기기 기록을 자동 병합하지 않음. 검수 회원 ID는 고정된 별도 ID로 신규 댓글/반응 검수에 사용.

`AccountProvider`는 DEV＋`VITE_ACCOUNT_ENDPOINT`미설정 때만 검수 어댑터 선택. API설정 시 기존 실제 어댑터가 우선하며, production 빌드에서 검수 이메일·비밀번호·회원ID 문자열이 포함되지 않는 것을 확인. 검수 mode는 실제 서비스 보안·권한 검사 대체로 사용하지 않음.

## 간편 로그인 교정

원인: `AccountSheet.begin()`에서 미연결 또는native일 때 `changeView('consent')`를 호출. 제공자 인증 결과 없이 신규 가입 동의를 표시하고, 기존 로그인 입력도 비워지는 동작이었음.

- 버튼명 ‘Google로 로그인’, ‘Apple로 로그인’. 기존 회원이면 로그인, 처음이면 제공자 인증과 서버 pending확인 후 약관.
- 미연결/로컬 검수모드/native인증 준비 전은 로그인 화면에서 해당 버튼 근처 안내. 이메일 입력 유지. 빈 가입 화면으로 이동하지 않음.
- 제공자 인증 시작이503/409/401/429등으로 실패해도 로그인 화면 유지. 특히 소셜409를 이메일 인증 미완료로 오해하여 인증번호 화면으로 넘기지 않음. 이메일·비밀번호와 일반 로그인 버튼 유지.
- 서버 callback의 `SIGNED_IN`은 기존 회원 프로필, `PENDING_SIGNUP`만 필수 동의 화면. Google/Apple 신규 분기를 각각 DEVfixture로 검수. 실제 OAuth등록·제공자 연결은 별도 서버 작업.

검수 이메일 로그인 이외 가입·메일/번호/비밀번호 재설정·소셜 인증·회원 탈퇴는 가짜 완료를 제공하지 않음. 정책은 계속초안, 가입 및 메일 요청 차단. 실제 메일 인증 가입 화면은 기존 서버 계약대로 유지.
