## 기존 그림의 누락·오해 수정

- 관리자 역할이 자료 검수 한 줄에만 존재 → 독립 관리자 업무 그림 추가, 전체 구성도에 관리자 클라이언트와 목표 내부 API 표시
- 지역·담당 업무 누락 → 지역 계층, 등록자·담당자·검수 상태·자료 묶음 연결. `createdById / assignedToId / reviewStatus / sourceBatchId` 사용
- 자료를 가져온 것과 승인한 것 혼동 → 고객 장소83개·미디어77개·출처22개는 미승인 초안, 합성 검수 장소6개 별도 표시
- 수정 중 공개본 노출 가능성 → 수정 초안과 공개본 분리, 명시적 공개 전 기존 공개본 유지
- 운영 추천 생성 흐름 누락 → 공개 가능한 등록 장소로 DAY·식사·숙박·사진·소개 초안 구성, 필요한 곳 수정, 비공개 미리보기 후 명시적 공개
- 실제 AI 생성으로 오해 → 현재 관리자 운영 추천 자동 초안은 `LOCAL_RULES`, LLM 호출 없음. 고객 AI·맥미니 RAG는 목표 연결로 표시
- 홈 추천과 고객 공개 여행기 혼동 → 홈 추천7개는 `sourceTemplateId`를 유지하는 비공개 수정 초안, 공개 읽기 여행기12개 별도
- 고객 신고와 관리자 조치 단절 → 5종 공개 대상 신고, 대상 ID·DAY·카드·사진·출처 문맥 확인, 사유 있는 조치·이력·고객 결과 연결
- 번역 완료 범위 과장 → 승인된 본문·장소 소개 연결, 나머지 원문 전체 번역은 연결 대기 표시
- 실서비스 연결로 오해 → DEV 공개 검수 투영과 서비스 API/DB 목표를 별도 표시. 실제 인증·권한·DB 처리는 서버 연결 대기
- 개인정보 제외 범위 불명확 → 공개 검수·관리자 기본 조회에서 개인 일정·예약·메모·AI 요청·대화 원문 제외. 서비스 DB 자체에 개인 여행을 저장하지 않는다는 의미 아님
- 오래된 도면 번호 → 현재 실제 제목 기준 00~13 목차와 링크 정정. 10 맥미니 전체, 11 요청 처리, 12 RAG 갱신, 13 관리자

## 유지한 기준

- 고객 내 여행은 개인 일정, 여행기는 별도 공개 기록. 운영 추천 여행기는 운영 콘텐츠로 구분
- 한 지점은 같은 `placeId`. 주변 관계는 랜드마크 `placeId`＋업체 `placeId`, 직선3km 기본/15km 확장
- 추천 선정도 공개·영업·좌표·사용권 기준 통과 필요. 제외는 해당 랜드마크에만 적용
- 소형 로컬 LLM 기본. 원본 DB는 사실·좌표·상태, RAG는 승인 설명 검색
- 근거가 충분한 모델 실패만 외부 대형 보완. 요청 전체 최대1회＋시간/비용 한도＋동일 서버 재검증
- Jev는 선택 비교 후보, RAG 검색 담당 아님. Flowise는 내부 실행 도구
- 향후 챗봇은 같은 검색·생성·수정·승인 저장 기능 재사용. 고객 명시적 조작 없이 저장·공개·삭제 없음
- 관리자 숨김·정지와 사용자 삭제/비공개 우선순위 유지. 휴지통은 한국 시각 달력6개월
