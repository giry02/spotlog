# Spotlog 1·2·3차 화요일 고객 보고·단계별 공개 일정안

> **이전 일정안:** [최신 첫 오픈 24주 세부 일정](FIRST_RELEASE_24_WEEK_PLAN.md)의 화요일 보고 24회를 확인한다. 최신안은 프론트 기획·고객 수정과 별도 AI/RAG 인원을 반영한 순차 개발이며 2027-03-02 첫 오픈 목표다. 아래 2026-12-22 목표는 이전 제안 이력이다.

작성일: 2026-09-15 · 상태: 검토용 제안 · 첫 보고 2026-09-22 · 최종 시범 검수 목표 2026-12-22

## 1. 일정의 목적과 기준

개발은 고객 공개보다 앞서 진행하고, 매주 화요일에는 검수가 끝난 누적 버전을 보여준다. 각 날짜는 고객 보고 목표일이며 구현 완료나 배포 실행 기록이 아니다. 공개 직전까지 미완성 기능을 계속 섞지 않고, 고객이 검토한 버전과 피드백을 함께 남긴다.

1·2차의 고객 보고는 앞서 제안한 09/22~10/27의 6회를 유지한다. 3차는 실제 서버·AI·경로·번역 연결과 사용자 검토를 포함해 11/03~12/22의 8회로 나눈다. 전체는 착수 기준 14주이며, 이 기간 전체가 순수 코딩 시간은 아니다. 기능 개발·본인 검수·고객 피드백·수정·외부 연동 확인을 포함한 공개 일정이다.

기존 PHASE_1/2/3 및 Excel의 30/40/30작업일 계획은 샘플과 로컬 기능 중심이었다. 이 문서는 실제 연동을 포함한 별도 일정안이며, 기존 문서나 Excel을 수정하거나 모든 날짜를 동기화한 것이 아니다. 구현에 착수할 때 합의된 범위와 실제 준비 상태를 기준으로 진행 기록을 작성한다.

최종 목표는 서울·부산·제주 중심의 제한된 시범 운영이다. 첫 실제 AI는 부산 1개 지역·당일 일정으로 시작하는 가안이다. 기존 부산 자료를 재사용할 수 있는지 확인한 뒤 09/29까지 지역을 결정한다. 전국 콘텐츠 완비·모든 이동 구간·상용 대규모 운영 완료를 의미하지 않는다.

## 4. 3차 주차별 상세 작업과 고객 검토

### R07 · 11/03 · 실제 계정과 서버 저장

- 개발: 로그인 1종, 여행·DAY·방문·블록·사진 저장, 접근 권한, 공개/비공개, 가져오기 전 백업과 기존 로컬 기록 이전을 연결한다. 공개 범위 변경과 기본 계정 삭제·데이터 정리 경로를 준비한다.
- 고객 시연: 로그인 → 여행 작성/사진 추가 → 재접속 또는 다른 기기에서 확인 → 다른 계정으로 비공개 접근 확인.
- 본인 검수: 이전 취소·일부 실패·중복 가져오기·사진 실패 시 기존 기록 보존, 동시에 수정한 기록의 충돌 안내.
- 피드백: 로그인 진입 위치, 저장 상태 문구, 기록 가져오기 흐름, 공개 범위 설명.
- 선행: 10월 중 데이터 구조와 서버 시험 환경을 준비한다. 신규 서버 작업 전부를 10/28에 처음 시작하는 일정이 아니다.

### R08 · 11/10 · 실제 소통과 추천 자료 기반

- 개발: 2차의 카드 소통 화면을 실제 계정·서버와 연결한다. 댓글·답글·수정·삭제·좋아요 중복 방지, 기본 신고 접수·숨김·차단, 공개 범위에 따른 접근을 구현한다.
- 자료 준비: 시범 지역의 허용 원천을 서버에 연결하고 장소 중복·좌표·사진 출처를 검수한다. 수정·삭제·권리 철회가 검색 자료에도 반영되도록 한다. 자료 수와 추천 가능 자료 수를 구분해 보고한다.
- 고객 시연: 계정 A가 쓴 여행의 특정 카드에 계정 B가 댓글/답글 작성 → 양쪽에서 확인 → 본인 수정/삭제 → 여행 공개 범위 변경.
- 본인 검수: 같은 업체가 다른 여행에 등장해도 반응 분리, 카드 이동 시 유지·복사 시 초기화, 비공개 자료가 공용 검색에서 제외됨.
- 피드백: 댓글 사용성, 소통 공개 범위, 신고 후 상태 표시, 시범 지역 자료의 적합성.

### R09 · 11/17 · 한 지역에서 첫 실제 AI 추천

- 개발: 내부 후보 검색/RAG, 자연어 조건 해석과 추천 설명 모델을 연결한다. 지역·취향 추천과 저장한 장소로 구성하는 두 모드를 당일 범위부터 검증한다.
- 고객 시연: 여행 조건 입력 → 실제 후보와 추천 이유 확인 → 포함/제외 → 승인 → 비공개 내 여행 저장.
- 본인 검수: 반환 장소가 실제 내부 ID와 일치함, 필수/제외 조건 준수, 비공개 자료 배제, 빈 자료·취소·늦은 응답·중복 승인 처리, 요청별 사용량 기록.
- 피드백: 추천 장소의 납득 가능성, 설명 길이, 후보 선택 흐름, 기다리는 동안의 안내.
- 범위: 첫 시연은 한 지역·당일이다. 이 보고에서 여러 도시·도보·대중교통의 이동 검증까지 완료한 것으로 표현하지 않는다.

### R10 · 11/24 · 여러 DAY와 음식점·숙소 보완

- 개발: AI 1~7일·최대 30곳을 처리하고 도착/출발·교통·속도·필수/제외·걷기·동행·식사·접근성 조건을 적용한다. 수동 편집에 AI 생성 개수 제한을 강제하지 않는다.
- 개발: 스팟을 먼저 구성한 뒤 허용된 내부 자료에서 음식점·카페·숙소를 제안한다. 사용자의 후보 승인, 숙박 DAY·연박·예약 고정, 실제 자동차 경로/구간 시간 확인을 연결한다.
- 고객 시연: 2박 3일 여행 생성 → 고정 숙소 유지 → 식사 후보 교체 → 빡빡한 DAY/미배치 장소 확인 → 승인.
- 본인 검수: 고정 일정 충돌, 빈 좌표, 당일 여행·마지막 날 비숙박, 지나치게 많은 필수 장소, 경로 실패 시 검증 여부 표시.
- 피드백: 하루 여행 밀도, 식사·숙소 제안의 적절성, 이동 시간과 설명, 미배치 이유.

### R11 · 12/01 · 이동수단 검증과 부분 변경

- 개발: 준비한 도보·대중교통 공급자의 실제 응답을 일정 검증에 연결한다. 확인한 구간·수단·조회 시점과 미지원 구간을 구분한다. 지도 SDK 교체와 별개인 경로 연결 작업이다.
- 개발: 특정 DAY·오후·남은 일정만 재생성하고 변경 전후를 비교한다. 원본 버전과 사용자 승인을 확인해 변경분만 반영한다.

- 범위: 텍스트 안내이며 음성 통역·상시 위치 추적은 별도 범위다.

월요일이 공휴일이면 금요일에 후보 버전 고정과 검수를 앞당긴다. 고객 피드백이 늦으면 영향 없는 작업을 진행하되, 미확정 화면을 확정안처럼 공개하지 않는다. 데이터 손실·권한 노출·핵심 조작 차단이 남으면 해당 기능의 공개를 미루고 영향과 새 목표를 보고한다.

주간 보고에는 공개 버전/주소, 이번에 가능한 행동, 실제 연결/샘플 상태, 전주 수정 내역, 고객 확인 항목, 남은 문제와 다음 목표를 넣는다. 완료율만으로 보고하지 않는다.

## 7. Git과 고객 공개 버전 관리

- 내부 작업은 기능 단위로 나누고 공통 저장 구조·사진 출처·방문/카드 관계처럼 선행이 필요한 변경을 먼저 정리한다.
- 고객 공개용 변경은 앞선 공개 버전에 해당 단계 기능을 더한 누적 버전으로 구성한다. 모든 단계가 서로 독립 실행된다는 의미는 아니다.
- R01~R14마다 해당 코드의 기준·배포 주소·검수 결과를 기록한다. 태그를 사용한다면 생성된 실제 태그만 보고에 적는다.
- 다음 단계 코드가 내부에 있어도 공개 버전에는 검수된 기능과 필요한 의존성만 포함한다. 숨김 버튼만으로 데이터 호환 문제까지 해결된다고 가정하지 않는다.
- 고객 피드백 수정은 공개 버전과 이후 개발 버전에 모두 반영한다. DB 변경은 이전 공개 버전의 읽기 호환·데이터 보존·복구까지 고려한다.
- 기존 미공개 로컬 작업·사진 모션 실험을 단계별 공개에 자동 포함하지 않는다. 실제 커밋·푸시·배포 실행은 승인된 대상과 범위에 맞춰 진행한다.

## 8. 일정의 전제와 조정 기준

이 일정은 기존 화면·저장 흐름을 재사용하고, 고객이 주 단위로 피드백을 제공하며, 외부 연동 준비를 선행한다는 조건의 제안이다. 지도 공급자·API 사용 조건·추천 자료·계정/서버 준비 상태가 아직 모두 확인된 것은 아니다.

지도 교체와 검색 연결만으로 네이버 앱의 사진·리뷰·예약·모든 길찾기가 따라오는 것으로 계획하지 않는다. 외부 검색 데이터의 저장·추천 사용은 각각 확인하고, 확인되지 않은 네이버 결과를 내부 DB·RAG·LLM 입력에 넣지 않는다. 일정 추가는 독립적으로 허용된 내부 자료나 허용이 확인된 결과를 사용한다.

추천 자료 부족·지원하지 않는 이동 구간은 화면과 보고에 표시한다. 단순히 달력 날짜가 되었다고 실제 연동 완료로 선언하지 않는다. 연결 지연이나 큰 화면 재설계가 발생하면 해당 화요일에 영향·대체 시연·수정 목표일을 함께 보고한다.

숙박 예약/결제·실시간 가격 비교, 전국 콘텐츠 전량 확보, 실시간 영업/대기 보장, 음성 통역, 상시 위치 추적, 공동 편집, 완전한 오프라인, 앱스토어 심사/출시는 이번 최종 시범 목표와 별도로 산정한다. 실제 사용자 인기 순위는 측정 기반을 준비하되 데이터가 부족한 동안 편집 추천과 구분한다.
