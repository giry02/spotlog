## 2026-09-15 · 사진 스와이프·지역 선택·끝에서 처음 순환

사용자가 Android Chrome에서 사진 스와이프가 안 된다고 알려 주고 지역 선택·위아래 버튼 정리와 마지막 장소에서 첫 장소로 이어지는 동작을 요청함. 같은 로컬 브랜치에서 구현했으며 커밋·푸시·배포 없음.

- 사진 피드는 좌우로 같은 장소 사진, 위아래로 장소를 이동함. 터치와 PC 드래그가 같은 방향 판별·거리/속도 기준을 사용하며 대각선 이동 중 두 축이 함께 움직이지 않도록 잠금 처리함. 브라우저 기본 팬 동작과의 충돌을 피하고 확대 제스처는 허용함. 버튼 클릭·출처 팝업 중에는 피드 드래그를 시작하지 않음.
- 장소가 두 곳 이상이면 마지막→첫 장소와 첫→마지막 장소가 이어짐. 경계에 복제 화면을 두고 스크롤 완료 시 같은 장소의 실제 위치로 옮겨 빈 화면 없이 반복함. 장소별 사진 ID를 기억하며 복제 화면과 실제 화면이 같은 사진을 표시함. 한 곳인 지역은 불필요하게 반복하지 않음. 가로 사진은 첫/끝에서 멈추며 장소 순환과 구분함.
- 위아래 이동 버튼을 제거함. PC는 마우스 드래그·휠·방향키, 터치는 스와이프로 이동함. 사진의 좌우 보조 버튼은 마우스 환경에만 노출하며 사진 선택 점은 유지함.
- 사진 상단의 ‘모든 지역/현재 지역’ 버튼 → ‘어느 지역을 볼까요?’ 하단 팝업 → 지역 선택 즉시 해당 사진 목록으로 복귀함. 지역 안내와 선택 지역을 공유하고 닫기 후 새 지역 버튼으로 초점을 돌려줌. 선택한 지역에 사진이 없으면 다른 지역을 고르는 안내를 제공함. 현재 사진이 있는 지역은 서울·강원·경북·부산·제주임.
- 편집 블록 분류·삽입 안내는12px/600, 삽입 버튼은14px/700으로 보완함. 본문 입력16px/400·소제목16px/700과 홈·목록·카드 외형은 유지함. 앞서 수정한 내부 팝업의 회색 사각형 제거도 유지함.
- 공공자료를 장소 ID로 사진 피드에 연결하고 동백섬의 동백꽃 사진1장을 추가함. 로컬 공공자료11곳12장, 사진 피드15곳20장임. 출처·권리·장소 연결과 신규 파일 기록은 [공공자료 출처](../PUBLIC_CONTENT_SOURCES.md)의09-15 항목에 보관함. 제주4곳의 다중 사진은 여전히 샘플임.
- 웹 타입 검사·빌드, 전체 테스트72개 통과(스와이프 방향/임계값·순환4개 추가, 타이포그래피7개 포함). 320/390/460px에서 피드·지역 팝업과 PC 드래그, 지역 적용·빈/한 곳·사진별 출처 전환·화면 왕복을 검수함. 기존 MapLibre 청크 크기 경고 외 빌드 오류 없음. 검수 자료는 `artifacts/phase1-local-20260915/photo-*` 및 `photo-feed-final-checks.json`임.

## 다음 작업과 복구

사용자 확인 후 수정할 부분을 같은 로컬 브랜치에서 이어감. P1-02의 입력·편집 도구 역할과 화면 보완, P1-14의 실제 Android 키보드·뒤로가기·재실행, P1-12의 실제 장소별 다중 사진 확보와 확인이 남음. 2차 구현이나 공개 배포를 자동 시작하지 않음.

코드는 위 백업 커밋 기준으로 되돌릴 수 있음. 복구 요청이 오면 이후 변경을 먼저 별도 보존하고 필요한 파일만 복원함. `reset --hard`, 원본 전체 덮어쓰기, 공개 브랜치 전체 push를 바로 실행하지 않음. Git 백업은 브라우저에 별도로 저장되는 여행 기록을 포함하지 않음. 사용자용 JSON 백업 메뉴는 제거했으므로 해당 메뉴 이용을 안내하지 않고, 검수·코드 복구 과정에서 기존 브라우저 기록을 초기화하지 않음.
