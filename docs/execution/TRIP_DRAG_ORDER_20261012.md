# 내 여행 드래그 순서 변경 · 2026.10.12

사용자 요청: 일정 작성 화면에서 장소를 드래그해 방문 순서 변경.

## 반영

- 작성·수정 중 카드 오른쪽 44px 손잡이를 끌어 같은 DAY 안에서 순서 변경. 마우스·터치·펜 공통 Pointer Events 사용.
- 이동 중 색으로 묶음 표시, 삽입 선과 장소 이름 표시. 화면 가장자리 자동 스크롤. 카드 본문은 일반 스크롤·장소 상세 열기 유지.
- 기준 장소와 연결된 식당·카페는 한 묶음으로 이동. 하위 업체 손잡이를 잡아도 묶음 이름과 수량 표시. 업체 연결·식사 시간대·메모·방문 ID 보존.
- 숙소와 예약 고정 방문은 이동·횡단 차단. 다른 DAY·후보·방문 기록·별도 여행기 영향 없음.
- 놓을 때 한 번 저장하고 실패하면 이전 순서 유지. 작성 초안 보존·완료 후 보기·다시 수정·되돌리기 유지.
- Escape·pointercancel·포인터 캡처 해제·창 포커스 이탈·목록 밖 놓기·동시 연결/예약/시간 변경은 취소. 헤더나 표지 위 놓기는 적용하지 않음.
- 손잡이에 이름·사용 설명·키보드 위아래 방향키 제공. 보기 모드에는 손잡이 없음. 기존 글자 역할과 사진 크기 유지.

## 구현·연결 기준

`tripPlan.ts`: `planVisitGroups`, `canDragPlanVisit`, `movePlanVisitBefore`. 방문 ID로 묶음과 삽입 위치 식별. 좌표·배열 인덱스를 공용 식별자로 저장하지 않음. 장소 카드 블록 순서와 미충족 식사 슬롯 경계 함께 조정. 잘못된 연결·다른 DAY ID·권한 없는 공개/여행기·휴지통 자료 거부.

`usePlanDragOrder.ts`: 화면 이동 미리보기만 유지하다 유효 drop에서 기존 저장 콜백 실행. 외부 데이터 갱신으로 연결·예약·시간이 바뀌면 기존 제스처 취소. 실제 서버 연계에서는 기존 revision 충돌 처리를 유지하고 순서 전체를 서버에서 다시 검증할 것.

새 라이브러리·서버·AI 호출 추가 없음. DEV 전용 시험은 별도 여행·저장 키 사용, 고객·관리자 저장 자료 접근 없음.
