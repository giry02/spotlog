# Spotlog 관리자와 고객 화면 사용성 검수

2026-10-08 · 현재 로컬 검수본 기준

AI 문장 입력과 후보 최종 선택의 기본 방향은 유지되고 있으나, 고객 화면의 생성 단계·입력 보존·일부 글자 크기와 관리자 작업 진입·신규 자료 갱신에 수정 필요. 전체 레이아웃을 다시 만드는 대신 아래 항목을 해당 화면에서 보완하는 방식 권장.

고객: http://127.0.0.1:5210/ · 관리자: http://127.0.0.1:5210/admin.html

## 유지할 동작

- AI 최초 화면: 요청 문장＋지역/기간/속도/이동수단 네 조건. 날짜·동행·필수 장소를 추가로 선택시키지 않음. 부산 2박3일 가족 여행 문장으로 부산/3일/여유롭게를 반영하고 음식점·카페·숙소가 포함된 샘플 초안 생성. 초안을 그대로 저장할 수 있고 수정은 선택 사항.
- 음식점·카페 후보는 목록에서 한 번 담기. 여러 후보를 담아도 확정 전 실제 방문과 지도에 들어가지 않음. 마지막 확인에서는 묶음별 한 곳만 반영하며 숙소는 숙박일별 구분.
- 내 여행과 내 여행기 탭 분리, 개인 일정의 선택 후보가 여행기에 넘어가지 않는 기준 유지.
- 주요 고객 입력16px, 장소명16px, AI/후보 확인 제목20px, 후보 이름14px·주소12px. 후보 선택 행은 충분한 높이이고 라디오18px. 최근 여행기 댓글 본문16px·등록/응원14px 유지.
- 관리자 입력16px, 버튼14px, 보조 정보12px 유지. 채널 선택→검색→빈 목록의 간격이 확보돼 이전에 붙어 있던 노출 설정 화면은 재현되지 않음.
- 관리자 첫 화면은 등록·가져오기·검수·추천 여행의 업무 진입을 제공하며, 미연결 항목15개를 주 화면에 반복 나열하지 않음.

|---|---|---|---|

| 높음 | 관리자 기존 자료 갱신 | 10/05 지역 마스터 갱신을 완료한 저장소에 새 업체18곳이 자동 합쳐지지 않음. 새 저장소는107개, 이전 자료89개를 유지한 갱신 결과도89개 | 새 공급 자료를 별도 버전으로 추가 반영. 기존 수정·공개본·삭제 이력을 유지하고 저장소 초기화 금지 |

| 보통 | 여행 생성 단계 일치 | 같은 저장 장소/기본1박2일: 내 여행→새 여행은 준비 상태 값 없이 바로 일정. 저장→바로 만들기는 후보0개인데도 준비 상태와 마지막 확인 추가 | 최초 생성 경로를 공통화. 여러 후보가 있는 경우 최종 선택은 유지. 후보 없는 생성은 기존 생성 확정에서 완성 처리해 빈 확인 화면을 반복시키지 않는 방향 권장 |

| 보통 | 관리자 장소 편집 밀도 | 1440×1000에서 여섯 필터·담당 정보·자료 상태가 상단을 차지. 기본 종류 입력은 y약905px, 장소명은 y약1000px. 가로 넘침은 없지만 핵심 입력이 첫 화면 밖 | 목록에서는 지역·검색·상태 중심, 추가 필터는 펼침. 상세 진입 시 필터 요약/목록 복귀로 공간 회수. 담당/검수 상태는 접을 수 있는 요약, 장소명·종류·주소를 편집 상단에 배치 |

‘원터치’는 입력할 조건을 모두 없애는 뜻이 아님. 문장으로 요청했으면 추가 필수 선택 없이 생성하고, 명확한 저장 승인 한 번으로 내 여행을 만드는 방식. 주변 후보 선택·예약 고정 등 의도적인 수정만 별도 조작으로 유지.

현재 한 지역의 저장 목록에서 기본 기간으로 완성까지는 바로 만들기→기간 확정→마지막 확인→내 여행 완성, 네 번 조작. 내 여행의 새 여행은 새 여행→생성, 두 번 조작. 두 경로의 기간·장소는 같은데 준비/완성 기준이 달라 공통 처리가 필요. AI는 문장 입력 후 초안 만들기→내 여행 저장으로 끝나며 후보를 조립하는 절차를 선행시키지 않음.

## 추가로 다듬을 항목

- 숙소는 선택한 밤·기간을 같은 팝업 안에서 유지하지만, 매 후보마다 숙박 설정 화면과 담기 버튼을 거침. 첫 선택에서 숙박일을 지정한 후 같은 밤의 다음 후보는 목록에서 한 번 담기, 숙박일 변경은 별도 행동으로 정리 가능. 예약 고정 확인은 유지.
- 홈 추천 카드의 장소 수/이용 안내10px는 읽어야 하는 정보이므로12px 검토. 캐러셀 점은 실제 버튼 높이6px라 조작이 어려움. 점의 시각 크기를 유지하며 터치 영역만36px로 보완 가능.
- 내 여행기 빈 화면의 안내는 ‘여행기로 남기기’인데 실제 버튼은 ‘여행기로 기록’. 동일한 행동명을 사용.
- 관리자 공개 전 확인·출처·권리 검수·조치 사유는 생략하지 않음. 한 번 공개하기 위해 검증을 우회하는 원터치 방식은 적용하지 않음.

## 검수 범위와 결과

- 격리 Edge에서 고객320/390/460px, 관리자1440/1024/390px 확인. 사용자 브라우저 저장소는 수정하지 않음.
- 고객72개 상태: 기본9화면, 여행기 댓글, AI 입력/결과/저장, 다지역 저장/기간, 새 여행/닫기 복원, 개인 준비/완성, 주변 업체/숙소, 후보 미선택/선택, 하단 스크롤.
- 관리자102개 상태: 7메뉴와 장소 상세7탭, 노출·커뮤니티·회원·AI·설정의 각 탭. 초기 데이터/대표 목록·상세·빈 화면 기준.
- 174개 상태에서 문서/관리자 본문 가로 넘침0, 로드가 끝난 이미지 실패0, 브라우저 JavaScript 예외0. 기능상 문제는 위 재현 항목으로 별도 구분.
- 선택 자동 검사40개 중39개 통과,1개 실패. 실패는 관리자 원본 카탈로그 수를83으로 고정한 검사에서 실제101을 반환한 것. 신규18곳 추가에 맞게 동일 ID·출처·사용 범위 보존 검사로 갱신 필요. 새 저장소의 원본 누락을 의미하는 오류는 아님. 기존 저장소 갱신 누락은 별도로 재현.
- 현재 확인은 로컬 샘플/검수 어댑터 기준. 실제 AI 인식률·서비스 접수·다중 기기 동기화·Android 실제 키보드는 이 검수의 완료 범위가 아님.
