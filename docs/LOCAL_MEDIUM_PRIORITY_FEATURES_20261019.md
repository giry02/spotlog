## 코드와 계약

- `lib/community-discovery*.ts`, `lib/community-trips.ts`, `lib/discovery-media.ts`, `lib/discovery-legacy-photos.ts`: 앱 기획 원문과 실제 사진 출처. 모델에는 제목·작성자·방문 ID·사진 개수 같은 짧은 메타데이터만 제공한다.
- `components/community-trips.tsx`, `components/discovery-media.tsx`: 검색·본문·작성자 바텀 모달·사진 탐색. 사진 지역 조회가 현재 여행 지역을 바꾸지 않는다.
- `lib/trip-local-features.ts`, `lib/trip-local-contract.ts`, `components/trip-local-features.tsx`: 상태·최근 여행·찜 역참조·독립 오프라인 사본. READY가 아닌 편집본이나 저장본과 달라진 화면을 암묵적으로 오프라인 저장하지 않는다. 명시 ID로 선택한 완료 저장본은 별도 읽기 가능하다.
- `lib/offline-trip-client.ts`: 명시한 offline-save/open/remove/library 버튼을 기기에서 검증·적용한다. 문장 입력은 실제 모델 경로를 사용한다.
- `lib/trip-sharing.ts`, `components/trip-share-controls.tsx`: 공유 범위·메모 제외 기본값·날짜 계산·실제 주소. 공유 모달만 열어서는 대화·모델 요청이 생기지 않는다.
- `lib/spotlog-action.ts`, `lib/spotlog-app-bridge.ts`, `lib/spotlog-draft-handoff.ts`, `components/spotlog-app-features.tsx`: 정확한 앱 진입점과 새 사본 전달. 전체 DAY와 방문을 보존하며 원본은 수정하지 않는다. 30 DAY/각 30방문/전체 900방문/256KB 상한. 미확인 장소는 별도 동의가 필요하고 조용히 버리지 않는다.
- 앱 `ChatbotHostController.tsx`, `chatbotHostBridge.ts`, 기존 JourneyEditor/AccountSheet/CardSocial 연결: origin/source/nonce/요청 ID·허용 대상·방문을 다시 검증한다. 사진·개인 메모·좌표·예약 세부는 새 사본 전달에 포함하지 않는다.
- `lib/local-feature-intent.ts`는 문장에 쓸 모델 문맥만 선택한다. 기능 실행을 정규식으로 대체하지 않는다. 실제 도구 선택은 LLM 응답이며 `chat-contract.ts`가 전체 검증 후 적용한다.
- `lib/model-input.ts`, `lib/model-context.ts`, `lib/large-model-adapter.ts`: 신규 기능은 현재 알려진 카탈로그/저장 메타데이터의 제한된 문맥을 쓴다. 새 관광지 생성·현재 날씨는 기존 자료 확인 경로를 유지한다. 보호 절과 명시 긍정 요청을 분리한다.
- `docs/flowise-system-prompt.txt`, `docs/flowise-output.schema.json`, `docs/flowise-structured-output.fields.json`: 총 57개 행동·23개 stage. native 구조화 필드 47개는 `scripts/sync-model-contract.mjs`로 생성한다. 두 활성 Flowise 그래프 프롬프트도 동기화했다.

## 검수와 인계

검수 결과는 `work/handoff/MEDIUM_FINAL_VERIFICATION_20261019.json`에 기록한다. 실제 모델 결과는 `work/handoff/medium-real-llm-20261019/`, 앱 iframe 결과는 `work/handoff/chatbot-medium-iframe-20261019{,-320,-460}/results.json`, 모바일 화면은 `work/handoff/medium-ui-20261019/`에 둔다. 앱 연결 상세는 `docs/spotlog-app-entry-handoff.md`에 있다.

최초 실제 모델 검수에서 신규 기능이 자료 검색 없는 읽기 전용 대체 경로로 빠지는 문제를 발견했다. 로컬 기능 전용 문맥과 요청별 도구 범위를 대형 모델 어댑터에 연결했다. AI 추천 유형 필터 누락도 발견하여 명시 조건을 생략하지 않도록 보완했다. 각 기능에 필요한 목록만 모델에 전달해 불필요한 문맥을 줄였다. 실패 기록도 최초·중간 결과 파일로 보존한다. 기존 RAG 관광지 생성의 근거 요건이나 원본 보호를 제거하는 방식으로 우회하지 않는다.

최종 검수는 전체 자동 검사 **675개 실패 0**, 챗봇 타입 검사·production 빌드 성공이다. 앱도 관련 검사 35개·타입 검사·빌드를 통과했다. 실제 앱과 챗봇 iframe 연결은 320·390·460px의 새 기능 54개와 기존 회귀 21개, 합계 **75개**를 통과했다. 별도 CUA 모바일 검수에서 공유·주소·작성자 바텀 모달의 대화 수 유지, 정확한 전체 방문 수, 지역과 작성 중 여행의 분리도 확인했다.

실제 API의 최종 의미 검사 **9개**가 Flowise/대형 모델에서 통과했다: AI 유형·지역·기간, 정확 제목 검색, 제주 관광지 사진, READY, 오프라인 저장, 목록, 금지/설명 요청의 무변경, 휴지통 제외 최근 여행, 앱 미리보기 목적 카드. 처음 실패한 유형 필터와 미리보기 형식은 별도 원문 재검수로 해결했다. 원래 일정·저장본·기존 오프라인 사본 보호를 각 시나리오에서 확인했으며 실제 사용자 자료를 입력하지 않았다.

실제 구현 대화방 **Spotlog 실제 LLM 챗봇 구현**은 같은 작업 폴더를 사용한다. 이 문서와 검수 결과를 전달했고, 문서 2개·검증 결과 2개를 읽었다는 수신 확인을 받았다. 해당 대화방은 추가 수정·실행을 하지 않았다. 확인 기록은 `work/handoff/MEDIUM_LLM_HANDOFF_ACK_20261019.json`이다. 이전 작업 전체 병합·서비스 재기동·공개 배포는 필요하지 않다.
