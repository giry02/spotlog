# RAG 일정 생성과 로컬 모델 전환

2026-10-18 현재 Windows PC에서 구현·실행했다. 맥미니 이전과 공개 배포는 수행하지 않았다. 아래 초기 평가 기록은 각 평가 날짜의 결과다.

## 현재 동작

일정 생성 요청은 실제 RAG 검색 → 검색된 장소 후보 → 무료 사용이 검증된 Gemini 우선 호출 → `build.visits` 검증 → 일정 카드 순서로 처리한다. Gemini의 무료 사용을 확인할 수 없거나 한도·연결 문제가 생기면 로컬 모델로 바로 전환한다. RAG가 충분하면 작은 로컬 계획기를 먼저 사용하고, 자료 부족이나 작은 모델의 응답 실패 때만 설치된 14B 모델을 호출한다. 모델이 `{day, placeId}`를 골라 보내면 서버가 그 날짜·순서 그대로 배치한다. 이전의 제주 12곳을 규칙으로 자동 채우는 경로는 모델 일정 생성에서 사용하지 않는다.

`LOCAL_ITINERARY_MODEL`을 명시하면 전체 일정 생성에 한해 검증된 로컬 Ollama 모델을 직접 호출할 수 있다. 이 선택은 명시된 로컬 Flowise 계획기와 loopback Ollama 설정이 모두 있을 때만 적용된다. 일반 대화·부분 수정·추가·저장 혼합 요청과 원격 Flowise 설정은 기존 경로를 유지한다. 모델 가중치는 매 생성 전에 로컬 GGUF인지 확인하며 클라우드 모델로 대체하지 않는다. 선택을 비우면 기존 Flowise 8B 계획기 경로로 돌아간다.

이 선택적 계획기의 기본 시간 한도는 75초이고 `LOCAL_ITINERARY_TIMEOUT_MS`로 1~90초 범위에서 지정한다. 초기 가중치 로딩과 입력 처리가 45초 대부분을 사용한 뒤 답변 직전에 취소되어 14B를 다시 읽는 낭비를 피하기 위한 별도 예산이다. 완료된 응답은 즉시 반환하며 전체 요청의 남은 예산도 적용한다. 일반 Ollama의 기존 45초 한도는 유지한다. 컨텍스트를 잘라내거나 원문 RAG를 줄이는 방식으로 속도를 높이지 않는다.

RAG는 기존 장소 설명 13개와 공식 안내 요약 62개, 총 75문서다. 추가 공식 장소 16개도 카드·상세·지도 이름 검색에서 사용할 수 있게 해 제주 28곳을 지원한다. 새로운 장소의 체류·이동 시간은 미산정이며 사진 대신 안내 일러스트임을 표시한다. 식당·카페·숙소 가상 업체 목록을 늘리지 않았고 사용자가 고르지 않은 업체로 일정 빈칸을 채우지 않는다.

계획 검색은 같은 장소의 여러 문서가 상위를 독점하지 않도록 장소별 상위 근거를 분산하고, 사용자가 명시한 장소의 문서를 우선 추가한다. 최대 12개 근거를 같은 색인에서만 병합한다. 계획 전용 프롬프트는 사용하지 않는 34개 행동 문법과 중복 카탈로그를 생략한다. 검색 본문·원래 질문·최근 대화·여행 조건·예약 상태는 유지한다. 첫 실제 시험에서 긴 일반 프롬프트가 잘못된 행동 필드를 생성해 차단된 기록은 인수인계 폴더에 보존했다.

서버는 새 일정의 모든 장소가 이번에 검색·재검증된 실제 후보인지 검사한다. 한라산과 우도는 하루를 단독으로 배정하는 계획 조건이다. 개방·기상·예약·선박 운항을 확인했다는 의미가 아니다. 방문별 `knowledge`에 색인·근거·문서 ID를 서버가 기록하며 저장·다시 열기에서도 유지한다. 과거 기록과 클라이언트가 보낸 메타데이터는 새 일정의 검색 권한을 부여하지 않는다. 예약 숙소와 부분 수정 범위는 기존 검증으로 보호한다.

## API 키 없는 큰 모델

RAG가 비었거나 요청 지역·장소·기간을 뒷받침하지 못하면 로컬 Qwen3 14B로 전환한다. 기본 모델이 `needsMoreContext:true`로 자료 부족을 알리거나 잘못된 기능 응답을 생성한 경우에도 큰 모델을 한 번 호출한다. 모델 사용 여부·전환 이유를 답변에 기록하고 화면에 표시한다. 출처 철회·사후 검증 오류는 모델 전환으로 우회하지 않는다.

실제 설치 모델은 `qwen3:14b`, 14.8B/Q4_K_M, 약 9.28GB이며 digest는 `bdbd181c33f2ed1b31c972991882db3cf4d192569092138a7d29e973cd9debe8`이다. RAM 약 32GB와 RTX 4060 Laptop 환경에서 실행했다. 기본값은 context 12288, 생성 상한 900토큰, think:false, temperature:0, repeat_penalty:1.1, 호출 한도 180초다. 호출 후 `keep_alive:0`으로 큰 모델을 내리고 기본 모델이 GPU를 재사용한다. 브라우저 대기 한도는 240초다. 참고: [공식 모델](https://ollama.com/library/qwen3:14b), [Ollama Chat API](https://docs.ollama.com/api/chat).

검증된 RAG 근거가 전혀 없는 요청은 원래 질문·최근 대화·기본 여행 조건·도구 결과만 짧은 읽기 전용 입력으로 보낸다. 큰 모델은 일반 지식에 따른 자연어 설명·일정 제안을 할 수 있지만, 검증되지 않은 새 장소로 카드를 만들거나 출처 ID를 생성할 수 없다. 큰 모델의 파라미터 지식은 웹 검색이나 최신 자료 조회가 아니며 사실성을 보장하지 않는다. 실시간 날씨는 별도의 Open-Meteo 도구를 사용한다.

Gemini는 실제 키의 프로젝트와 결제 비활성 상태를 매 생성 전에 확인한다. OAuth 액세스 토큰만 재사용하고 키·프로젝트·결제 판정은 캐시하지 않는다. 무료 모델 목록, 보수적인 분당·일일 호출 제한과 429 차단도 유지한다. 확인 실패는 원격 생성을 허용하지 않고 로컬로 전환하며, 유료 사용이 검증되지 않은 OpenAI 호환 외부 API는 차단한다.

## 재실행과 검증

2026-10-18 속도 검증에서는 실제 앱의 무료 Gemini 우선 일정 생성이 16.0초와 10.3초에 완료됐다. Gemini 한도 오류만 주입하고 실제 로컬 생성과 RAG 사후 검증을 실행한 시험은, 설치된 `qwen3:4b-instruct-2507-q4_K_M`의 모델 로딩 포함 52.6초, 모델이 준비된 동일 3일 요청 5.3초, 다른 사려니숲길·절물 당일 요청 6.0초였다. 현재 PC의 `.dev.vars`는 `LOCAL_ITINERARY_MODEL`로 이 선택적 계획기를 사용한다. 세부 측정 조건·초기 실패한 후보의 기록과 한계는 [속도 평가 기록](evaluations/2026-10-18-itinerary-latency.json)에 보존했다. 이 결과가 모든 질문의 응답 시간을 보장하지 않으며, 14B 보완까지 필요한 요청은 더 오래 걸릴 수 있다. 최종 운영 코드의 전체 회귀 508개, 타입 검사, 빌드와 변경 공백 검사를 통과했다.

기존 Ollama·Flowise를 실행한 상태에서 `npm run local:services`로 RAG 상태를 확인한다. 모델은 이미 설치되어 있으므로 다시 다운로드할 필요가 없다. 큰 모델을 다른 PC에서 준비할 때는 `node scripts/prepare-local-large-model.mjs`, 설정은 `node scripts/configure-large-model.mjs --provider=ollama --model=qwen3:14b`를 사용한다. 준비 스크립트의 옵션은 파일의 사용 안내를 확인한다. `.dev.vars`를 변경한 뒤 앱 개발 서버를 재시작한다. 이 파일과 런타임 인증 정보는 Git에서 제외된다.

native Flowise의 일반 대화 flow는 `e842c7b5-f902-4681-8a3a-033ac4ac2c6f`, 계획 전용 flow는 `c2bcb74b-7896-44d0-8e68-4dfaf59f167d`다. 두 flow 모두 같은 기존 전용 키와 제한된 8B 모델을 사용한다. `FLOWISE_PLANNER_CHATFLOW_ID`로 계획 전용 경로를 고른다. bootstrap은 두 flow의 ID와 재현 가능한 내보내기를 보관한다.

실제 앱 평가 결과는 [RAG 일정 및 모델 전환](evaluations/2026-10-15-rag-driven-itinerary.json)에 기록한다. 사려니숲길·절물 당일 일정(7.877초), 한라산/우도/숲길 3일 일정(11.176초), 별도 지정 장소 없는 제주 3일 생성(10.667초), RAG에 없는 부산 여행 준비 질문의 14B 전환(20.516초)을 각각 확인했다. 화면 카드와 스크롤은 별도 브라우저 검증 기록으로 남긴다. 전체 단위·회귀 313개, TypeScript, production build를 통과했다. 이 결과는 모든 한국어 요청의 정확도나 실제 운영·예약 연결을 검증한 것이 아니다.

재현 명령은 `npm run eval:rag-itinerary`이며 실제 로컬 모델 4건을 순차 호출한다. 특정 사례 ID를 인수로 주면 해당 사례만 실행하고 이전 결과의 사례별 평가 시각을 유지한다. 브라우저의 기존 2일 여행을 당일로 바꾼 시험에서는 모델이 기간·포함 조건을 빠뜨리는 문제를 발견해 명시적 조건을 서버에 보존했다. 잠긴 숙박은 유지하고, 근거 검증 실패 시 기존 일정은 그대로 남는다. [최종 화면](../work/handoff/RAG_DRIVEN_ITINERARY_UI_20261015.jpg)과 [검증 기록](../work/handoff/RAG_DRIVEN_ITINERARY_UI_20261015.json)은 실제 대화 7턴과 당일 장소 2개·근거 8개가 새로고침 후에도 유지된 결과다.

큰 모델의 일반 지식은 사실 검증된 RAG와 구분한다. 초기 미수록 관광지 비교 시험에서 감천문화마을을 전통 한옥으로 잘못 설명한 사례도 [지식 한계 기록](evaluations/2026-10-15-large-model-knowledge-limitation.json)에 보존했다. 전환·JSON 계약 성공을 사실성 통과로 판정하지 않는다. 미검증 장소를 카드로 생성하지 않는 이유이며, 해당 지역 자료를 공식 근거로 추가하기 전까지 일반 지식 안내로 표시한다.
