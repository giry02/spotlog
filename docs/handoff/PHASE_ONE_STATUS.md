## 최신 로컬 구현 · 2026-09-15

**가장 최신:** 하단 모달60개 상태 재검수, 새 여행 간격/DAY7 노출/직접 등록의 잘못된 대체 사진을 수정함. 샘플 갤러리6곳10장을 실제 사진으로 교체하여 피드15곳20장에 출처를 연결함. 전체73개 검사와 빌드 통과. 실제 Android 기기 및 전수 콘텐츠 확보는 미완료이며 상세 근거는 [진행 기록](../execution/PROGRESS.md), [사진 수급 기록](../LICENSED_PLACE_PHOTOS.md)을 우선함. 아래 테스트72개/샘플 갤러리 미확보는 이전 이력임.

최신 추가: 사진 피드의 가로/세로 방향 잠금 드래그, 마지막↔첫 장소 순환, 현재 지역 버튼·하단 지역 선택, 위아래 화살표 제거를 적용함. 편집 분류12px·삽입 행동14px·입력16px로 정리함. 공공 동백섬 사진1장을 추가하여 로컬 사진 피드는15곳20장임. 웹 테스트72개와 빌드 통과. 실제 Android Chrome 기기 검수와 다른 장소의 실사진 수급은 별도이며 아래 최초 구현 수치보다 [최신 진행 기록](../execution/PROGRESS.md)을 우선함.

사용자 요청으로 큰 랜드마크 카드 갤러리·사진 ID/출처·저장 지역 범위의 1~7일 초안 미리보기/승인·발견 스크롤 복원을 보완함. 이후 상세 DAY 마우스 드래그·일회성 안내와 입력 글자 굵기 보정을 적용함. 프로필에 추가했던 JSON 백업·복구는 서비스에 불필요하다는 사용자 지시로 제거함. 휴지통은 사용 흐름 기획 단계이며 아직 구현되지 않음. **현재 결과는 [실행 진행 기록](../execution/PROGRESS.md)을 우선 확인함.** 최초 웹 테스트 68개, 최신 변경 관련 테스트 27개·빌드를 통과했으며 실제 Android 검수와 장소별 실사진 추가 수급은 남음. 공개 배포·원격 푸시는 하지 않음. 아래 09-10 게시 당시 미완료 목록은 과거 상태임.

## 최신 로컬 추가 구현 · 2026-09-10 후속 요청

아래 가이드 게시 당시 현황은 과거 기준임. 이후 사용자 요청으로 F02~F04의 담기 흐름을 기존 하단 팝업에 연결함. 당일치기~6박 7일·출발일·DAY 선택, 내 여행 상세 이동, 기간/DAY 상태 분리, 소유 여행만 수정, 방문별 해제·다른 DAY 재방문을 구현함. 저장 카드와 전역 디자인은 유지함.

홈의 글 입력형 AI 여행 로컬 미리보기, 여행기 내 AI 추천 분리, 권리 확인 공공자료 여행기와 출처 표시를 추가함. 업체 검색 후속 계획은 네이버 지역 검색 API 기준으로 변경함. 실제 LLM·네이버 API 호출이나 공개 배포를 완료한 것이 아님.

현재 기준과 검수 범위는 [로컬 여행 생성·추천 추가 사항](./LOCAL_TRAVEL_ADDITIONS.md)을 우선 확인함. **1차 전체는 아직 완료가 아님.** 아래 `planningJourney`·기간/DAY 결합·visits 미연결 지적은 이번 후속 구현에서 해소된 과거 문제임.

기준일: 2026-09-10. 현재 활성화된 로컬 코드와 최신 사용자 지시를 대조함. **1차 전체 완료가 아님.** 철회된 시안이나 과거 테스트 통과를 현재 완료로 계산하지 않음. 이번 요청은 가이드 게시와 현황 보고이며 남은 서비스 기능을 바로 구현하는 요청이 아님.

## 가장 먼저 정리할 동작

1. **현재 디자인 유지:** 저장은 작은 가로 카드와 지역 목록을 유지함. 별도 보관함·분류 단계를 추가하지 않음.
2. **담기 대상 명확화:** 저장에서 담기를 시작하고, 내 여행에서 대상 여행·DAY를 확인하도록 동작을 정리함. 저장 목록에 여행 편집 폼을 다시 넣지 않음. 구현 전 짧은 흐름을 먼저 확인함.
3. **기간과 DAY 분리:** “2일 여행 만들기”와 “기존 여행 DAY 2에 담기”는 서로 독립된 값이어야 함.
4. **내 여행만 수정:** 소유 여행이 없으면 생성으로 안내하고, 공개 샘플·다른 작성자 원본은 담기 대상으로 삼지 않음.
5. **방문 단위 담김·해제:** 같은 장소를 여러 여행·날짜에 쓸 수 있게 하며, 특정 방문을 해제해도 다른 DAY·글·사진·북마크는 보존함.
6. **끝까지 검수:** 선택·취소·빈 여행·DAY 부족·중복·뒤로가기·새로고침·저장 실패를 연결해서 확인함. 이후 콘텐츠 점검과 실제 Android 검수를 수행함.

## 활성 코드에서 확인된 주의점

- `App.tsx`의 `planningJourney`는 첫 `PLANNING` 또는 첫 여행을 자동 선택하고 `isMine`을 확인하지 않음. 현재 담기·해제 함수에도 소유 여부 방어가 없음. 내 여행이 없으면 공개 샘플이 선택될 수 있음.
- `Saved`의 `effectiveDayCount`는 AI 생성 기간이면서 개별 장소를 담는 DAY로도 전달됨. 원래 화면으로 복원하면서 이 결합도 다시 활성화된 상태임.
- `SavedPlaces.tsx`·`MyTripsFromSaved.tsx`는 철회된 시안 파일이며 활성 App에서 사용하지 않음. 이 파일들의 과거 여행·DAY 선택 테스트를 완료 근거로 사용하지 않음.
- `visits.ts`의 안전한 방문별 추가·삭제 함수는 단위 테스트되어 있으나 현재 Saved 담기 경로에서는 사용하지 않음. 31개 단위 테스트 통과는 도우미·저장소 검증이지 전체 사용자 흐름 완료가 아님.
- 도보 표시에는 자동차 도로 기반 추정이라는 안내를 추가한 상태임. 실제 교통수단별 경로 엔진은 여전히 후속 개발임.

## 철회·후속 항목

- **철회:** 별도 보관함 생성·중첩 분류, 저장 화면 안의 복잡한 여행/DAY 편집, 큰 장소 카드로의 일괄 교체, 새 글꼴·버튼·여백을 전역 적용한 시안. 이번 재정리에서 되살리지 않음.
- **계획서 정정 대상:** F02~F04에 남은 큰 저장 카드·철회된 선택 화면 설명. 현재 디자인과 확정할 단순 동작에 맞게 이후 갱신해야 함.
- **2차:** 여행기 작성/복구·DAY 이동/복사·여행기 안 장소별 좋아요·댓글/스레드와 하단 팝업.
- **3차 및 서버 이후:** AI/RAG·관광 안내·자동번역 연결, 로그인·동기화·실제 집계·원격 푸시. 1차 완료에 묶지 않음.
