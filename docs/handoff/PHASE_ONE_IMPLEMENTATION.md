## 저장과 내 여행의 역할 — 철회 전 기록

| 화면 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 저장 | 발견한 장소를 한 목록에 저장, 지역/검색으로 보기, 담기·여행 만들기·AI 진입 버튼 | 여행·DAY 선택창, 생성 폼, 방문 해제·일정 편집, 별도 보관함 분류 |
| 내 여행 진입 | 저장에서 이동한 뒤 기존 여행·DAY를 선택하거나 이름·기간·출발 날짜를 입력하여 생성함 | 사용자가 확정하기 전에 여행 데이터를 바꾸지 않음 |
| 내 여행 상세 | 생성 직후 도착하는 화면. 날짜별 장소와 동선을 먼저 확인함 | 생성 직후 편집기를 강제로 열지 않음 |
| 내 여행 편집 | 여행 기간·DAY·장소 순서·글·사진을 수정하고 관리함 | 저장 화면에 같은 편집 기능을 중복 배치하지 않음 |

**저장의 버튼 → 내 여행으로 먼저 이동 → 여행·DAY 선택 또는 생성 입력 → 확정한 DAY 상세 → 그곳에서 수정·관리함.**

- 저장 카드의 `내 여행에 담기`는 내 여행으로 이동만 함. 그곳에서 여행과 DAY를 명시적으로 고른 뒤 확정함. DAY 2 확정 후 DAY 2 상세를 표시하며 새로고침 후에도 해당 날짜를 유지함.
- 선택 날짜에 이미 담긴 장소는 `이 날짜 보기`를 제공함. 저장 화면에서 눌렀다는 이유로 기존 방문을 삭제하지 않음. 실제 삭제는 내 여행의 편집에서 수행함.
- 저장 카드에 담긴 여행·DAY를 읽기 전용으로 표시함. `저장 해제`는 저장 목록에서만 빼며 여행의 기록은 유지함.
- 저장 화면의 `여행 만들기`는 내 여행의 생성 화면을 여는 버튼임. 이름·기간·출발 날짜는 이동한 내 여행에서 입력함. 현재 목록의 장소를 DAY 1에 담아 시작한다는 안내를 보여줌.
- 저장 화면의 AI 버튼도 내 여행의 AI 생성 화면으로 이동만 함. 그곳에서 기간을 고르고 생성한 후 해당 내 여행 상세로 이동함.
- 기간과 담을 DAY를 다른 상태로 관리하며, 취소·뒤로가기·저장 공간 부족 시 변경을 임의 반영하지 않음.
- AI는 실제 LLM/RAG 호출이 아닌 기존 로컬 거리·체류시간 규칙임을 명시함. 요청 일수를 임의 축소하지 않음.

### 폐기한 방향

이전 구현의 '저장 → 보관함 분류 → 보관함과 일정 연결 → 일자별 배치 시작'은 사용자가 명시적으로 거절함. 해당 UI와 연결 로직은 제거함. `SavedLibrary.tsx`, `saved-library.css`, `TripPlacementSheet.tsx`의 이전 UI 소스도 제거함. 다시 도입하지 않음.

그 다음 시안의 **저장 상단 여행/DAY 선택 패널과 저장 내부 생성 폼도 거절됨.** 최신 버튼 진입 방식으로 대체함. 오래된 검수 파일의 흐름으로 되돌리지 않음.

사용자의 기존 보관함 데이터·메모·연결된 여행은 삭제하거나 자동 변환하지 않음. 원래 저장소와 백업에 보존하되 현재 화면에서 별도 분류 단계로 노출하지 않음. 저장 카드의 저장 해제도 은퇴한 분류 데이터를 수정하지 않음.

## 장소 카드와 사진 피드

- 지역 안내와 저장 목록은 **같은 `LandmarkGuideCard`**를 사용함. 큰 사진이 위에 나오고 소개·메모·버튼이 아래에 나옴. 안목해변도 작은 가로 썸네일 카드로 만들지 않음.
- 사진 피드는 한 화면에 한 장소를 보여줌. 세로로 다른 랜드마크, 가로로 같은 장소의 사진을 넘김.
- 사진 피드에 지역/검색 선택을 강제하지 않음. 지역 안내의 필터와 별개임.
- 영상·사진·안내·저장은 장소 ID와 저장 상태를 공유함.
- 협재·오설록·사계·새별오름·서울숲·안목해변의 준비된 샘플 이미지를 사용하고 샘플임을 표시함. 같은 장소용 샘플이 있으면 저장 카드도 동일 대표 이미지를 사용함.
- 기존 영상 및 별도 사진 모션 실험은 유지함. 전용 사진이 없는 장소에 다른 지역 사진으로 새 피드를 채우지 않음.
