## 02 / 47 · 개발 범위와 완료 수준

01 · EXECUTIVE SUMMARY

3차까지 완료 시점은 서비스 흐름을 검증하는 프런트엔드 완성 단계임. 실제 사용자 서비스 출시는 서버와 운영 기반 이후에 판단함.

### 1·2·3차에서 완성할 흐름

- 여행기를 먼저 읽고, 장소를 저장한 뒤 내 여행으로 담음

- 저장에서는 담기·만들기를 시작하고 하단 팝업에서 기간·DAY를 고름. 확정 후 내 여행에서 관리함

- 글·사진·장소를 작성하고 임시 저장·복구함

- AI 일정·관광 안내·영어 보기를 샘플 응답으로 검증함

### 이후 서버에서 완성할 기능

- 회원·기기 간 동기화·접근 권한을 연결함

- 실제 업로드·댓글·조회·담김을 운영 데이터로 전환함

- 경로·AI·번역 공급자를 서버에서 연결함

- 신고·차단·운영 대응을 갖춘 뒤 공개함

**이번 산출물은 개발 계획서임.** 계획서 제작과 앱 기능 구현을 구분하며, 기존 로드맵·확장 보고서·로컬 전용 실험을 보존함.

## 08 / 47 · 여행기 기반 서비스 흐름

02 · PRODUCT DIRECTION

예약 상품을 늘리기보다, 읽고 저장한 경험이 내 여행과 다음 여행기로 이어지는 구조를 강화함.

STEP 1 **발견** 추천 여행기·영상·지역 안내에서 관심 장소를 만남

STEP 2 **빠른 저장** 목적지를 정하지 않아도 장소를 저장함

STEP 3 **여행 만들기** 저장에서 진입해 내 여행에서 새 여행·AI 여행을 만듦

STEP 4 **일정 구성** 생성한 여행 상세로 이동해 날짜·내용을 수정함

STEP 5 **실제 여행** 이동·방문·사진·한 줄 메모를 기록함

STEP 6 **여행기 발행** 기록을 글과 사진으로 다듬고 출처와 함께 공유함

### 유지할 제품 성격

- 모바일웹이 본체이며 앱은 필요한 기기 기능을 보완함

- 숙소·맛집은 여행기 속 장소로 취급함

- 다른 사람의 글은 먼저 읽고 담도록 함

### 새로 보완할 방향

- 저장한 이유와 현장 팁을 기록할 수 있게 함

- 추천·사용자 경험·공식 정보·광고를 구분함

- 작성 완료와 실제 재사용을 콘텐츠 품질 신호로 삼음

## 09 / 47 · 저장·하단 선택 · 내 여행 관리

03 · SAVE & MY TRIPS

저장 목록은 유지함. 담기는 하단 팝업에서 여행·기간·DAY를 고르고, 확정 후 내 여행 상세로 이동함.

### 저장 동작

- 발견한 장소를 하나의 저장 목록에 모으고 지역으로 걸러 봄

- 기존 SavedPlaceCard의 작은 가로 사진·설명·담기 구조를 유지함

- 만들기·AI 버튼에서 하단 입력을 열고, 승인 후 내 여행 상세로 이동함

- 저장 본문에 편집창·보관함을 추가하지 않고 하단 팝업만 사용함

### 하단 팝업에서 선택·확정

- 장소 카드의 담기를 누르면 하단 선택 팝업을 엶

- 하단 팝업에서 대상 여행과 DAY를 고르고 담기를 확정함

- 확정한 DAY의 상세를 열며, 저장 카드는 담긴 위치만 표시함

- 기간·DAY·순서·글·사진 수정은 내 여행 상세에서만 진행함

| 동작 | 결과 |
| --- | --- |
| 저장 해제 | 저장 장소 목록에서만 제거함. 이미 만든 여행의 방문 기록은 유지함 |
| DAY 담김 해제 | 내 여행에서 해당 방문 항목만 제거함. 원래 저장 장소는 유지함 |
| 같은 장소 재방문 | 중복 안내 후 사용자가 허용하면 별도 방문 항목으로 추가함 |

장소 ID와 여행 방문 ID를 분리함. 별도 보관함 생성·분류 없이 저장과 내 여행으로 역할을 구분함.

## 10 / 47 · 블로그형 여행기 작성 보완

03 · WRITING & TRUST

장소 카드 나열보다 관찰·평가·주변 사진이 자연스럽게 이어지는 여행기를 만들 수 있도록 함.

### 작성 기능

- 글·사진·장소 블록을 추가하고 읽는 순서대로 배치함

- 사진 여러 장 선택, 설명·대표 사진·초점 위치를 지원함

- 장소를 다른 DAY로 이동해도 연결된 글과 사진을 유지함

- 자동 임시 저장, 작성 위치 복구, 마지막 변경 취소를 제공함

### 공개 전 확인

- 장소와 관계없는 사진을 임의 대체 이미지로 사용하지 않음

- 사진이 없으면 사진 없음 상태와 등록 방법을 제공함

- 좌표·이용 정보가 없으면 미확인 상태를 표시함

- 공식 정보와 방문 당시 경험, AI 안내를 구분함

권장 작성 항목: 방문 이유, 주변에서 본 것, 좋았던 점·아쉬운 점, 이동·입장 팁, 사진 설명, 정보 확인일. AI가 방문자의 체험담을 지어내도록 하지 않음.

## 38 / 47 · 스팟 중심 일정과 주변 장소 추가

2026.09.10 · SPOT-FIRST FLOW

스팟으로 DAY별 일정의 기본 구성을 정한 뒤, 내 여행에서 음식점·카페와 숙박 거점을 보완함.

| 화면 | 사용자 동작과 연결 |
| --- | --- |
| 장소 발견·저장 | 가고 싶은 스팟을 저장함. 저장 화면은 기존 목록·지역 필터·여행 만들기 진입을 유지하고 업체 추천·일정 편집을 펼치지 않음. |
| 여행 만들기 | 기간과 DAY를 선택하고 사진 카드로 장소를 확인함. 승인하면 해당 내 여행 상세를 열며 이후 수정은 그곳에서 진행함. |
| 내 여행 · 스팟 주변 | 스팟 카드의 ‘＋ 주변 장소’로 하단 팝업을 엶. 추천 / 직접 검색 / 저장한 장소에서 음식점·카페를 고름. |
| 추가 위치 | 현재 여행·DAY·기준 스팟을 팝업에 표시함. 고른 장소는 기준 스팟 다음에 추가하며 여행과 DAY를 다시 묻지 않음. |
| 숙박과 공개 열람 | 숙소는 숙박할 DAY의 거점으로 추가함. 다른 사람의 여행기에는 편집 동작을 숨기고 읽기·저장·복사 흐름을 유지함. |

**화면 역할:** 저장은 모으기·만들기, 내 여행은 DAY별 보완·관리임. 주변 업체의 직접 선택과 선택적 AI 보완은 같은 후보와 장소 카드를 사용함.

스팟을 먼저 고르는 흐름만으로 동선이 보장되지는 않음. 예약한 숙소·고정 시간은 처음부터 반영하고, 음식점은 다음 스팟 방향과 식사 시간을 함께 검토함.

## 44 / 47 · 네이버 API HUB 서버 연결 준비

2026.09.10 · DATA & LANDMARK GALLERY

키와 공급자 정책을 서버에서 관리하고, 공식 응답 범위와 오류 상태부터 검증함.

| 기술 항목 | 구현 기준 |
| --- | --- |
| 호출·인증 | 서버가 GET /search/v1/local을 호출함. X-NCP-APIGW-API-KEY-ID·X-NCP-APIGW-API-KEY를 사용하며 웹·APK에 키를 넣지 않음. |
| 검색 조건 | query, display 최대 5, start 1을 사용함. sort=random은 정확도, comment는 블로그·카페 리뷰 수 기준이며 별점순이나 Spotlog 인기순으로 표시하지 않음. |
| 응답 검증 | 이름·주소·분류·링크·mapx/mapy를 검사함. 문서상 WGS84라도 실제 값의 단위·스케일을 확인함. 안정적인 공급자 장소 ID가 있다고 가정하지 않음. |

| 한도·비용 확인 | HUB 안내의 한시 무료·월 775,000회 공유·키별 50 RPS와 지역 API의 일 25,000회 설명이 함께 존재함. 콘솔·공식 답변으로 적용 한도와 유료 전환을 확정함. |
| 검증·차단 | 인증·한도 초과·빈 결과·지연·좌표 오류·표시 정책·캐시 만료를 시험함. 권한 없는 저장·AI 전달을 차단하고 키·개인정보를 로그에 남기지 않음. |

전체 주소는 공식 API 규격에서 확인함. 키 발급·실제 호출·내부 ID 연결은 계약과 데이터 사용 범위가 확인된 뒤 진행함.
