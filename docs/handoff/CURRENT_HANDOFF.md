APK는 웹을 불러오는 하이브리드 셸임. 완전한 오프라인 네이티브 서비스로 설명하지 않음. 과거 사용자가 약 85MB라고 언급했지만, 현재 배포 파일 크기·최종 APK 주소를 이번 작업에서 다시 검증한 것은 아님. 새 빌드나 유료 EAS 작업을 자동 실행하지 않음.

## 5. 확정된 제품 방향

읽을 만한 여행기 → 장소 저장 → 내 일정에 활용 → 실제 여행 → 내 여행기 발행의 순환을 중심으로 함. 여행기는 글 속 사진·평가·현장 팁·숙소·음식점과 지도 동선이 연결되는 블로그형 가이드임.

- 여러 여행을 만들고, 먼저 읽은 뒤 복사·수정함. 보기 대신 수정 버튼부터 강요하지 않음.
- 국내 콘텐츠를 먼저 확보하고 영어 이용을 확장함. 한국어 원본은 유지함.
- 숙박비 비교·재고·예약·결제·정산은 포함하지 않음.
- 장소를 모두 미리 구축한다고 가정하지 않음. 직접 입력을 유지하고 외부 검색은 추후 연결함.
- 지도는 현재 방식 유지. 카카오 지도 전환은 사용자가 나중에 다시 처리한다고 명시함.
- 모바일에 맞는 읽을 수 있는 글자와 단순한 여행 브랜드 디자인을 유지함.
- DAY 탭 앞 뒤로가기 화살표를 유지함. 별도 고정 헤더를 추가해 높이를 차지하지 않음.
- 기간 2일과 장소를 넣을 DAY 2는 서로 다른 선택 상태로 관리함.
- 사진 모션을 승인 없이 공개 영상 화면에 넣지 않음. 풀영상과 사진 기반 형식의 병행 가능성은 유지함.

## 6. 개발 순서의 최신 결정 (2026-09-10 정정)

프런트엔드는 사용자가 혼자 개발함. 1차·2차·3차는 기능 구현 단위이며 주수나 일수로 고정하지 않음. 개발자 A/B/C 역할 배정은 삭제함. 각 차수 완료 조건을 확인하고 다음 차수로 진행하며 백엔드는 그 이후임.

1. 1차: 발견·단일 저장 목록·여행 생성·대상 여행/DAY 담기·상태/오류 정돈. 별도 보관함 분류는 도입하지 않음.
2. 2차: 작성/자동 임시 저장·복구·글/사진/장소 편집·복사/이동·지도 연결.
3. 3차: AI 입력/결과/후보 승인/부분 수정, 관광 안내, 한국어/영어 흐름을 샘플 응답으로 검증.
4. 이후 B1 사용자/데이터 → B2 장소/미디어/공개 콘텐츠 → B3 커뮤니티/안전 → B4 실제 AI/영어 → B5 앱 현장 기능/확장.

`FUTURE_ROADMAP.md`는 보존된 과거 자료임. 그 안의 백엔드 우선 순서는 위 최신 결정에 의해 변경됨. 이전의 3주 일정·다인 역할 분담 역시 이 결정으로 대체됨. 보고서 제작이 완료되었다는 것과 계획에 있는 기능 개발이 완료되었다는 것을 혼동하지 않음.

## 7. AI 방향의 최신 결정 — 특히 중요

사용자가 원한 핵심은 선택 장소를 순서대로 배열하는 기능만이 아님. **Spotlog에 쌓인 여행기·장소·인기도 데이터를 검색하여 지역/취향에 맞는 랜드마크를 찾고, 가까운 인기 음식점·숙소를 함께 매칭하는 추천**임.

| 계층 | 역할 |
|---|---|
| 내부 DB·메타 필터 | 지역·분류·좌표·권한·확인일·사용자 조건으로 후보를 제한함 |
| RAG·검색 | 여행기/장소 설명에서 취향과 맥락에 맞는 근거를 찾음. 벡터 검색만 사용하지 않음 |
| 인기 순위·재정렬 | 실제 저장·복사·반응 등 로우 데이터를 지역/분류별로 보정해 계산함. LLM이 수치를 창작하지 않음 |
| 후보 조합 | 랜드마크 주변 음식점, 전체 여행의 숙박 거점을 조건에 맞춰 추천함 |
| 경로·일정 | 실제 이동수단별 시간으로 실행 가능성을 검사함. 복잡한 시간 제약에는 OR-Tools를 선택적으로 사용함 |
| LLM | 자연어 조건 이해, 후보 조합 보조, 근거 기반 설명·관광 질문 응답. 없는 장소/좌표/후기를 생성하지 않음 |

모드도 분리함: ① 지역·취향 추천은 내부 후보를 초안에 자동 조합 후 사용자 최종 승인 ② 저장한 곳 구성은 선택 장소만 사용하고 보충은 선택 사항 ③ 외부 후보는 사용자가 승인하고 내부 인기 데이터와 구분함.

초기 기술 후보는 PostgreSQL + PostGIS + pgvector, 키워드/메타/의미 검색 결합임. 임베딩은 text-embedding-3-small과 BAAI bge-m3 등을 비교하는 계획임. LLM은 GPT 한 모델로 확정하지 않았음. 계획서의 Sol·Sonnet·Gemini·Luna 후보를 같은 데이터로 품질/비용/지연 평가한 뒤 결정함. 제품 내부 모델 명칭과 실제 API 제공 여부·단가·계약은 도입 시 공식 문서로 다시 확인함.

OR-Tools는 추천 데이터베이스나 대화 AI가 아니라 시간·순서 제약을 계산하는 선택 도구임. 처음에는 규칙 + 실제 경로 검증으로 시작하고 복잡해질 때 도입함. AI 생성 검증 범위 1~7일/최대 30곳은 초기 제안이며 수동 여행을 제한하는 결정이 아님.

번역은 한국어 원문에 영어 사본을 연결함. UI 직접 관리와 콘텐츠 자동번역을 구분하고, 원문/용어집 버전·검수 상태·한글 주소·숫자 보존을 검사함. 자세한 모델 비교, 단가 조건, 처리 예시와 출처는 AI_GUIDE_PLAN.md 전체에 보존함. 이 인수인계에서 새로 단가를 검증하거나 API를 호출한 것은 아님.
