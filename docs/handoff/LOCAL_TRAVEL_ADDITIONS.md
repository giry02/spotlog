# 로컬 여행 생성·추천 추가 사항

기준일: 2026-09-10. 이번 요청은 로컬 기능 추가임. 커밋·푸시·공개 배포·APK 재빌드를 하지 않음. 원래 디자인과 사용자 저장 데이터를 보존함.

## 후속 문서 갱신 · 데이터 수급과 여러 사진

이전 기능 구현과 구분하여 [데이터 수급·네이버 연동·랜드마크 여러 사진 계획](../DATA_SUPPLY_AND_NAVER_PLAN.md)을 추가함. 개발·AI 전체/요약본에 반영하며 이 갱신 자체는 문서만 변경함. 랜드마크 카드의 같은 장소 여러 사진 가로 넘김은 1차 후속 계획임. 지역 안내·AI·담기 팝업이 공유하고 저장 바깥 작은 가로 카드와 전체 화면 사진 피드의 역할은 유지함. 아래 40·15·61·9쪽 및 125쪽 검수는 이 문서 갱신 전 기록임.

## 사진 카드 확인과 스팟 중심 계획 · 후속 반영

- **계획서:** 개발 전체/요약과 AI 전체/요약에 스팟 중심 일정, 내 여행의 주변 장소 팝업, 숙박일 거점, 수동·AI 보완의 공통 후보와 차수 구분을 추가함. 기존 내용을 축약하지 않고 각각 3쪽씩 추가한 40·15·61·9쪽임. 주변 업체 추천·숙박 거점은 후속 구현 계획으로 남김.
- **홈 AI:** 글로 요청한 뒤 DAY별로 기존 `LandmarkGuideCard`의 사진·소개·메모·자료 출처를 확인함. 장소를 방문별로 제외/재포함할 수 있으며, 최종 승인 시 선택한 방문만 비공개 내 여행으로 저장함. 모두 제외하면 생성을 막음. 빈 DAY·기간·다른 DAY의 같은 장소를 보존함. 로컬 추천 상태 표시는 유지함.
- **담기:** 하단 팝업 맨 위에 같은 큰 사진 카드를 표시하고 여행·기간·DAY 입력을 이어서 제공함. 해당 DAY의 담김 해제를 카드에 연결하고 다른 일정에 들어 있는 정보도 표시함. 작은 가로 저장 목록과 저장 상단 AI 영역은 변경하지 않음.
- **공통 카드:** 본문은 그대로 재사용하고 `actions` 슬롯으로 발견 저장/공유, AI 포함/제외, 실제 DAY 담김 해제를 구분함. AI 선택은 녹색, 발견 북마크는 기존 코랄임. 사진이 없거나 실패하면 원래 크기의 안내를 표시하며 다른 장소 사진을 대체하지 않음.
- **검증:** 단위 테스트 49개와 App 실제 연결 13시나리오 통과. 큰 카드 사진205px·제목21px·설명13px과 320/390/460px의 팝업·스크롤·선택 상태는 `artifacts/landmark-modal-qa/`에서 전후 비교함. 추가 17시나리오에서 전체 제외·재포함·선택 방문만 저장·빈 DAY 보존·사진 실패·출처 유지 및 녹색 상태를 확인함. sticky DAY는 본문 padding을 고려한 top:-20px로 헤더 아래 틈이 0px임을 실측함. 전체 보고서 125쪽의 데스크톱·모바일·인쇄 검수는 `artifacts/spot-first-reports-qa/results.json`임. 최종 웹 빌드도 통과함.
- **이번 경계:** 새로운 주변 업체 검색·RAG·숙박/식사 최적화 엔진이나 네이티브 기능은 개발하지 않음. 실제 사용자 저장소에 테스트 데이터를 넣지 않음. 아래 45개 테스트/113쪽 검수는 이번 후속 전의 기록임.

## 구현 흐름

1. **저장 장소 담기:** 작은 가로 저장 카드를 유지함. `여행에 담기`를 누르면 기존 BottomSheet가 열림. 내 여행을 선택하거나 새 여행의 제목·기간·선택 출발일을 입력함. 당일치기~6박 7일에 맞춰 DAY가 표시되고, 원하는 DAY에 담으면 그 내 여행 상세로 이동함.
2. **기간과 DAY 분리:** 저장 상단 AI 카드의 여행 기간과 개별 담기 팝업의 DAY는 독립 상태임. 기존 여행 기간은 담기 팝업에서 바꾸지 않음. 내 여행에서 편집함.
3. **담김·해제:** 내 여행만 대상으로 함. 같은 DAY 중복을 막고 다른 DAY 재방문은 허용함. 여행·DAY별 담김을 표시하며 정확한 방문만 해제함. 북마크·다른 여행·사진·글을 보존함. 취소와 저장 실패에는 원본을 바꾸지 않음.
4. **홈 AI 여행 만들기:** 기존 홈 검색 안내 카드의 형태를 재사용함. 글 입력 → 지역·기간·속도·교통수단 확인 → DAY별 초안 → 명시적인 비공개 내 여행 저장 흐름임. 로컬 등록 장소의 단어 일치·직선거리 기반 후보 배치이며 실제 LLM/RAG·실시간 경로 연결이 아님을 화면에 표시함.
5. **추천 여행 분리:** 여행기 메뉴의 여행자 여행기와 AI 추천 여행을 구분함. 공식 자료로 구성한 샘플은 후자에 표시함. 사용자가 홈에서 만든 비공개 초안은 공개 여행기 목록으로 노출하지 않음.
6. **공공자료 콘텐츠:** 개별 자료의 이용 조건과 장소가 일치하는 사진을 확인한 뒤 구성함. 저작권이 없다고 표현하지 않고 공공누리 제1유형 출처표시 조건을 따름. 출처는 이미지 재사용·일정 복사에도 유지함. 실제 방문 체험담이나 인기 수치를 꾸미지 않음.

## 업체 검색 방향 변경

- Kakao Local 연결 계획을 네이버 지역 검색 API로 변경함. 현재 실제 외부 업체 검색 연결은 만들지 않음.
- 신규 신청은 NAVER API HUB 기준임. 네이버는 독립 검색 확인 채널로 두며 선택했다고 내부 DB·여행에 영구 복사할 수 있다고 가정하지 않음. 자체 추천·RAG는 별도로 권리를 확보한 내부 자료만 사용함.
- 결과 최대 5개·start 1이며 다음 페이지를 전제하지 않음. HUB 개요의 월775,000건/키50RPS와 지역 API 본문의 일25,000회가 달라 적용 한도를 운영 전에 확인함. 현재 한시 무료를 영구 무료로 쓰지 않음.
- 업체명·분류·주소·링크·좌표 제공 형식은 승인된 시험 응답으로 검증함. 사진·별점·반경·경로 필드가 없고 전화번호는 빈 값임. 결과 정렬·자체 사진 결합·장기 저장은 승인 범위 확인 전 구현하지 않음.
- NCP API 키를 서버에만 보관함. 개발자센터 검색 특약의 2026-09-07 개정과 HUB 별도 계약을 구분하고 적용 약관·목적별 저장·캐시·AI·다른 지도·수익화 허용 범위를 서면 확인함.
- 지도 표시는 MapLibre를 유지함. 향후 이동 경로는 교통수단별 공급자로 별도 검증함. 네이버 검색 채택이 네이버 지도·길찾기 채택을 뜻하지 않음.
- 추천 인기 순위는 우리 데이터의 실제 저장·담김 등으로 산정하며 네이버 검색 결과 순서를 내부 인기도로 둔갑시키지 않음.
