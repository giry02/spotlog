확인일: 2026-09-10. **수급·API·갤러리는 계획·검토 사항이며 연동 완료를 뜻하지 않음.** 최초 수급안 작성은 로컬 문서 작업이었으며, 후속 확정한 사진 출처 표시 기준은 6절에 함께 기록함. API 계정 신청·키 발급·대량 수집·커밋·푸시·공개 배포를 수행하지 않음.

## 02 / 32 · 1. 확정할 방향

- 스팟으로 DAY별 일정의 기본 구성을 만들고, **내 여행**에서 주변 음식점·카페와 숙박 거점을 보완함. 저장 화면에 일정 편집 도구나 보관함 단계를 다시 만들지 않음.


- 내부 추천용 자료는 사용권이 확인된 공공 개방 자료·직접 제작·제휴·사용자 콘텐츠로 확보함. 네이버 검색 결과를 내부 장소 DB나 RAG에 무조건 적재하는 안은 채택하지 않음.


- 랜드마크는 **기존 카드의 사진 영역에서 같은 장소의 여러 이미지를 좌우로 넘겨 보는 구조**를 1차 보완 목록에 넣음. 지역 안내·AI 미리보기·담기 팝업의 공통 카드에 적용할 계획임. 현재 동작을 바꾼 것은 아님.


- 기술 도입 판단은 `검색 결과를 보여줄 수 있음 / 여행에 영구 저장할 수 있음 / 자체 추천에 사용할 수 있음 / LLM에 전달할 수 있음`을 각각 구분함. API 키 발급은 이 모든 권한의 승인이 아님.

## 07 / 32 · TourAPI 장소·좌표와 공공 사진 연결 — 추가 개발 기준 · 1/3

**TourAPI로 장소의 기본 정보를 먼저 확보하고, 사용 조건을 확인한 사진을 같은 내부 장소에 연결함.** 공공누리는 이용 조건을 표시하는 체계이자 자료 검색 창구이며 모든 사진에 표준 좌표가 함께 제공되는 장소 데이터베이스로 취급하지 않음. 다음 내용은 추가 개발 계획으로, 현재 샘플 화면과 출처 팝업이 동작한다는 것과 실제 API 자동 수급이 연결되었다는 것을 구분함.

| 항목 | 적용 기준 |
|---|---|
| API 이용과 비용 | 국문 TourAPI의 이용 요금은 무료임. 활용 신청·인증키·호출 한도·운영계정 심사와 트래픽 증설 조건을 확인함. 무료 호출을 무제한 수집이나 저작권 소멸로 해석하지 않음 |
| 장소 기본 정보 | 공급자 콘텐츠 ID, 장소명·주소·분류·좌표·소개·이미지 등 실제 응답에서 제공되는 필드를 수집함. 항목이 없으면 누락 상태로 남기며 모든 관광지에 사진·좌표·최신 운영 정보가 있다고 가정하지 않음 |
| 위치 검증 | 원천 좌표계와 경도·위도 순서·값 범위를 확인하고 지도용 좌표로 정규화함. 관광지 대표 지점과 실제 입구를 구분하고, 촬영 위치를 관광지 입구나 경로 도착점으로 자동 사용하지 않음 |

## 08 / 32 · TourAPI 장소·좌표와 공공 사진 연결 — 추가 개발 기준 · 2/3

| 항목 | 적용 기준 |
|---|---|
| 사진 연결 | 관광사진 API·지자체 공개 사진 중 장소가 일치하고 권리가 확인된 사진을 확보함. 공급자 ID·주소·좌표·사진 설명을 대조한 뒤 내부 placeId에 mediaId 여러 개를 연결함. 이름만 같은 다른 지점은 합치지 않음 |
| 개별 이용 조건 | 1유형은 출처 표시 조건으로 상업적 이용·변경이 가능하므로 카드용 가공·사진 편집·모션의 우선 후보로 삼음. 3유형은 출처 표시와 변경 금지를 지킨 상업적 이용을 별도로 검토하며 원형 사용 또는 별도 허락 범위 안에서 제공함 |
| 출처 표시 | 현재 짧은 ‘사진 출처’ 버튼과 기존 하단 팝업을 유지함. 사진마다 기관·저작자·라이선스·원문 링크·확인일을 연결하고 캡션에 같은 출처를 다시 붙이지 않음. 여러 장 넘김은 현재 사진의 출처를 함께 바꾸는 후속 요건임 |
| 자동 수급 운영 | B1의 서버·권한·키 관리 기반 후 B2에서 페이지 단위 수집, 재시도·한도 제어, 중복 통합, 변경분 갱신·권리 철회 처리를 구현함. 수급 규격과 검증을 확정하기 전 전국 자료를 일괄 내려받지 않음 |


1차에는 사용 조건을 확인한 소량 샘플과 장소·사진·출처 필드를 준비하여 기존 카드·팝업 및 계획된 여러 사진 탐색을 검증함. 2차에는 편집·이동·복사 후 장소와 사진 출처 연결을 보존함. 3차에는 허용한 내부 자료만 사용하는 추천·번역 화면을 검증함. 실제 TourAPI 자동 수집은 B1·B2 이후 작업임. 사진 저장·전송·검수와 서버 운영비는 무료 API 호출료와 별도 비용으로 산정함.

## 10 / 32 · 사진 사용 조건

공공자료를 ‘저작권 없음’이라고 표현하지 않음. 상업 표시·재배포·변형·AI 사용을 별도로 기록하고 불명확하면 사용을 보류함.

- 공공누리 0유형과 1유형을 우선 검토함. 1유형은 출처 표시를 유지함.


- 2·4유형의 비상업 조건은 상용 서비스 기본 수급안과 맞지 않으므로 별도 허락 없이는 제외함.


- 3유형은 변경 금지를 확인함. 자동 크롭·모션·합성을 허용된 것으로 처리하지 않으며, 필요한 사용 형태가 불명확하면 문의 후 적용함.


- AI유형은 AI 학습 목적의 별도 이용 조건임. 일반 카드 사진의 재배포 허가와 같지 않음. RAG 직접 인용 시 출처 표시 조치 등 해당 조건을 검토함.


- 유형과 별개로 초상권·상표권·제3자 권리 및 기관이 서비스를 보증하는 것으로 오해할 표현을 확인함. [공공누리 공식 이용조건](https://www.kogl.or.kr/static/html/opencode.html)


관광사진 API는 웹용 URL·촬영자·촬영지 등을 제공하는 1유형 콘텐츠로 소개됨. 포토코리아 웹에서 신청하는 고해상도 원본은 사용용도 등 별도 이용 안내가 있으므로 API 개방 이미지와 동일하게 취급하지 않음. 개별 자산과 취득 경로별 조건을 남김. [관광사진 API](https://www.data.go.kr/data/15101914/openapi.do), [포토코리아 이용 안내](https://phoko.visitkorea.or.kr/main/index.kto)

## 11 / 32 · 초기 콘텐츠 운영 목표 — 제안값

서울·부산·제주에서 도시별 핵심 스팟 약 20곳, 스팟별 사진 2\~3장을 검수하는 범위부터 시작함. 사진이 부족하면 한 장만 제공하며 다른 장소의 이미지를 채우지 않음. 음식점·카페는 주요 스팟 주변 3\~5개 후보를 우선 확인하되 전부 자동 삽입하지 않음. 숙소는 스팟마다 반복해서 붙이지 않고 숙박 지역·교통 접근성을 기준으로 준비함.

각 도시의 당일·1박 2일·2박 3일 여행기 1개씩 총 9개를 목표로 함. **현재 완료 수가 아님.** 기존 부산·경주 자료 4여행·11사진은 [사용 기록](../PUBLIC_CONTENT_SOURCES.md)을 따라 재활용하고 서울·제주 부족분을 확보함. 이후 경주·강릉으로 확대함. 수집한 레코드 수, 검수된 추천 가능 장소 수, 발행 여행기 수를 분리함.

## 21 / 32 · 6. 장소·사진·권리 데이터 규격 · 2/2

이름만으로 장소를 합치지 않음. 지점·주소·좌표·업종을 대조하고 애매한 후보는 검수함. 공급자별 좌표계를 변환·검증하며 원본 좌표계도 남김. 외국어 자료는 ID가 동일하다고 가정하지 않고 같은 내부 장소에 확인 후 연결함.

수집 → 권리 확인 → 중복 대조 → 좌표·분류 정리 → 사진·본문 검수 → 발행 → 변경·철회 반영 순서로 운영함. 원천 정보가 바뀌어도 사용자가 작성한 여행 당시 글을 덮어쓰지 않음. 현재 장소 정보와 여행 기록을 분리함.

삭제·비공개 전환·권리 철회는 원문뿐 아니라 검색 인덱스·임베딩·번역·썸네일·캐시에도 반영함. 재사용이 허가된 데이터에는 원천 동기화 주기에 맞춰 확인 일정을 두고, 운영 시간처럼 변동이 큰 정보는 일정 생성 시 재확인하거나 ‘미확인’으로 표시함. 일괄적인 영구 저장·재수집을 모든 공급자에 적용하지 않음.

## 22 / 32 · 사진 출처 표시·중복 방지 — 확정 기준 · 1/3

**사진 설명은 캡션에, 출처는 사진에 연결된 메타데이터에 보관함.** 화면에는 짧은 ‘사진 출처’ 버튼을 제공하고 누르면 기존 하단 팝업에서 상세를 확인함. 같은 출처 문장을 캡션과 버튼 옆에 반복하지 않음. 출처를 제거하는 것이 아니라 표시 위치를 하나로 정리하는 기준임.

| 구분 | 수집·표시·보존 기준 |
|---|---|
| 수집 메타 | 사진마다 원문 제목·소유 기관·표기된 저작자·제작/게시 시점·라이선스명·조건 URL·원문 URL·확인일을 기록함. 원문에 없는 저작자나 날짜는 추정하지 않고 미표기로 구분함 |
| 캡션 | 사진의 장소·장면·촬영 맥락을 설명함. 새로 만드는 샘플에는 `사진: 기관 · 공공누리 제1유형` 같은 표시용 출처 문구를 중복 저장하지 않음 |
| 개별 사진 | 가까운 위치의 ‘사진 출처’ 버튼에서 해당 사진의 메타데이터와 원문·이용 조건 링크를 보여줌. 긴 출처를 이유로 저작자나 링크를 생략하지 않음 |
| 여행기 전체 | 하단의 ‘사진 출처 / N개 자료’ 행에서 사용된 자료 목록을 확인함. 동일 자료의 반복 사용은 중복 집계하지 않되 사진별 출처 연결은 유지함 |

## 25 / 32 · 7. 랜드마크 여러 이미지 좌우 넘김 — 1차 추가 계획 · 1/2

**사진 한 장짜리 카드를 새 레이아웃으로 교체하는 것이 아니라, 승인된 카드의 사진 영역만 여러 장을 탐색할 수 있게 보완함.** 이 절은 앞으로 구현할 구조임. 실제 다중 사진 기능은 이번에 수정하지 않음.

| 화면 | 적용 기준 |
|---|---|
| 지역 안내 랜드마크 카드 | 같은 장소의 사진 목록을 좌우로 넘김. 사진 아래 정보·저장·공유 동작은 유지함 |
| AI 일정 미리보기 | 같은 카드·사진 목록을 재사용함. 사진 넘김과 방문별 포함/제외를 분리함 |
| 담기 하단 팝업 | 같은 사진을 확인한 후 여행·DAY를 선택함. 사진을 넘긴다고 담기·해제를 실행하지 않음 |
| 전체 화면 사진 피드 | 기존 ‘다음 장소는 세로, 같은 장소 사진은 가로’ 구조를 유지함 |
| 저장 바깥 목록 | 작은 가로 SavedPlaceCard와 대표 썸네일을 유지함. 큰 사진 카드로 일괄 교체하지 않음 |

## 27 / 32 · 동작과 표시

- 기존 사진 영역의 높이·모서리·글자·여백·색상을 유지함. 카드 전체가 아니라 사진 영역에만 가로 넘김을 적용함.


- 두 장 이상이면 작은 현재 순서/전체 개수 표시와 이전·다음 접근 수단을 제공함. 한 장이면 불필요한 넘김 표시를 숨김.


- 처음·마지막 사진에서 멈추는 방식을 기본안으로 함. 자동 재생이나 무한 반복을 기본으로 넣지 않음.


- 현재 사진의 출처·촬영자·설명을 함께 바꿈. 다른 사진의 출처가 남지 않게 함.


- 사진이 없거나 실패하면 기존 영역에 상태를 표시함. 나머지 유효 사진은 계속 볼 수 있게 함. 장소명만 보고 유사 사진을 자동 연결하지 않음.


- 활성 사진과 인접 사진을 우선 읽고 나머지는 지연 로딩함. 목록 전체의 원본 사진을 처음부터 내려받지 않음.


- 사진 넘김은 세로 목록 스크롤·하단 팝업 스크롤/닫기와 충돌하지 않게 함. 드래그 종료를 카드 클릭·담기·공유로 처리하지 않음.


- 키보드 이전/다음과 명확한 접근성 이름을 제공함. 조작 후 불필요한 초점 이동이나 스크롤 초기화를 막음.


- 포함/제외·DAY 상태 갱신 때 보고 있던 사진을 유지함. 사진 삭제나 권리 철회로 목록이 바뀌면 유효한 순서로 보정함.

## 31 / 32 · 9. 비용·품질 관리

월 비용을 `수집·검수 + 서버·DB + 사진 저장·전송 + 검색 API + 내부 검색/RAG + 경로 + LLM + 번역`으로 분리함. 공공 API가 무료여도 사진 전송·편집 검수는 무료가 아님. 승인된 쿼터와 확인된 단가를 설정값으로 관리하고, 네이버 유료 전환·약관 변경 알림을 운영 점검에 포함함.

주요 검증 항목은 다음과 같음.

- 같은 지점 판별, 좌표계 변환, 출입구 위치, 폐업·누락·오래된 정보 처리.


- 사진과 장소 일치, 개별 권리·현재 사진 출처, 권리 불명확 자료 차단.


- 네이버 결과의 순위·출처·링크 보존, 장기 저장·LLM 유입 차단, 승인 범위 외 기능 비활성화.


- 키 비노출, 사용량 제한, 타임아웃·빈 결과·쿼터 초과, 허용 캐시 만료 삭제.


- 공용 검색의 비공개 자료 제외, 공개 범위 변경·삭제 후 인덱스·번역·미디어 반영.


- 실제 인기와 편집 추천 구분, 데이터 부족 시 후보 없음 안내, 승인 전 일정 불변.


실제 API 응답·상용 계약·Android 실기기 시험은 후속 작업임. 이 문서는 조사와 설계 기준을 기록하며 법적 사용 허락이나 검수 완료를 대신하지 않음.
