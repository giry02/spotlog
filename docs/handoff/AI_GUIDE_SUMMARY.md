## 01 / 12 · AI 관광 가이드의 핵심

SPOTLOG · AI GUIDE SUMMARY · 1

Spotlog 내부 데이터에서 취향에 맞는 인기 장소를 찾고, 음식점·숙소와 실행 가능한 일정으로 연결함.

| 구성 | 쉽게 말하면 | 담당 역할 |
| --- | --- | --- |
| 내부 RAG | 우리 자료를 먼저 찾아 읽게 함 | 여행기·장소 설명에서 지역/취향에 맞는 후보와 추천 근거를 찾음. |
| DB·인기 순위 | 조건과 실제 반응을 계산함 | 좌표·분류·권한으로 걸러내고 저장·복사·반응을 보정해 인기 순위를 계산함. |
| LLM | 조건을 이해하고 설명함 | 자연어 요청을 해석하고 후보 조합을 보조하며, 확인된 근거로 추천 이유와 관광 안내를 작성함. |
| 경로·일정 엔진 | 실제로 다닐 수 있는지 검사함 | 교통수단별 이동 시간과 체류·고정 조건을 확인하고 DAY별 배치를 검증함. |

**현재 자동 일정은 로컬 정렬과 정해진 문구 기반임.** 내부 RAG·실제 교통·LLM 추천 엔진은 이후 개발할 대상임.

## 02 / 12 · 추천 방식과 업체 매칭

SPOTLOG · AI GUIDE SUMMARY · 2

홈·저장의 AI 입력을 하단 팝업으로 열고 조건·후보를 확인함. 승인 후 비공개 내 여행 상세에서 수정함.

| 모드 | 처리 기준 |
| --- | --- |
| 지역·취향 추천 | 내부 후보에서 랜드마크·음식점·숙소를 자동 조합하고 최종 저장 전 사용자 승인을 받음. |
| 저장한 곳 구성 | 저장 장소를 전달받아 하단 팝업에서 기간·조건을 정함. 승인 후 내 여행으로 저장함. 음식점·숙소 보충은 선택 사항임. |
| 외부 보완 | 내부 자료가 부족하면 별도 후보로 제시함. 승인 없이 넣거나 내부 인기 장소로 표시하지 않음. |

### 예시: 부산 2박 3일, 덜 걷고 바다·로컬 음식 선호

- 지역·취향·걷기 조건으로 내부 랜드마크를 찾고 실제 반응과 근거를 확인함.

- 음식점은 주변 인기와 식사 시간·다음 동선을, 숙소는 여러 날의 이동 부담을 고려해 매칭함.

- 실제 경로로 무리한 이동을 검사하고, 미배치 장소·이유·변경안을 보여 준 뒤 승인받음.

필요 데이터: 고유 장소 ID·좌표·분류·메타 정보, 연결된 여행기/사진, 확인일·권한, 중복을 제거한 실제 저장·복사·반응. 숙박 가격·예약은 제외함.

## 03 / 12 · 기술과 모델 선택 기준

SPOTLOG · AI GUIDE SUMMARY · 3

원본의 후보 기술을 역할별로 나눔. 특정 모델을 확정하거나 추천 품질이 검증됐다고 가정하지 않음.

| 역할 | 원본의 적용 후보 | 선택 기준 |
| --- | --- | --- |
| 검색 기반 | PostgreSQL + PostGIS + pgvector | 장소·권한·거리 조건과 키워드/의미 검색을 함께 관리함. |
| 의미 검색 | text-embedding-3-small / BGE-M3 | 문장의 의미를 검색용 숫자로 변환함. 한국어 여행 데이터 검색 품질과 운영비를 비교함. |
| 추천·설명 LLM | GPT / Claude / Gemini 계열 비교 | 같은 후보로 조건 준수·추천 근거·한국어/영어 품질·지연·1건 총비용을 평가함. |
| 경로 조회 | 자동차·도보 TMAP, 대중교통 ODsay 검증 | 교통수단별 실제 구간을 확보함. 상용 계약·표시·캐시·요금 조건 확인 후 확정함. |
| 일정 배치 | 규칙 기반 시작, 필요 시 OR-Tools | OR-Tools는 방문 순서·시간 제약 계산 도구임. 복잡한 고정 일정이 필요할 때 추가함. |

지도 표시는 현재 MapLibre를 유지함. LLM이 좌표·영업시간·경로를 만들어내지 않도록 결과를 검사함. 개별 모델명·단가·조건은 원본 29~33쪽을 참고하고 도입 시 다시 확인함.

## 04 / 12 · 관광 안내와 자동번역

SPOTLOG · AI GUIDE SUMMARY · 4

국내 여행기 원문을 유지하고, 외국인이 실제로 찾아가고 이용할 수 있는 영어 안내를 연결함.

| 영역 | 처리 방식 |
| --- | --- |
| 여행 중 안내 | 오늘 일정·다음 장소 이동·볼거리·이용 주의사항을 현재 여행과 확인된 근거로 답함. |
| 자동번역 | 본문·사진 설명은 원문 버전별로 번역·재사용함. UI 문구는 직접 관리하고 댓글은 요청 시 번역함. |
| 번역 기반 | Google Cloud Translation Advanced와 용어집을 적용 후보로 검토함. 원문/자동번역/검수/재번역 필요를 구분함. |
| 현장 정보 | 한글 장소명·주소 크게 보기와 복사, 역·출구·마지막 도보, 예약·결제·문화 차이 정보를 원문부터 확보함. |

### 안내 품질의 필수 기준

- 주소·장소명·숫자·날짜·부정 표현을 보존하고 출처와 확인 시점을 표시함.

- 미확인 영업·대기시간은 모른다고 표시함. 실제 방문자의 체험담을 생성하지 않음.

한국어→영어가 첫 운영 범위임. 추가 언어·음성 가이드·실시간 통역·상시 위치 추적은 후속 단계로 분리함.

## 05 / 12 · 개발 순서와 비용 관리

SPOTLOG · AI GUIDE SUMMARY · 5

모델 호출료뿐 아니라 데이터 준비·검색·경로·번역·운영 비용까지 묶어 판단함.

| 단계 | 진행 내용 |
| --- | --- |
| 프런트엔드 1·2·3차 | 현재 화면 역할별 스타일을 재사용함. 1차 담기 팝업·홈 AI 초안, 3차 안내·번역 확장을 샘플로 검증함. |
| 서버 기반 이후 | 내부 데이터/권한·검색 색인을 준비하고, 추천·업체 매칭과 LLM 비교를 진행함. |
| 엔진·영어 시범 | 실제 경로·일정 검증과 관광 안내·번역을 연결한 뒤 비공개 평가를 통과함. |

### 예산에 포함할 항목

- 초기 원문 정리·임베딩 색인과 콘텐츠 검수 비용을 별도 확보함.

- 요청별 검색·LLM·재시도, 교통 경로, 새 번역량, DB·저장·전송 비용을 합산함.

- 동일 요청 중복 방지, 변경분만 재처리, 번역 재사용, 사용자 한도·예산 경보를 적용함.

**도입 전 결정:** 내부 자료·인기 지표 기준, 공급자 계약, 모델 비교 결과와 실제 1건 비용, 월 예산 한도를 확정함. 비밀 키와 비공개 여행의 권한은 서버에서 관리함.

## 06 / 12 · 홈 AI와 네이버 검색 · 적용 구분

2026.09.10 · ADDITIONAL DECISIONS

홈의 글 입력부터 초안 확인·승인·내 여행까지 먼저 연결하고, 실제 추천 엔진은 서버 기반 이후 적용함.

| 항목 | 추가 구현 기준 |
| --- | --- |
| 홈 입력과 결과 | 1차는 자유 문장의 지역·기간·취향·제외 조건을 등록 자료에 대조함. DAY별 로컬 초안과 한계를 표시하며, 승인한 결과만 비공개 내 여행으로 생성함. |
| RAG·인기 매칭 | 현재 화면 미리보기와 실제 추천 엔진을 분리함. 서버에서는 내부 공개 데이터·권한·인기 지표로 후보를 추린 뒤 LLM 설명과 실제 경로 검증을 연결함. |
| 네이버 지역 검색 | 신규 연결은 NAVER API HUB를 검토함. 최대 5건·start 1이며 월·일 한도 안내 차이를 콘솔에서 확인함. 한시 무료를 상시 무료로 가정하지 않음. |
| 제공 정보와 한계 | 업체명·분류·지번/도로명 주소·링크·WGS84 mapx/mapy를 장소 후보로 사용함. 사진 필드는 없고 전화번호는 빈 값임. 가격·재고·인기 점수·길찾기 응답으로 취급하지 않음. |
| 서버 연결 준비 | HUB의 API Gateway 키를 서버에서만 사용함. 좌표·표시와 계약을 검증하고, 내부 병합·영구 저장·RAG 사용은 허용 범위 확인 전 차단함. |
| 추천·출처 구분 | 공개 추천 샘플은 여행기의 AI 추천 여행에서 표시함. 개인 생성본은 비공개로 유지함. 공공 사진도 개별 이용 조건·저작자·원문 출처를 기록하며 생성 안내를 방문 후기로 꾸미지 않음. |

지역을 알아듣지 못하거나 후보가 부족하면 확인을 요청함. 장소·사진·영업시간·인기 수치를 임의로 만들지 않고, 기간과 담을 DAY를 분리함.

## 07 / 12 · 스팟 중심 일정과 주변 장소 추가

2026.09.10 · SPOT-FIRST FLOW

스팟으로 DAY별 일정의 기본 구성을 정한 뒤, 내 여행에서 음식점·카페와 숙박 거점을 보완함.

| 화면 | 사용자 동작과 연결 |
| --- | --- |
| 장소 발견·저장 | 가고 싶은 스팟을 저장함. 저장 화면은 기존 목록·지역 필터·여행 만들기 진입을 유지하고 업체 추천·일정 편집을 펼치지 않음. |
| 여행 만들기 | 기간과 DAY를 선택하고 사진 카드로 장소를 확인함. 승인하면 해당 내 여행 상세를 열며 이후 수정은 그곳에서 진행함. |
| 내 여행 · 스팟 주변 | 스팟 카드의 ‘＋ 주변 장소’로 하단 팝업을 엶. 추천 / 직접 검색 / 저장한 장소에서 음식점·카페를 고름. |
| 추가 위치 | 현재 여행·DAY·기준 스팟을 팝업에 표시함. 고른 장소는 기준 스팟 다음에 추가하며 여행과 DAY를 다시 묻지 않음. |
| 숙박과 공개 열람 | 숙소는 숙박할 DAY의 거점으로 추가함. 다른 사람의 여행기에는 편집 동작을 숨기고 읽기·저장·복사 흐름을 유지함. |

**화면 역할:** 저장은 모으기·만들기, 내 여행은 DAY별 보완·관리임. 주변 업체의 직접 선택과 선택적 AI 보완은 같은 후보와 장소 카드를 사용함.

스팟을 먼저 고르는 흐름만으로 동선이 보장되지는 않음. 예약한 숙소·고정 시간은 처음부터 반영하고, 음식점은 다음 스팟 방향과 식사 시간을 함께 검토함.

## 08 / 12 · 사진 카드로 확인하는 AI·담기 팝업

2026.09.10 · SHARED PLACE CARDS

지역 안내에서 사용 중인 큰 랜드마크 카드의 사진·정보 구조를 AI 미리보기와 담기 팝업에도 재사용함.

| 적용 위치 | 구현 기준 |
| --- | --- |
| AI 일정 미리보기 | DAY별 후보를 사진·장소명·지역·설명·체류 정보가 있는 카드로 보여줌. 방문별 제외·다시 포함으로 장소를 고른 뒤 여행 생성을 승인함. |
| 담기 하단 팝업 | 담을 장소를 같은 큰 사진 카드로 보여주고 그 아래 여행·기간·DAY를 선택함. 여러 장소도 개별 카드를 확인할 수 있게 함. |
| 동일한 장소 표현 | 기존 LandmarkGuideCard의 사진 비율·정보 위계·여백을 재사용함. 저장 상태와 출처를 유지하고 화면 목적에 맞는 동작만 연결함. |
| 화면별 역할 보존 | 팝업 바깥 저장 목록의 작은 가로 SavedPlaceCard는 유지함. 여행기 본문 임베드·사진/영상 쇼츠를 일괄 교체하지 않음. |
| 미확인·실패 상태 | 장소 사진이 없으면 사진 없음으로 표시함. 다른 장소의 사진·가짜 평점·인기를 채우지 않으며, 로컬 초안·출처·오류 상태를 구분함. |

**승인 기준:** 글 목록만 보고 생성·담기를 결정하게 하지 않음. 팝업을 닫거나 뒤로 가면 원래 화면 위치를 유지함. 새로 담기·AI 생성은 승인 전 원본 여행을 변경하지 않음.
