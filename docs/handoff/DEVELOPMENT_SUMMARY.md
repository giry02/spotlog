2026-09-10 · 4쪽 요약본. 2026-09-08~09 원본 계획에 근거하며, 새로운 기능 구현이나 모델 선정 완료를 뜻하지 않음.

[발표형 요약](https://giry02.github.io/spotlog/spotlog-development-summary.html) · [기존 원본](https://giry02.github.io/spotlog/spotlog-development-plan.html)

## 1. 추가 개발 계획 핵심

기존 여행기 서비스를 유지하고, 총 3주간 프런트엔드 사용 흐름을 보완함.

| 구분 | 요약 |
| --- | --- |
| 제품 방향 | 여행기를 읽고 장소를 저장한 뒤, 내 일정으로 활용하고 여행 후 기록을 발행함. 국내 콘텐츠를 먼저 쌓고 영어 이용을 준비함. |
| 현재 활용 | 홈 추천·여행기 검색, 장소 발견·지역별 저장, 여러 여행과 DAY 편집, 글·사진·장소 블록, 여행기 복사·지도 표시를 활용함. |
| 우선 보완 | 담을 여행·DAY를 명확히 선택하고, 저장/담김/해제를 구분함. 작성 중 기록 복구와 사진·장소 정보의 신뢰도를 높임. |
| 운영 전제 | 현재 AI·댓글·반응 등의 로컬 동작과 실제 서버 기능을 구분함. 3주 완료는 화면 검증 단계이며 정식 출시를 뜻하지 않음. |

**모바일웹과 하이브리드 앱을 유지함.** 숙소·음식점은 여행기 속 장소로 다루며 예약·결제·숙박비 비교는 제외함.

[원본 상세](https://giry02.github.io/spotlog/spotlog-development-plan.html#slide-4)

## 2. 3주 프런트엔드 개발

개발자 A는 탐색·저장, B는 작성·일정·AI 화면을 담당함. 선택 인력 C는 콘텐츠·통합 검수를 지원함.

| 차수 | 주요 개발 | 완료 기준 |
| --- | --- | --- |
| 1차 · 1주 | 보관함 관리, 여행·DAY 선택 분리, 담김 상태·해제, 검색/목록/오류 정돈 | 원하는 여행의 원하는 DAY에 담고 해당 항목만 해제함. |
| 2차 · 1주 | 자동 임시 저장·복구, 글/사진/장소 편집, DAY 이동·복사, 삭제 복구·지도 연결 | 사진 있는 여행기를 복구할 수 있고, 복사본 수정이 원본에 영향을 주지 않음. |
| 3차 · 1주 | AI 조건·추천·승인·부분 수정, 관광 안내, 한국어/영어 전환과 전체 검수 | 샘플 응답으로 생성부터 수정·안내·영어 보기까지 연결함. |

### 주간 운영 기준

- 1일차 설계 확정, 2~4일차 구현, 5일차 통합 테스트·수정에 배정함.

- AI·번역·외부 장소 검색은 연결 규격을 맞춘 샘플로 검증함. 실제 연동 전 상태를 표시함.

로그인·서버 저장·실제 집계·외부 AI 호출은 이후 단계임. AI 문서 때문에 3주 일정이 별도로 추가되지 않음.

## 3. 백엔드와 콘텐츠 확보 순서

3주 프런트엔드 이후 데이터 기반과 운영 안전성을 갖춘 뒤 실제 AI를 연결함.

| 순서 | 추가 개발 |
| --- | --- |
| B1 · 데이터 기반 | 회원·권한·기기 동기화, 로컬 여행 이전, 이미지 저장소, 계정 삭제·백업. |
| B2 · 콘텐츠 운영 | 장소 검색·중복 통합, 사진/영상 업로드·최적화, 공개 URL·검색, 원문/복사 관계. |
| B3 · 커뮤니티 | 실제 조회·담김·댓글·반응, 작성자 등급·팔로우, 신고·차단·관리자 처리. |
| B4 · AI·영어 | 내부 RAG 추천·업체 매칭, 실제 경로·일정·관광 안내, 번역·품질·사용량 관리. |
| B5 · 앱 확장 | 원격 푸시·수신 설정, 오프라인 자료, 현장 방문 기록, 앱 링크·추가 언어·공동 편집. |

### 초기 콘텐츠 운영

- 서울·부산·제주에서 당일/1박 2일/2박 3일 샘플 9개를 먼저 검수함. 이후 경주·강릉으로 확대함.

- 작성자를 모집하고 실제 저장·복사·작성 완료를 측정함. 샘플 반응을 실사용 성과로 사용하지 않음.

## 4. 우선 결정과 완료 판단

기존 기능을 다시 만들기보다 저장의 정확성, 기록 보존, 여행 정보의 신뢰도를 먼저 확인함.

| 판단 항목 | 통과 조건 |
| --- | --- |
| 저장·편집 | 여행 기간과 대상 DAY가 독립적이며, DAY 이동/복사/삭제 후 글·사진·장소 연결이 유지됨. |
| 모바일 이용 | 새로고침 후 로컬 초안을 복구하고, 긴 스크롤에서도 뒤로가기·DAY 전환이 가능함. |
| 신뢰도 | 장소와 사진을 맞추고 미확인 좌표·영업·추정 경로를 표시함. 도보를 자동차 경로와 혼동시키지 않음. |
| 출시 판단 | 실제 회원·권한·집계·미디어·운영 대응은 백엔드 이후 별도 검증함. 화면 시연만으로 출시 완료라 하지 않음. |

### 착수 전에 확정할 사항

- 2인 역할과 검수 시간을 배정하고, 첫 9개 샘플의 사진 권리·내용 검수 담당을 정함.

- 이번 3주 범위와 후속 서버 범위를 고정함. 국내 콘텐츠 확보는 별도 운영 업무로 함께 진행함.
