## 01 / 11 · 추가 개발 계획 핵심

SPOTLOG · DEVELOPMENT SUMMARY · 1

프런트엔드를 1차·2차·3차로 나누어 구현함. 차수별 완료 조건을 기준으로 진행함.

| 구분 | 요약 |
| --- | --- |
| 제품 방향 | 여행기를 읽고 장소를 저장한 뒤, 내 일정으로 활용하고 여행 후 기록을 발행함. 국내 콘텐츠를 먼저 쌓고 영어 이용을 준비함. |
| 현재 활용 | 홈 추천·여행기 검색, 장소 발견·지역별 저장, 여러 여행과 DAY 편집, 글·사진·장소 블록, 여행기 복사·지도 표시를 활용함. |
| 우선 보완 | 담을 여행·DAY를 명확히 선택하고, 저장/담김/해제를 구분함. 작성 중 기록 복구와 사진·장소 정보의 신뢰도를 높임. |
| 운영 전제 | 현재 AI·댓글·반응 등의 로컬 동작과 실제 서버 기능을 구분함. 3차까지 완료는 화면 검증 단계이며 정식 출시를 뜻하지 않음. |

**모바일웹과 하이브리드 앱을 유지함.** 숙소·음식점은 여행기 속 장소로 다루며 예약·결제·숙박비 비교는 제외함.

## 02 / 11 · 1차·2차·3차 프런트엔드 합본

SPOTLOG · DEVELOPMENT SUMMARY · 2

1차·2차·3차의 구현 범위와 완료 기준을 정리함.

| 차수 | 구현 범위 | 완료 후 가능한 일 |
| --- | --- | --- |
| 1차 · 발견·저장 | 검색·사진 넘겨보기·보관함·여행/DAY 선택·담김 상태·해제 | 찾은 장소를 원하는 여행과 DAY에 정확히 넣음. |
| 2차 · 일정·작성·소통 | 임시 저장·복구·사진/글·장소 카드 반응·댓글·지도·복사 | 여행기를 편집하고 본문 속 장소마다 반응·댓글을 남김. |
| 3차 · 추천·안내 | AI 추천·후보 승인·부분 수정·관광 안내·영어 | 추천 초안 수정·관광 안내·영어 열람을 확인함. |

### 차수 진행 기준

- 각 차수 안에서 구조 정리, 기능 구현, 실패 상태 처리, 전체 흐름 검증을 순서대로 진행함.

- 앞 차수의 기록과 상태를 다음 차수에서 재사용함.

1~3차는 프런트엔드 범위임. 실제 로그인·서버 저장·AI/RAG·교통·번역 연동은 이후 백엔드 단계임.

## 03 / 11 · 전체 페이지 구조 · 메뉴와 하위 화면

SPOTLOG · DEVELOPMENT SUMMARY · 3

현재 하단 메뉴를 유지하고, 각 메뉴 안의 화면을 연결하며 필요한 기능을 차수별로 보완함.

| 진입 메뉴 | 하위 페이지와 연결 | 개발 배치 |
| --- | --- | --- |
| 홈 | 추천 일정·여행자 일정 → 여행기 읽기 지역·기간 검색 → 여행기 목록 | 기존 활용 / 1차 탐색 정돈 |
| 여행기 | 검색·지역·기간 목록 → 여행기 읽기 작성자 프로필·다른 여행기 / 복사 → 내 여행 | 1차 검색 / 2차 읽기·복사·카드 반응 |
| 장소 | 안내 목록 · 영상 · 사진 이야기 랜드마크 상세 → 빠른 저장 / 여행·DAY 담기 | 1차 사진 넘김·저장 통일 |
| 내 여행 | 여러 여행 목록 → 읽기·편집·미리보기 DAY·글·사진·업체 카드·지도 / 현장 안내·영어 | 2차 작성·소통 / 3차 안내·영어 |
| 저장 | 지역별 저장·보관함 → 여행·DAY 선택 여행 만들기 → 조건 → 추천 결과 → 편집 | 1차 정리·담기 / 3차 추천 연결 |

**공통 진입:** 프로필은 홈에서 열며 아이콘·등급·내 공개 글·반응·알림 설정을 연결함. AI 관광 안내는 여행 안에서 제공하며 하단 메뉴를 늘리지 않음.

기존 화면을 활용하는 목표 구조임. 새 하위 기능은 1·2·3차에서 보완하며 실제 로그인·동기화·집계·푸시는 후속 서버 단계에서 연결함.

## 04 / 11 · 여행기 화면 구조 · 작성과 독자 이용

SPOTLOG · DEVELOPMENT SUMMARY · 4

한 여행기의 글·사진 사이에 업체와 랜드마크를 넣고, 독자는 해당 항목을 보고 저장하거나 반응함.

| 화면 영역 · 위에서 아래 | 구성 및 독자 동작 | 차수 |
| --- | --- | --- |
| 표지·작성자 | 제목·대표 사진·지역·기간·작성자·등급 작성자 프로필과 다른 여행기로 이동 | 기존 활용 / 2차 정돈 |
| DAY 선택 줄 | DAY 앞 뒤로가기, 가로 DAY 전환 스크롤 중에도 뒤로가기·날짜 선택 유지 | 1차 공통 / 2차 편집 연결 |
| 본문 · 글·사진·장소 카드 | 글·주변 사진·평가 사이에 음식점·호텔·랜드마크 삽입 장소명·설명·방문 정보·저장·여행 담기 제공 | 1차 저장 / 2차 작성 |
| 카드 하단 · 좋아요·댓글 | 카드별 개수 표시 → 하단 팝업 반응한 사용자·댓글 목록·답글 펼침·입력창 | 2차 F19 / 실제 집계 B3 |
| 지도·여행기 하단 | DAY 지도 핀·이동 구간 / 여행기 전체 댓글·작성자 글 공유·내 여행으로 복사, 편집 시 저장·미리보기 | 2차 연결 / 실제 발행 B2·B3 |

**작성자 흐름:** 글·사진 추가 → 장소 선택 또는 직접 입력 → 카드 삽입 → 미리보기. **독자 흐름:** 여행기 읽기 → 카드 저장·반응 → 필요할 때 내 여행으로 복사함.

카드별 댓글과 여행기 전체 댓글은 서로 다른 영역임. 3차의 관광 안내·영어 보기는 이 여행과 DAY를 그대로 사용함. 숙소 예약·결제·가격 비교는 포함하지 않음.

## 05 / 11 · 기능 구조 · 1·2·3차 구현 로드맵

SPOTLOG · DEVELOPMENT SUMMARY · 5

장소·저장·방문·본문을 공통 기반으로 연결하고, 앞 차수의 결과를 다음 차수가 이어서 사용함.

| 차수 · 연결 영역 | 주요 기능 묶음 | 완료 후 이어지는 화면 |
| --- | --- | --- |
| 1차 · 발견·저장 F01–F06 · F20 | 검색·사진 넘겨보기, 빠른 저장·보관함 대상 여행·DAY 선택, 담김·해제·상태 복원 | 장소를 보고 저장한 뒤 원하는 여행의 DAY에 넣음. 선택한 장소·방문 기록을 2차로 전달함. |
| 2차 · 작성·독자 소통 F07–F12 · F19 | 임시 저장·복구, 글·사진·업체 카드·DAY 편집 이동·복사·지도·미리보기, 카드별 좋아요·스레드 | 읽을 만한 여행기를 작성하고 카드별 반응을 시연함. 편집기와 읽기 화면을 3차가 재사용함. |
| 3차 · 추천·현장 안내 F13–F18 | AI 조건·후보 승인·결과·일부 재생성 관광 안내·영어·원문 보기·전체 회귀 검수 | 저장 장소로 초안 생성 → 편집 → 오늘 일정 안내. 샘플 연결부를 이후 실제 서버로 교체함. |

### 공통 기능의 연결 원칙

- 사진·영상·안내는 같은 장소와 저장 상태를 사용함. 여행 방문·본문 카드·댓글 대상은 별도 ID로 구분함.

- 읽기·편집·지도·추천 결과는 같은 여행과 DAY를 참조함. 임시 저장·빈 목록·실패·뒤로가기를 각 차수에서 검증함.

이후 서버: B1 회원·데이터 → B2 콘텐츠·발행 → B3 실제 커뮤니티 → B4 AI·번역 → B5 푸시·현장 앱. 프런트엔드 샘플을 실사용 집계나 실제 AI 결과로 표시하지 않음.

## 06 / 11 · 1차 · 장소 발견부터 정확한 담기까지

SPOTLOG · DEVELOPMENT SUMMARY · 6

구현 목표: 장소를 저장한 뒤 어느 여행의 몇 일차에 들어가는지 명확하게 확인함.

| 구현 항목 | 화면에서 구현할 내용 |
| --- | --- |
| 검색·지역 목록 | 검색·지역 조건에 맞는 목록, 자동 추가 로딩, 빈 결과·오류·이전 목록 복원을 정리함. |
| 저장함·보관함 | 빠른 저장과 이름 있는 보관함을 제공함. 보관함 생성·이름 변경, 장소 이동·복사·메모를 구현함. |
| 여행·DAY 선택 | 담기 창에서 여행 제목과 DAY를 직접 선택함. 여행 기간 입력과 분리하고 없는 DAY는 추가 여부를 확인함. |
| 담김·해제 표시 | 담긴 여행과 DAY를 확인하고 해당 방문만 해제함. 저장 해제와 여행에서 빼기를 구분하며 재방문도 처리함. |
| 기존 기록·예외 | 기존 데이터를 보존하고 여행 없음·중복·저장 실패를 안내함. 긴 스크롤에서도 조작과 뒤로가기를 유지함. |
| 랜드마크 사진 보기 | 장소 메뉴의 ‘사진’ 보기에서 1~5장 사진·짧은 설명을 좌우로 넘기고, 세로로 다음 랜드마크를 봄. 사진 순번·장소명·지역·저장 상태를 표시함. |

**사용 흐름:** 사진을 넘겨 장소 찾기 → 보관함 저장 → ‘부산 여행’ DAY 2 선택 → 담긴 위치 확인 → DAY 2에서만 해제함.

완료 기준: 사진·영상·안내에서 저장 상태가 같고, 여행·DAY·보관함 관계를 보존함. 사진 모션 실험은 별도 관리함.

## 07 / 11 · 2차 · 여행기 작성과 장소 카드별 소통

SPOTLOG · DEVELOPMENT SUMMARY · 7

목표: 글·사진·업체·랜드마크로 여행기를 작성하고, 읽는 사람이 카드별 반응·댓글을 남기는 화면을 완성함.

| 구현 항목 | 화면에서 구현할 내용 |
| --- | --- |
| 자동 임시 저장 | 작성 중 로컬 초안을 자동 저장함. 새로고침·앱 재실행 후 내용과 위치를 복구하고 저장 실패를 알림. |
| 글·사진·장소 편집 | 글·사진·업체·랜드마크 카드 삽입과 순서 변경을 구현함. 사진 여러 장·설명·대표 사진, 오류·미확인 상태를 표시함. |
| DAY 이동·복사 | 장소와 연결된 글·사진을 함께 이동/복제함. 여행 전체·하루·장소 단위 복사와 원문 출처를 보존함. |
| 삭제 복구·지도 | 마지막 변경 취소와 삭제 복구를 제공함. 선택 DAY·본문 장소·지도 핀이 같은 방문을 가리키게 함. |
| 공개 전 미리보기 | 여행기를 읽는 화면으로 확인하고 빠진 사진·장소 정보를 점검함. 원본에 영향을 주지 않는 사본을 만듦. |
| 카드별 반응·댓글 | 본문의 업체·랜드마크마다 좋아요·댓글 수를 표시함. 하단 팝업에서 반응 확인·댓글·답글 작성·수정·삭제를 샘플로 구현함. |

**사용 흐름:** DAY 2 장소에 주변 사진과 평가 작성 → 잠시 종료 → 초안 복구 → DAY 이동 → 지도와 미리보기 확인.

완료 기준: 여행기별 카드 반응을 분리하고 이동 시 유지·복사 시 0건으로 시작함. 실제 발행·저장·집계는 서버 단계이며 3차는 편집기를 재사용함.

## 08 / 11 · 2차 · 여행기 속 장소 카드별 소통

SPOTLOG · DEVELOPMENT SUMMARY · 8

작성자는 여행기 본문에 업체·랜드마크를 넣고, 독자는 각 카드에 좋아요·댓글·답글을 남김.

| 구현 영역 | 화면과 동작 |
| --- | --- |
| 작성·제공 | 저장 장소·검색·직접 입력으로 음식점·호텔·랜드마크 카드를 넣음. 사진·경험·설명과 함께 독자에게 제공함. |
| 카드별 반응 | 각 카드 아래 좋아요 버튼·좋아요 수·댓글 수를 표시함. 좋아요는 누르기/취소, 숫자는 해당 카드의 하단 팝업을 엶. |
| 하단 팝업 | 좋아요 수를 누르면 반응한 사용자 목록, 댓글 수를 누르면 아이콘·이름·시각·본문과 입력창을 보여 줌. 여행기 제목·장소명을 함께 표시함. |
| 댓글·답글 | 댓글별 ‘답글 N개’를 같은 팝업에서 펼침. 답글 대상·취소, 본인 글 수정·삭제, 신고를 제공함. 목록은 나눠 불러오고 키보드 위에서 작성함. |
| 연결·보존 | 여행기 ID + 장소 카드 ID로 스레드를 구분함. 같은 업체라도 다른 여행기의 반응은 섞지 않음. 카드 이동은 유지, 복사본은 새 ID·반응 0건으로 시작함. |

**2차 F19:** 카드 삽입·미리보기·반응·댓글·답글과 실패·로그인 필요 상태를 샘플로 구현함. **이후 B3:** 실제 저장·권한·중복 방지·집계·신고·차단을 연결함.

여행기 전체 댓글·업체 공통 리뷰와 분리함. 좋아요는 카드·계정별 1회, 댓글 수는 공개 댓글·답글 합계임. 닫기·뒤로가기 시 본문 위치·포커스·미전송 초안을 보존함. 샘플 수치는 실제 인기와 구분함.

## 11 / 11 · 우선 결정과 완료 판단

SPOTLOG · DEVELOPMENT SUMMARY · 11

기존 기능을 다시 만들기보다 저장의 정확성, 기록 보존, 여행 정보의 신뢰도를 먼저 확인함.

| 판단 항목 | 통과 조건 |
| --- | --- |
| 저장·편집 | 여행 기간과 대상 DAY가 독립적이며, DAY 이동/복사/삭제 후 글·사진·장소 연결이 유지됨. |
