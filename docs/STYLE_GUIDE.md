# Spotlog 디자인 가이드 — 현재 사이트 전체 화면 기준

기준일: 2026-09-10. **사용자가 좋아한 현재 사이트 전체의 디자인을 기록하고 재사용함. 저장 한 화면을 다른 모든 화면의 기준으로 확대하지 않음.** 홈페이지·여행기·장소 안내·영상·사진·저장·내 여행·상세·편집·프로필·팝업까지 현재 구현을 대조함.

글자 적용 규칙 갱신: **2026-09-13**. §3의 적용 계약은 신규·수정 작업의 기준이며, 나머지 화면별 값은 기존 화면 보존을 위한 현황임. 작은 기존 값이 있다는 이유만으로 새 화면에 같은 크기를 복제하지 않음.

공개 문서: [전체 화면 디자인 가이드](https://giry02.github.io/spotlog/spotlog-design-guide.html). 사용자 요청으로 가이드 문서와 검수용 캡처만 별도 게시함. 기준 화면은 검수한 로컬 구현이며, 미공개 기능은 참고 캡처로만 포함함. 로컬 1차 기능·사진 실험·서비스 화면 변경을 함께 배포한 것은 아님.

2026-09-13 게시 범위: [문서 모음의 디자인·폰트](https://giry02.github.io/spotlog/spotlog-documents.html#typography)에서 전체 디자인과 폰트 기준을 선택함. 작성자 통계18px/12px·관련 여행기16px/11px 보완은 로컬 검수 완료 상태이며, 제품 CSS·역할 별칭·타이포그래피 테스트는 이번 가이드 게시에 포함하지 않음.

이 문서는 디자인 재설계안이 아님. 새 폰트·색상·간격 척도를 도입하지 않고, 화면과 기능의 역할에 따라 이미 다른 값을 그대로 기록함. 같은 높이의 버튼이라도 카드 안 행동과 편집기 행동은 같은 부품이라고 가정하지 않음.

## 1. 승인된 원본과 적용 순서

**현재 화면 전체 → 해당 화면에 최종 적용된 CSS/컴포넌트 → 이 가이드 → 공통 helper** 순으로 판단함. 가이드나 helper가 현재 화면과 다르면 화면을 바꾸지 않고 가이드부터 수정함.

- 전체 기준: 현재 복원된 제품 화면과 실제 동작 상태. 홈과 상세, 목록과 사진 피드의 고유 구조를 모두 보존함.
- 저장의 이력: GitHub `81a1085dfbe6c71f138b57a223d463e249d5432d`의 `Saved`·`SavedPlaceCard` 복원본에서 사용자 요청으로 샘플 링크·샘플 여행 생성만 제거함. 이는 **저장 화면의 출처**이며 홈·편집·사진 피드의 원본을 저장 카드로 바꾸라는 의미가 아님.
- `web/src/styles.css`: 기존 화면 규칙과 마지막 모바일 규칙을 포함한 원본. 같은 선택자의 앞부분 값만 읽지 않고 최종 적용값을 확인함.
- `phase-one.css`, `photo-landmark-feed.css`: 현재 활성화된 팝업·보기 전환·가로 지역 선택·사진 피드의 국소 규칙도 함께 확인함.
- `theme.css`·`ui.tsx`: 기존 역할값을 재사용하는 helper. 전체 제품에 새 기본 크기·폰트·버튼을 덮어쓰는 권한이 없음.
- `App.tsx`: Home·Community·PlaceDiscover·FeedCard·Trips·Saved·SavedPlaceCard·상세·편집·프로필의 현재 구조. `LandmarkGuideCard.tsx`와 `PhotoLandmarkFeed.tsx`는 서로 다른 장소 표현 역할임.
- `SavedPlaces.tsx`·`MyTripsFromSaved.tsx`는 철회한 로컬 시안임. 현재 화면의 원본으로 사용하지 않음.
- `#photo-stories`와 사진 모션은 별도 로컬 실험임. 원형을 기록하되 전 화면 기본값이나 공개 변경 승인으로 취급하지 않음.
- 기존 발표형 보고서·아이콘 비교 페이지는 별도 문서/브랜드 산출물임. 모바일 제품 규격을 강제로 적용하지 않음.

**디자인 가이드 요청은 문서와 개발용 예시만 수정하도록 승인한 것임.** 제품 재스타일링, 화면 통합, 데이터 변경, 기능 개발, 공개 배포는 포함하지 않음.

현재 검색 목록의 가로 넘김은 의도된 영역 내부 스크롤임. 화면 전체에 가로 스크롤을 허용하는 규칙으로 바꾸지 않음. 카드의 높이는 내용에 따라 늘어나며 측정된 높이를 모두 고정값으로 바꾸지 않음.

### 글꼴과 글자 역할

본문 선언은 `'DM Sans', Pretendard, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`임. 기존 제목에 지정한 `'Manrope', sans-serif`를 유지함. Pretendard는 별도 번들로 공급하지 않으므로 실제 한글 글꼴은 기기/외부 폰트 로드 상태에 따라 달라짐. 이를 이유로 새 글꼴을 강제하지 않음.

### 글자 적용 계약 · 2026-09-13

**같은 역할은 같은 규격을 사용함.** 기존 역할이 있으면 해당 컴포넌트와 아래 확정값을 재사용함. 없는 역할은 기본값으로 제안하고 별도 확인 후 추가함. 가이드 정리는 다른 화면의 글꼴·간격을 일괄 변경할 권한이 아님.

| 페이지 제목 | 28px / 750 / 1.25 | 기존 app-header. 프로필 제목 예외는 아래 표에 명시함 |
| 일반 섹션 제목 | 20px / 700 / 1.35 | home-section-heading·section-heading. 글 본문 소제목22px와 구분함 |

#### 예외와 금지 사항

- **11px는 명시된 짧은 메타만 허용함:** 저장 카드 지역·DAY, 작성자 여행기 지역·기간·담김 수, 기존 배지와 사진 출처. 새 통계 라벨·안내문·오류 설명을11px로 줄이지 않음.
- **8~10px는 기존 영문 장식 분류의 국소 예외임.** 의미를 전달해야 하는 한글 정보·버튼·숫자의 신규 규격으로 사용하지 않음. 기존 정보성8~10px는 유지 현황이지 권장값이 아님.
- 홈29px, 추천 커버24px, DAY25px, 장소 카드21px, 저장 카드17px, 기존 카드 소개13px 및 미디어 clamp는 승인된 역할별 예외로 보존함. 20~22px처럼 범위 안에서 임의 선택하지 않음.
- 숫자가0이거나 비활성·선택 상태가 되거나320px로 좁아져도 글자 크기를 낮추지 않음. 먼저 줄바꿈·기존 말줄임·내용에 따른 높이 증가로 처리함. 금액·날짜·오류 핵심 내용은 생략하지 않음.
- 굵기·줄높이·서체도 크기와 함께 확인함. 기본 본문400, 일반 라벨/버튼은 해당 역할600/700을 사용하고 임의의 중간 굵기를 새로 만들지 않음. 기존750/800은 해당 제목·강조 역할에 한정함.
- 폰트 크기를 키웠다고 색상 대비·실제 Android 가독성까지 검증된 것으로 보지 않음. 현재 한글은 대체 서체일 수 있음. 한글 폰트 번들링이나 회색 색상 변경은 별도 시안·승인이 필요함.

#### 구현과 검수

- 값의 기준은 기존 `styles.css :root`임. `--type-stat-value → --type-headline(18px)`, `--type-stat-label → --type-caption(12px)`, `--type-related-title → --type-body(16px)`, `--type-related-meta → --type-micro(11px)`를 사용함. `theme.css`에 다른 기준을 중복 선언하지 않음.
- 신규 작업은 역할명·재사용할 선택자·예외 여부를 먼저 기록함. 해당 역할의 font-size를 화면 CSS에서 임의의 숫자로 재정의하지 않음. 새로운 예외는 이 절·HTML 가이드·검사를 함께 갱신함.
- 로컬 작업본의 `node --test web/tests/typography.test.cjs`로 작성자 통계/관련 여행기 및 기존 핵심 토큰의 회귀를 검사함. 해당 파일과 제품 폰트 수정은 이번 문서 공개본에 포함하지 않으며, 없는 검사 파일을 이미 배포된 것으로 가정하지 않음. 이 검사가 아직 사이트의 모든 옛 선언을 강제하는 것은 아님.
- 화면은320/390/460px에서 실제 표시값·긴 제목·0/일반 수량·선택·빈 목록·팝업을 역할에 맞게 확인함. 글자 때문에 카드의 정렬·사진 폭·패딩이 바뀌지 않았는지 비교함.
- **남은 별도 검수 후보:** 작성자 소개10px, 작성자 여행기 개수9px, 댓글 날짜9px, 반응 수9px, 일부 알림 설명8~9px. 이번 통계 수정과 함께 일괄 변경하지 않으며, 순서대로 승인 후 보완함.

## 5. 입력·하단 팝업·내비게이션

### 입력과 편집

- 검색은 `.destination-search`를 재사용함. 필드 컨테이너 최소51px/R14, 입력14px, 좌우12px, 아이콘gap9px임.
- 일반 편집 입력은 최종16px·높이50px, 텍스트 영역16px/1.75를 기준으로 함. 여행 제목 입력은25px/1.35이고 자체 padding/자동 높이를 가지므로 모든 input을50px로 덮어쓰지 않음.
- 하단 팝업 원래 label은14px, 입력과 gap8px, 다음 필드까지18px임. 현재 `Field`로 구성된 생성 팝업의 라벨은12px/1.5이고 입력/선택은16px이며 실제50px로 표시됨. helper 사용 여부에 따른 현재 차이를 기록하고 임의로 하나로 통일하지 않음.
- 기본 팝업 입력의 최소높이48px, padding12px, R12, 테두리 `#ddddd8`, 흰 바탕을 유지함.
- 파일 선택은 현재 FileUpload의 운영체제 선택기·선택 파일명·오류 표시를 사용함. 백업 파일 저장과 복원은 별도 행동 묶음이며 라벨이 앞 버튼에 붙지 않게 기존 묶음 여백을 재사용함.
- 프로필 이미지 등록은 기존 아바타 오버레이 입력을 유지함. 모든 파일 입력을 큰 사각 업로드 카드로 바꾸지 않음.
- 오류는 해당 입력/행동 근처의 기존 설명 역할과 상태를 사용함. 오류 처리 요청이 없는 가이드 작업에서 검증 기능을 새로 만들지 않음.

### 팝업

`BottomSheet`의 `.phase-sheet`는 최대460px, 최대높이88dvh, 윗모서리24px, 바탕 `#fafaf8`임. 배경막은 `rgba(20,20,18,.38)`, 본문은 내부 스크롤임.

- 헤더: padding24px20px16px, gap12px, 제목 20px/1.4, 설명 14px.
- 본문: padding20px20px, 아래 `max(24px,safe-area)`.
- 닫기: 44×44px 원형.
- 주요 버튼: 팝업 국소 규칙을 적용하며 페이지 기본52px와 다름.
- 현재 새 여행 생성과 장소 삽입은 모두 BottomSheet 안의 `phase-embedded-sheet` 구조임. 바깥 R24/최대 88dvh·본문 좌우 20px를 사용하고 내부는 padding 0/R0/최대높이 제한 없음임. CSS에 남은 독립형 `place-picker` R26/최대 90%나 `sheet-title` 선언을 현재 활성 팝업으로 소개하지 않음.
- 공유는 현재 `shareContent`의 시스템 공유 또는 클립보드 복사와 결과 토스트로 처리함. 별도 앱 공유 시트나 새로운 안내 팝업을 예시로 만들어 넣지 않음.
- 닫기·Esc·뒤로가기·배경 클릭·포커스 복귀는 현재 구현 기준으로 확인함. 키보드/접근성 개선이 필요하면 디자인 문서에서 발견사항으로 분리함.

### 뒤로가기·DAY·고정 행동

- 상세 커버 상단의 기존 버튼은40px 원형이고 상단 영역62px임. 스크롤 후에는 DAY1 앞44px 뒤로가기를 사용함. 추가 고정 제목바로 위 공간을 더 차지하지 않음.
- 상세 DAY 탭은 `sticky top:0`, 좌우18px·세로13px, gap8px, 가로 스크롤임. 일반 DAY 버튼은 최소너비106px·padding10px13px·R13이며 DAY11px/800·날짜13px임. 뒤로가기의44px 원형은 DAY 버튼과 다른 규칙임.
- 편집 상단은 최소62px 고정, 편집 DAY 탭은 그 아래에 붙음. 편집 DAY는 일반38px높이·최소너비76px/R10이며 뒤로가기44px가 별도로 있음.
- 상세/편집 하단 주요 행동은 기존52px/R15/14px를 유지함. 고정 바의 좌우18px·세로11px·안전영역과 아래 내용 가림 방지 여백을 함께 확인함.
- 토스트는 기존 하단91px, 캡슐, padding11px15px, 글자12px, 어두운 반투명 배경임. 긴 문구가 안 맞으면 발견사항으로 기록하며 guide 요청만으로 전체 메시지 디자인을 바꾸지 않음.

## 6. 홈·여행기 검색의 기준

### 홈

브랜드 상단 → 소개 → AI 여행 만들기 → 추천 일정 → 여행자 일정 → 여행기 검색 진입 → 장소/내 여행 바로가기 순서를 유지함. 검색 진입 버튼을 다시 상단으로 올리거나 소개를 새 KPI 영역으로 바꾸지 않음.

- `.home-topbar`: 최소91px, 위18px·아래14px, 로고22px/800/1, 프로필42px 원형.

## 7. 장소 발견 — 안내·영상·사진

### 지역 안내

### 영상

한 화면 미디어를 배경으로 작성자/설명/장소 정보와 오른쪽 행동을 겹침. 일반 페이지의 padding 18px를 미디어 전체에 넣지 않음.

### 사진

현재 사진 피드는 영상과 같은 전체 화면 탐색 구조이며, 장소 세로/사진 가로 넘김을 분리함. 사진 카드 목록 형태나 지역 선택을 먼저 강제하는 구조로 되돌리지 않음.

- 설명 묶음: 왼쪽 20px·오른쪽 82px·아래 80px + 안전 영역.
- 사진 위 제목 26~31px·설명 15px/1.7·지역 12px·장소 이야기 13px.
- 장소/사진 수는 기존 반투명 캡슐. 사진 점의 실제 터치 버튼 44px와 작은 시각 점을 구분함.
- 저장/공유 46px 원형, 장소 이야기 클릭 시 기존 BottomSheet.
- 이야기 본문 16px/1.8, 메모 15px/1.8, 주소표 14px, 설명/주의문과 저장 행동을 유지함.

1. 전체 화면 목록에서 가장 가까운 역할을 찾고 해당 현재 화면을 직접 확인함.
2. 사용할 원본 컴포넌트/선택자를 명시함. 저장 가로 카드·탐색 세로 카드·상세 장소 카드를 구분함.
3. 최종 CSS와 실제 상태를 확인함. 오래된 가이드 숫자나 helper 기본값을 앞세우지 않음.
4. 기존 역할로 충분하면 그 규칙을 재사용함. 없는 시각 유형은 이유·시안·예상 화면을 별도로 제안하고 승인받음.
5. 제품 수정 범위와 가이드 갱신 범위를 구분함. 가이드 요청만으로 styles.css나 폰트·구조를 변경하지 않음.
6. 같은 데이터와 조건에서 수정 전후 320/390/460px를 비교함. 목록 첫 화면뿐 아니라 스크롤 하단·팝업·빈 상태·선택·오류를 포함함.
7. 사용자의 기존 데이터와 무관한 로컬 작업을 보존함. 실사용 localStorage를 초기화하지 않음.
8. 새 기준을 추가할 때 원본 화면·선택자·상태·검증 근거를 함께 문서화함. 승인 없는 커밋·푸시·배포를 하지 않음.
