# 모아 — Spotlog 챗봇 모바일 체험

Spotlog의 챗봇 하위 프로젝트입니다. 장소를 찾는 첫 질문부터 식당·카페·숙소·DAY별 일정·내 여행 저장까지 이어집니다. 질문과 카드 조작은 같은 상태를 바꾸고 새 응답을 아래에 추가합니다. 이전 응답은 당시 결과를 보존합니다. 실제 Jev·LLM 호출은 없습니다.

## 접속

- [누구나 볼 수 있는 공개 체험](https://moa-adaptive-mobile-demo.companydasom.chatgpt.site)
- [모아만 보관하는 GitHub 브랜치](https://github.com/giry02/spotlog/tree/codex/moa-demo)
- PC에서는 휴대폰 프레임, 휴대폰에서는 전체 화면을 사용합니다. 헤더·입력창을 고정하고 대화 영역만 스크롤합니다.
- 집 와이파이 시연: PowerShell에서 `$env:MOA_DEV_HOST = '0.0.0.0'` 설정 후 `npm run dev`. 표시되는 Wi-Fi Network 주소로 접속합니다. 기본 실행은 localhost만 사용합니다.

## 여섯 가지 시나리오

| 시작                    | 이어지는 체험                                                         |
| ----------------------- | --------------------------------------------------------------------- |
| 장소부터 하나씩         | 제주 바다 장소 찾기 → 장소 선택 → 식당 선택 → 숙소 비교 → 일정 만들기 |
| 이런 분위기의 다른 곳   | 오설록을 기준으로 비슷한 분위기 찾기 → 장소 찜 → 주변 식당·카페       |
| 일정부터 한 번에        | 제주 1박 2일 완성 초안 → DAY 선택 → 식당 하나만 교체 → 저장           |
| 숙소는 이미 예약했어요  | 예약 숙소 구간을 고정한 초안 → 방문·식사 수정 → 예약 유지 확인        |
| 서울숲에서 반나절       | 서울숲 → 점심 → 카페 → 방문 순서                                      |
| 찜한 장소로 여행 만들기 | 샘플 찜 두 곳 추가 → 같은 지역의 장소로 DAY 구성 → 내 여행 저장       |

헤더의 시나리오 메뉴에서 새 대화를 시작할 수 있습니다. 새 시나리오에서도 찜과 저장한 여행은 유지합니다. 북마크 버튼으로 찜한 장소·내 여행을 열 수 있습니다. 모니터 비교는 현재 화면과 진입점에서 제외했고 이전 구현 파일만 보관합니다.

오른쪽 상단의 회전 화살표 **대화 초기화**를 누르면 대화 이력·현재 조건·진행 중 일정·입력 문장을 지우고 시작 화면으로 돌아갑니다. 찜한 장소와 내 여행에 저장한 일정은 유지됩니다. 초기화 상태도 이 브라우저에 저장되어 새로고침 후 이전 대화가 돌아오지 않습니다. 새 질문이나 시나리오를 시작하면 초기화 안내가 사라집니다.

## Spotlog 기능과 연결

Spotlog 원본 기능 흐름을 참고해 모아 안에 별도로 구현했습니다. Spotlog 본체·계정 데이터·배포 브랜치는 수정하지 않았습니다.

- 장소 발견·찜: `SavedPlaces.tsx`, `SavedLandmarkDetailSheet.tsx`의 장소 ID 기반 흐름.
- 찜한 장소로 일정 만들기: `savedTripBuilder.ts`, `MyTripsFromSaved.tsx`의 지역·DAY 배치.
- 완성 일정부터 생성: `AI_COMPLETE_ITINERARY_RESULTS_20260920.md`의 방문 → 점심 → 오후 → 저녁 → 숙박 구조, 예약 숙소 보존, 식사·숙박 제외 요청.
- 주변 업체 선택·교체: `NearbyBusinessSheet.tsx`의 DAY·기준 장소·식사 자리 문맥.
- 내 여행과 방문 순서: `PersonalTrip.tsx`의 개인 일정과 여행기 구분. 이번 모아에는 실제 여행기 게시·계정·댓글 기능을 연결하지 않았습니다.

식당을 선택하면 선택 결과와 다음 행동을 먼저 보여줍니다. 숙소를 선택하면 앞서 고른 장소·식당·숙소를 묶어 일정으로 연결합니다. 일정 수정은 방문 ID를 지정해 해당 자리만 바꾸며, 다른 DAY와 예약 숙소는 유지합니다. DAY 전환 시 해당 날짜의 기준 장소가 주변 탐색에 전달됩니다. 카페·식당은 선택한 DAY에 추가할 수 있습니다.

## 데이터와 저장 범위

식당·카페 12곳과 숙소 5곳에는 상세정보가 있습니다. 후보의 사진·분위기 요약을 눌러 메뉴별 가격, 객실 구성, 시설, 운영시간 예시, 선택 전에 살펴볼 점과 현재 여행에 맞는 이유를 확인합니다. 상세 화면에서 선택하면 새 대화가 이어지며, 일정에서도 상세정보를 열고 해당 자리의 다른 후보를 찾을 수 있습니다. 상세정보를 열거나 닫는 것만으로 여행 선택은 바뀌지 않습니다.

- 장소: 제주·서울 네 곳과 기존 이용허락 사진. 지역·분위기 검색 결과는 체험 규칙으로 정합니다.
- 식당·카페·숙소·메뉴·요금·도보 시간: **가상 예시**. 실시간 영업·객실·예약 가능 여부를 제공하지 않습니다.
- 일정: 당일부터 최대 3일. 다른 지역을 한 일정에 섞지 않고, 후보 부족은 미정/빈 날로 표시합니다.
- 방문 순서: 일정과 같은 방문 목록을 보여주는 도식입니다. 실제 지도·경로·이동시간을 계산하지 않습니다.
- 길찾기: “여기 길찾기 해줘” 또는 다음 방문 카드로 외부 지도를 엽니다. 실제 랜드마크의 이름·주소를 Google Maps 목적지로 전달하고, 카카오·네이버 장소 검색 링크도 제공합니다. 사용자가 지도에서 출발지·교통수단·도착점을 확인합니다. 가상 업체와 위치 미입력 예약 숙소에는 길찾기 URL을 만들지 않습니다. 기준 랜드마크로 이동하는 것은 별도 버튼으로 표시합니다.
- 실제 주변 검색: “실제 식당 찾아줘”로 현재 기준 랜드마크의 식당·카페·숙소 검색을 카카오지도에서 엽니다. API 결과를 수집하거나 AI 입력·내부 DB에 저장하지 않으며, 검색 결과를 일정에 자동으로 추가하지 않습니다.
- 여행 진행: “다녀왔어”, “이번엔 건너뛸래”, “다음 어디 가?”가 방문 ID별 완료·건너뜀·다음 방문 카드로 이어집니다. 다음 DAY도 이어서 확인하며 기록에서 미방문으로 되돌릴 수 있습니다. 같은 장소가 여러 날짜에 있으면 개별 방문 버튼으로 고릅니다. 선택한 장소·예약 구간·과거 응답·저장본은 보존합니다. 내 여행 저장본 갱신은 명시적으로 다시 저장합니다.
- 대화·찜·내 여행: 이 브라우저의 `moa.spotlog.travel.v1` 저장소에 보관합니다. 실제 Spotlog 서버와 동기화하지 않습니다. 저장 불가 시 화면에 알립니다. 입력된 실제 개인정보를 요구하지 않습니다.
- `이 결과에서 이어가기`: 과거 조건으로 새 응답을 추가합니다. 그 사이의 대화와 현재 찜 목록은 지우지 않습니다.
- 일반 자연어 전체를 이해하는 모델은 연결하지 않았습니다. 화면의 다음 질문·카드와 지원 표현을 사용합니다.

## 구현과 검증

- `app/page.tsx`: 여행 체험 진입점.
- `components/trip-workspace.tsx`, `components/trip-workspace.css`: 모바일 시작 화면, 기능 카드, 대화, DAY 편집, 이 기기의 보관함.
- `lib/trip-data.ts`: 시나리오·가상 숙소·기존 장소와 식당 데이터 재사용.
- `lib/business-details.ts`, `components/business-detail.tsx`: 가상 업체 프로필, 같은 업체 ID의 메뉴·가격, DAY·기준 장소를 반영한 설명과 모바일 상세 화면.
- `lib/trip-engine.ts`: 검색 조건, 선택 ID, 일정 생성, 방문 하나의 교체/추가/순서 변경, 예약 보존, 독립된 응답 기록과 저장본.
- `lib/travel-links.ts`: 실제 랜드마크 지도 URL, 기준 장소의 외부 업체 검색, 가상 업체·위치 미입력 숙소의 길찾기 차단.
- `tests/trip-engine.test.mjs`: 장소→식당→숙소 연결, 즉시 일정 생성, 부분 수정, 예약 숙소, 찜 지역 제한, 제외 조건, 빈 결과 복구, 저장본 불변성, 과거 응답 복원, DAY 연결 검증.

Node 22.13 이상에서 `npm ci`, `npm run dev`. 테스트는 Node 26에서 확인합니다.

```sh
node --test tests/trip-engine.test.mjs
npx tsc --noEmit
npm run build
```

실제 연결 단계에서는 Jev의 기능 유닛 선택, 검색 결과 확정, LLM의 설명을 분리합니다. 선택한 장소·방문·DAY와 검색 결과를 먼저 확정하고 카드·설명이 같은 결과를 사용해야 합니다. 체험 성능을 실제 Jev 성능으로 주장하지 않습니다.

## Flowise로 실제 챗봇 연결하기

2026-10-02 공식 문서와 Spotlog의 기존 Flowise 실행안을 확인했습니다. **Flowise를 대화·검색·도구 실행 서버로 쓰고, 모아의 모바일 화면을 유지하는 구성이 가능합니다.** 기존 실행안에는 Mac mini에서 Flowise와 외부 모델 공급자를 운영한다고 기록돼 있지만 실제 주소·설치 버전·flow ID·인증·접속 가능 여부는 이번에 확인하지 않았습니다. 현재 체험판과 Mac mini를 연결하거나 설정을 변경한 것은 아닙니다.

구성: 모아의 질문과 현재 여행 문맥 → Spotlog 서버 → Flowise Prediction API → 허용된 검색·일정 도구 → 서버에서 결과 검증 → 설명과 기능 카드를 새 대화로 추가.

| 요청                         | Flowise가 호출할 기능                             | 모아가 보여줄 결과                   |
| ---------------------------- | ------------------------------------------------- | ------------------------------------ |
| 이 장소와 분위기가 비슷한 곳 | 허가된 장소 데이터 검색, 선택적으로 Jev 검색 도구 | 같은 장소 ID를 쓰는 후보 카드와 설명 |
| 그 근처 카페, 메뉴도 보여줘  | 기준 장소·DAY를 전달한 업체 검색과 상세 조회      | 카페 후보·메뉴 상세 카드             |
| DAY 2 점심만 바꿔줘          | 방문 ID를 지정한 후보 검색·변경 제안              | 해당 식사 자리의 후보와 변경 결과    |
| 여기 길찾기 해줘             | 확인된 실제 장소의 지도 링크 생성                 | 목적지 카드·외부 지도 버튼           |
| 다녀왔어, 다음 어디 가?      | 방문 상태 변경과 다음 미방문 조회                 | 진행 카드·다음 방문·길찾기           |
| 주차나 이용 규정 알려줘      | 허가된 FAQ/RAG 검색 (추가 데이터 연결 필요)       | 근거가 있는 안내와 출처 카드         |

Flowise의 [Prediction API](https://docs.flowiseai.com/using-flowise/prediction)는 `POST /api/v1/prediction/:id`, 대화 기록, session ID 및 스트리밍을 지원합니다. [Agentflow V2](https://docs.flowiseai.com/using-flowise/agentflowv2)는 도구·문서 검색·JSON Structured Output을 제공하며, [Custom Tool](https://docs.flowiseai.com/integrations/langchain/tools/custom-tool)에 검색·상세 조회·일정 기능을 연결할 수 있습니다. 실제 설치 버전과 모델의 지원 여부는 연결 전에 확인해야 합니다.

연결 시 사용할 응답 형식의 예시 (현재 API 구현이 아니라 설계):

```json
{
  "sourceTurnId": 12,
  "message": "협재해변으로 가는 길을 지도에서 확인해보세요.",
  "units": [{ "type": "directions", "placeId": "hyeopjae" }]
}
```

Flowise가 임의의 HTML·좌표·외부 링크를 생성해서 화면에 넣는 방식은 사용하지 않습니다. 서버가 허용한 카드 종류와 실제 데이터 ID만 통과시키고, 프론트는 지금의 카드 컴포넌트로 렌더링합니다. 문맥에는 서버가 발급한 session/request ID, 현재 응답 버전, DAY·기준 장소·방문 ID를 전달합니다. 변경 요청은 최신 버전·사용자 권한·예약 고정 여부를 검증하고 결과를 반영합니다. 인증키는 서버에만 두고 runtime override는 필요한 문맥 변수만 허용합니다. Jev는 실제 제공 API와 역할을 확인한 뒤 검색·유닛 선택 도구로 추가할 수 있으며 Flowise 사용만으로 Jev 연동이나 자동 화면 구성이 완성되는 것은 아닙니다.

지도 링크 형식은 [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started), [Kakao 지도 URL 가이드](https://apis.map.kakao.com/web/guide/#routeurl)를 참고했습니다. 경로 API·실시간 교통 조회를 직접 연결한 것은 아닙니다.

## 이전 구현

`connected-workspace`, `connected-engine`, `conversation-session`은 이전 장소·제품 비교 구현을 보관한 코드이며 현재 루트에서 불러오지 않습니다. 이전 여행 데모 `/travel`과 그 전용 `lib/jev.ts`, `/api/compose`도 별도로 보존합니다. `JEV_API_KEY`를 설정해도 현재 루트 여행 체험에는 실제 AI가 연결되지 않습니다.

## 디자인과 사진
