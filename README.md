# Spotlog Hybrid

Spotlog는 국내 랜드마크 영상을 발견의 입구로 사용하고, 사용자가 다녀온 여러 여행을 날짜별 동선과 장소 이야기로 남겨 공유하는 모바일 우선 여행일기 서비스입니다.

상용화 이후의 기능 우선순위와 구현 원칙은 [`FUTURE_ROADMAP.md`](./FUTURE_ROADMAP.md)에 정리되어 있습니다.

## 대화 복구·인수인계

[복구 문서 목차](./docs/handoff/README.md)에 현재 구현 상태, 작업 이력, 공개 금지인 로컬 실험과 계획서 전체 MD를 보존했습니다. 새 작업에서는 이 문서부터 확인합니다. 과거 로드맵보다 **1·2·3차 프런트엔드 우선 → 이후 백엔드**라는 최신 결정을 우선합니다.

## 현재 구조

Spotlog의 본체는 모바일웹이고 Expo 앱은 네이티브 기능이 필요할 때만 개입하는 하이브리드 셸입니다.

| 영역 | 담당 |
|---|---|
| `web/` | 추천 홈, 공개 여행기 검색, 영상·지역 안내형 랜드마크 발견, 다중 여행, 날짜별 지도·동선, 장소 공유 등 모바일웹 UI |
| `src/hybrid/HybridShell.tsx` | 모바일웹 로딩, 연결 오류 처리, 웹 메시지 수신 |
| `shared/hybridBridge.ts` | 웹과 앱이 주고받는 메시지 계약 |
| Expo 네이티브 | OS 공유 시트와 향후 카메라·위치·알림·딥링크 |

웹 브라우저에서는 웹 공유 API 또는 클립보드로 동작합니다. 같은 웹을 Expo WebView에서 열면 공유 요청이 브리지를 거쳐 Android·iOS 네이티브 공유 시트를 호출합니다.

이전 React Native 전용 화면은 `src/screens/` 등에 프로토타입 참고용으로 남아 있지만 현재 `App.tsx` 진입점에서는 사용하지 않습니다.

## 실행

처음 한 번 의존성을 설치합니다.

```bash
npm install
```

기본 실행은 모바일웹입니다. 다음 명령을 실행하면 개발 서버를 시작하고 브라우저를 엽니다.

```bash
npm start
```

브라우저에서는 `http://localhost:5173`으로 확인할 수 있습니다.

브라우저를 자동으로 열지 않으려면 `npm run web`을 사용합니다.

터미널 2에서 Expo 앱을 실행합니다.

```bash
npm run android
# 또는 macOS에서
npm run ios
```

Expo 개발 서버만 먼저 열고 싶다면 `npm run app`을 사용합니다.

Android 에뮬레이터는 기본적으로 `http://10.0.2.2:5173`, iOS 시뮬레이터는 `http://localhost:5173`을 불러옵니다. 실제 휴대폰에서는 컴퓨터와 같은 Wi-Fi에 연결한 뒤 컴퓨터의 LAN 주소를 지정합니다.

```powershell
$env:EXPO_PUBLIC_SPOTLOG_WEB_URL='http://192.168.0.10:5173'
npm run android
```

운영 빌드에서는 배포된 HTTPS 모바일웹 주소를 `EXPO_PUBLIC_SPOTLOG_WEB_URL`로 지정합니다.

## Android 설치 파일

휴대폰에 직접 설치할 APK는 EAS의 `preview` 프로필로 빌드합니다. 이 프로필은 개발 서버가 아니라 배포된 `https://giry02.github.io/spotlog/` 모바일웹을 불러오므로 별도 PC 서버 없이 실행됩니다.

```bash
npx eas-cli@latest login
npm run android:apk
```

빌드가 끝나면 EAS가 제공하는 APK 주소를 Android 휴대폰에서 열어 설치합니다. Play 스토어 등록용 AAB는 `npm run android:aab`로 별도 생성합니다.

현재 여행기 편집·복사와 댓글·응원·프로필 아이콘은 브라우저 `localStorage`에서 실제 동작합니다. 선택한 사진은 모바일 크기로 축소해 데모 데이터에 함께 저장합니다. 여러 사용자의 담김 수와 댓글을 실시간으로 공유하려면 운영 단계에서 회원·여행·댓글·응원 API와 데이터베이스로 같은 상태 계약을 교체해야 합니다. 배경 지도와 마커·경로선 표시는 MapLibre와 OpenStreetMap 타일을 사용합니다. 좌표가 있는 장소는 OSRM 공개 데모 서버에서 도로 경로와 예상 이동시간·거리를 받아오며, 실패하면 직선거리 기반 예상치로 자동 전환합니다. 이 값은 실시간 교통을 반영하지 않으므로 정확한 출발 시점의 소요시간은 외부 길찾기에서 다시 확인해야 합니다. 운영 단계에서는 지도·검색·경로 공급자를 다시 결정하고 제품용 API를 서버에서 연결해야 하며, 여러 장의 원본 사진을 위한 오브젝트 스토리지 업로드와 회원 서버 동기화도 추가해야 합니다. 현재 개별 장소 길찾기는 키가 필요 없는 카카오맵 외부 링크를 임시로 엽니다.

현재 `AI 여행 만들기`는 API 키를 모바일웹에 노출하지 않는 제품 데모입니다. 기기 안에서 실제 저장 장소의 거리와 체류시간을 기준으로 편집 가능한 초안을 생성합니다. 사용자 요청으로 샘플 링크와 샘플 생성 경로를 제거했으며, 저장 장소가 없으면 먼저 장소를 저장하도록 안내합니다. 운영 단계에서 생성형 AI를 연결할 때는 같은 입력·출력 계약을 유지하고 서버 API에서 사용자 취향과 계절, 운영시간을 반영하도록 확장합니다.

### 조회수 목표 푸시

웹 프로필의 푸시 설정은 `localStorage`에, Expo 앱에서 확인한 실제 알림 권한은 네이티브 저장소에 보관합니다. 앱에서는 `expo-notifications`로 권한을 요청하고 Android 알림 채널을 만들며, `테스트 푸시 받기`로 즉시 로컬 알림을 확인할 수 있습니다. Android의 원격 푸시는 Expo Go가 아니라 개발 빌드 또는 배포 앱에서 검증해야 합니다.

운영 서버는 다음 순서로 연결합니다.

1. 공개 여행기 조회 API에서 유효 조회수를 원자적으로 증가시킵니다.
2. 사용자가 선택한 목표값을 처음 통과했을 때 `(journeyId, milestone)` 고유 이벤트를 한 번만 기록합니다.
3. 알림을 켠 작성자의 Expo 푸시 토큰으로 `CREATOR_VIEW_MILESTONE` 메시지를 발송합니다.
4. 동일 목표 재발송을 막고, 다음 목표를 선택하면 새 목표부터 다시 감시합니다.

현재 로컬 화면의 조회수와 테스트 알림은 이 서버 연결 전 UI·브리지 검증용입니다. 실제 사용자 간 조회수 집계와 앱이 종료된 상태의 원격 발송에는 회원 ID, 여행기 ID, 푸시 토큰, 목표 달성 이벤트를 저장하는 서버와 데이터베이스가 필요합니다.

현재 피드 영상은 UI 검증을 위한 Cloudinary 공개 데모 자산입니다. 운영 전에는 Spotlog 콘텐츠 저장소와 스트리밍 CDN URL로 교체해야 하며, 장소 데이터의 `video` 필드만 바꾸면 됩니다.

## 프로젝트 원칙

- 모바일웹이 서비스 UI와 비즈니스 흐름의 기본 실행 환경입니다.
- Expo 앱은 기기 권한과 OS 기능이 필요한 경계만 담당합니다.
- HotelNGo와 회원·저장소·런타임을 공유하지 않습니다.
- PMS 또는 HotelNGo를 직접 참조하지 않습니다.
- 가격·재고·예약·정산은 Spotlog 1차 범위가 아닙니다.
- 숙소와 업체는 가격·예약 상품이 아니라 여행일기 속 공유 가능한 장소로 다룹니다.
- 공개 여행기 복사는 원본을 수정하지 않고 출처를 보존한 새 비공개 초안을 만듭니다.
- 향후 예약 연결이 필요해질 때만 독립 API 어댑터로 HotelNGo를 선택 연동합니다.
