# 모아 — Spotlog 챗봇 모바일 체험

Spotlog의 챗봇 하위 프로젝트입니다. Spotlog 디자인을 적용한 모바일 대화형 기능 연결 체험판입니다. 질문 또는 카드 조작마다 사용자 메시지와 새 응답·기능 카드가 아래에 누적됩니다. 이전 응답은 당시 결과 그대로 남습니다. 사용자의 말과 버튼 조작이 같은 선택·필터 상태를 변경하고, 독립된 유닛들이 그 상태와 검색 결과를 입력으로 사용합니다. 실제 Jev·LLM 호출은 없습니다.

## 접속과 모바일 시연

- 공개 체험: https://moa-adaptive-mobile-demo.companydasom.chatgpt.site
- 이 체험판의 소스만 보관하는 GitHub 브랜치: https://github.com/giry02/spotlog/tree/codex/moa-demo
- PC에서는 휴대폰 프레임, 휴대폰에서는 화면 전체를 사용합니다. 헤더와 입력창은 유지되고 대화 영역만 스크롤됩니다. 다음 질문 칩은 가로로 넘길 수 있습니다.
- 화면 높이·안전 영역과 키보드에 따른 표시 영역 변화를 반영합니다. 실제 기기·브라우저마다 키보드 동작은 다를 수 있습니다.
- 집 와이파이에서 로컬 시연하려면 PowerShell에서 `$env:MOA_DEV_HOST = '0.0.0.0'` 설정 후 `npm run dev`를 실행하고, 터미널에 표시되는 Wi-Fi Network 주소로 접속합니다. 기본 실행은 localhost만 사용합니다.

## 실행과 확인

- Node 22.13 이상, `npm ci`, `npm run dev`
- 테스트는 Node 26에서 확인: `node --test tests/conversation-session.test.mjs tests/connected-workspace.test.mjs tests/unit-engine.test.mjs`
- `npx tsc --noEmit`, `npm run build`

## 체험 경로

장소 발견: `두 번째 장소 근처 맛집은?` → 도보 5분 → 지도 핀 선택 → 메뉴·이동 정보 확인 → 다른 장소 선택. 식당 목록과 지도는 하나의 검색 결과를 공유합니다. 선택 장소가 바뀌어도 도보·음식 조건은 유지되고, 이전 식당 선택은 해제됩니다.

모니터 비교: `게임도 하고 눈이 편했으면 좋겠어` → `30만원 이하로 보여줘` → 제품을 비교에 추가 → 선택 제품을 새 기준으로. 검색 순서와 비교 항목이 조건에 따라 달라집니다. 비교 중인 제품은 예산을 넘겨도 유지하고 예산 초과를 표시합니다. 기준 제품과 후보 2개까지 비교하며 비교표에서 해제할 수 있습니다.

두 탭은 각자의 대화와 상태를 유지합니다. 최신 응답의 카드만 조작할 수 있으며, 과거 응답의 `이 결과에서 이어가기`는 그 기준·선택·조건으로 새 대화를 추가합니다. 그 사이 대화는 지우지 않습니다. 슬라이더는 조작 완료 시 대화 한 건을 추가합니다. 새 대화 시작 위치로 이동하며, 모션 감소 설정을 존중합니다. `최근 대화`로 돌아갈 수도 있습니다. 마지막 대화 취소, 처음부터, 기준 바꾸기, 연결 보기, 질문 이력을 제공합니다. 모든 상태는 현재 페이지 메모리에만 저장되어 새로고침하면 초기화됩니다.

## 기능 구성

- `lib/connected-data.ts`: 장소·식당·모니터의 타입과 샘플 데이터. 실제 장소 사진 외 분위기 점수·식당·메뉴·가격·도보 시간·모니터 제품과 스펙은 체험용입니다.
- `lib/connected-engine.ts`: 공유 상태, 자연어 규칙, 검색, 유닛 등록과 입력·출력 연결, 설명 문장. 같은 reducer가 대화·카드·필터를 처리합니다. 순서는 현재 표시된 결과에서 해석하고, 선택 대상이 없거나 결과가 없으면 이를 명시합니다.
- `components/connected-workspace.tsx`: 장소 후보, 분위기 비교, 식당 목록, 상대 위치 지도, 이동·메뉴, 제품 목록, 제품 비교표, 예산·조건의 8개 유닛. 필요한 유닛만 조합하며 작업에 따라 순서와 상세·요약 표현을 바꿉니다.
- `lib/conversation-session.ts`: 응답별 상태 보존, 대화 누적, 과거 결과로 이어가기, 마지막 대화 취소. 응답마다 고유 번호를 사용하고 이전 상태 객체를 변경하지 않습니다.
- `tests/conversation-session.test.mjs`: 연속 대화의 과거 결과 불변성, 조건 복원, 취소, 탭 독립성 검증.
- `tests/connected-workspace.test.mjs`: 참조 연결, 목록·지도 결과 공유, 필터 유지, 선택 해제, 비교 한도, 금액 파싱, 빈 결과 복구 검증.

이번 단계는 기능 유닛의 연결을 검증합니다. 자유로운 자연어 전체를 이해하지 않으며, 지원하지 않는 입력에는 체험 모드의 한계를 표시합니다. 지도는 도보 시간과 가상 각도를 그린 상대 위치 도식으로 실제 지리·길찾기 기능이 아닙니다. 예약·구매·결제는 실행하지 않습니다.

다음 실제 연동 단계에서는 Jev의 유닛 판단, 데이터 검색, LLM 설명을 분리합니다. 검색 결과와 선택 ID를 먼저 확정하고, 모든 유닛과 설명이 그 결과를 공유하도록 해야 합니다. 현재 연결 체험의 `workspace`는 `decisionMode: demo`, `narrationMode: sample`을 반환합니다. Jev 키를 설정해도 루트 체험에 실제 AI가 연결되지는 않습니다. 성능·비용 개선 수치는 측정하지 않았습니다.

## 이전 여행 체험

이전 여행 유닛 데모는 `/travel`에 보존했습니다. `lib/unit-engine.ts`, `lib/jev.ts`, `app/api/compose/route.ts`는 이전 체험 전용입니다. 서버 `JEV_API_KEY` 설정 시 사용하는 기존 Jev 어댑터는 루트의 새 연결 체험과 별개이며, 실제 호출·한국어 판단 품질은 검증하지 않았습니다. 비밀 값은 서버 환경 또는 무시된 `.dev.vars`에만 둡니다.
