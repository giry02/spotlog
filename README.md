# 모아 — Spotlog 여행 챗봇

Spotlog 앱 안에서 사용할 여행 챗봇의 모바일 웹 구현입니다. 질문을 해석한 모델이 허용된 기능을 선택하면, 서버가 검증한 결과를 장소·업체·코스·지도·일정·스레드 카드로 표시합니다. 질문과 결과는 아래로 이어지고, 상세 조회는 현재 화면 위의 바텀시트에서 열립니다.

이 브랜치는 **모아 챗봇만 보관하는 codex/moa-demo**입니다. Spotlog 앱 본체는 별도 브랜치에서 관리합니다. GitHub 업로드와 공개 사이트 배포는 별개이며, 이 소스의 모든 기능이 이전 공개 체험 사이트에 배포됐다는 의미는 아닙니다.

## 실행

Node.js 24 이상을 권장합니다. 별도 AI 설정 없이 먼저 데모 기능을 실행할 수 있습니다.

```sh
npm ci
npm run dev -- --port 3001
```

브라우저에서 <http://localhost:3001/>에 접속합니다. PC는 휴대폰 프레임, 모바일은 화면 전체를 사용합니다. 이 기기의 찜·저장 여행·댓글은 브라우저에 보관됩니다.

이미 Ollama·Flowise·RAG를 구성한 Windows PC에서는 **Spotlog 시작.vbs** 또는 **npm run local:start**로 설치된 서비스를 숨김 실행하고 정상 서비스는 재사용합니다. 새 PC의 서비스 설치·모델 다운로드·키 설정은 별도로 필요합니다. [로컬 실행 안내](docs/LOCAL_START.md), [Flowise 런타임](scripts/flowise/README.md), [RAG 런타임](scripts/rag/README.md)을 참고하세요.

집 와이파이의 휴대폰에서 보려면 PowerShell에서 다음과 같이 실행하고, 출력된 Network 주소를 같은 와이파이의 휴대폰에서 엽니다.

```powershell
$env:MOA_DEV_HOST = '0.0.0.0'
npm run dev -- --port 3001
```

## 체험 기능

| 흐름 | 화면과 조작 |
| --- | --- |
| 장소부터 여행 만들기 | 장소 검색·비슷한 분위기·사진 발견 → 여러 장소 담기 → 주변 식당·카페·숙소 추가 |
| 다른 여행자의 코스 | 공개 코스 검색·필터 → 작성자 소개 → 장소별 상세 펼치기 → 내 여행으로 가져오기 |
| 제주 실제 장소 11곳 | 협재·금능·오설록·송악산·새별오름 + 실제 식당 3곳·카페 2곳·숙소 1곳의 주소와 개별 좌표 |
| 전체 동선 | 모든 DAY의 방문과 전날 숙소 출발을 한 지도에 표시, DAY별 보기, 방문 카드 이동 |
| 일정 편집 | 제목·날짜·방문 시간·메모·체류시간·방문 순서·DAY 추가/복사/삭제·숙박일/연박 편집 |
| 저장과 다시 열기 | 개인 여행 저장·작성 완료·저장본 열기·휴지통/복원·오프라인 사본·경로 공유 |
| 평가와 스레드 | 장소 좋아요·코스 3가지 평가·스레드/답글·내 글 수정/삭제/복원·담김 수 |
| 앱 연결 | 연결한 Spotlog 앱의 여행/DAY·글·사진·초안·댓글/응원 등 목적 화면으로 이어가기 |
| 여행 안내 | 근거를 확인한 RAG 답변, 지원 지역의 날씨, 예산·일정 점검·외부 지도 길찾기 |

상단은 **처음으로 · 대화 이력 · 저장한 여행 · 여행 시나리오** 한 줄 메뉴입니다. 대화 초기화 후에도 찜·저장 여행·소셜 기록은 유지됩니다. 모니터 비교는 현재 체험 화면에서 제외했습니다.

바로 해볼 질문:

- 제주 바다 볼 만한 곳 찾아줘
- 협재 근처 식당 찾아줘
- 제주 서쪽 실제 장소 11곳 코스 보여줘
- DAY 2 일정 보여줘 / DAY 1 점심 바꿔줘
- 협재신국수 스레드 보여줘
- 제주 서쪽 실제 장소 11곳 평가랑 담김 보여줘

카드의 상세·작성자·스레드를 여는 조회는 새 대화를 추가하지 않습니다. 일정을 바꾸거나 질문을 보내면 새 결과가 대화 아래에 이어집니다.

### 샘플 커뮤니티

다른 사람의 글·답글·평가·담김 수는 **샘플**로 구분해 기본 표시합니다. 장소·업체 전체, 공개 코스 전체, 코스 안의 특정 방문 카드에 남긴 이야기는 각각 분리합니다. 샘플 원글에 내 답글을 달거나 평가를 선택할 수 있고, 내 기록은 이 브라우저에만 저장됩니다. 샘플 사용자의 글을 수정하거나 삭제할 수는 없습니다.

샘플 기준 수에 내 기록을 더한 체험 합계를 표시하며 상세에서 각각을 구분합니다. 담김은 활성 저장 사본 기준의 횟수입니다. 실제 회원 통계·실제 방문 후기·서버 게시물은 연결 전이며, 가상 별점이나 서버 게시 성공으로 표시하지 않습니다.

### 정보와 지도 출처

Spotlog 등록 자료와 제주관광공사 VisitJeju의 공식 기본정보를 재사용하고 출처·확인일을 표시합니다. 제주 보강 업체 6곳은 2026-10-22 확인한 업체별 실제 주소와 좌표를 사용합니다. 가상 업체는 별도 표시하며 실제 업체로 치환하지 않습니다.

지도는 등록 좌표와 방문 순서를 사용합니다. 도로 조회 성공 시 참고 경로·시간을 표시하고, 조회 실패 시 같은 전체 위치를 방문 순서의 직선으로 연결합니다. 실시간 교통·현재 영업·가격·객실 재고·예약 가능 여부는 확인 전입니다.

## 실제 LLM 연결

기본 실행은 기능 체험 모드입니다. 서버 설정을 넣으면 실제 Flowise/Ollama와 RAG를 사용합니다. 현재 로컬 구현에는 일반 대화·검색·일정 기능 및 큰 로컬 모델로의 전환 경로가 포함돼 있습니다. 연결한 모델과 서비스가 없으면 실제 LLM 응답으로 표시하지 않습니다.

모바일 UI → POST /api/chat → 모델·RAG → 허용된 기능·ID·수정 범위 검증 → 동일한 카드·지도·일정 UI 순서입니다.

모델은 설명과 정해진 기능 요청을 반환합니다. HTML·좌표·임의 URL·전체 상태를 모델 출력 그대로 실행하지 않습니다. 예약 숙박·원본 코스·기존 저장본을 보호하고 잘못된 응답이면 현재 결과를 유지합니다. 소셜 도구는 화면 열기 전용이며 댓글·평가는 사용자가 직접 등록합니다. 모델에 샘플 집계는 출처와 함께 전달하지만 내 댓글 본문·내 반응은 보내지 않습니다.

- [실제 챗봇 통합 가이드](docs/CHATBOT_INTEGRATION.md): 현재 계약, 소셜 샘플, 실제 서비스 전환 경계
- [RAG 일정 생성과 로컬 모델 전환](docs/RAG_ITINERARY_ROUTING_20261015.md)
- [Spotlog 앱 진입점 인계](docs/spotlog-app-entry-handoff.md)
- [Flowise 출력 스키마](docs/flowise-output.schema.json), [Structured Output 필드](docs/flowise-structured-output.fields.json), [시스템 프롬프트](docs/flowise-system-prompt.txt)
- [.env.example](.env.example): 비밀값 없는 서버 설정 예시

실행 중 Flowise의 프롬프트만 갱신하려면 scripts/flowise/sync-system-prompt.mjs --dry-run 으로 먼저 확인한 뒤 --apply 를 사용합니다. 모델·그 외 그래프·설정이 그대로인지 검증합니다. 일상적인 갱신에 bootstrap 전체를 재실행할 필요는 없습니다.

API 키·회원 토큰·Flowise DB·개인 대화·모델 파일은 Git에 포함하지 않습니다. 실제 앱 운영에는 회원 인증·서버 소유 여행/대화·권한·트랜잭션·다중 기기 저장·게시/관리 API가 추가로 필요합니다. 실제 Jev 검색을 현재 /api/chat에 연결한 상태는 아닙니다.
