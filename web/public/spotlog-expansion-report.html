PRODUCT STRATEGY PRESENTATION

Spotlog 서비스
확장 전략

현재 모바일웹·하이브리드 앱의 구현 범위를 기준으로 상용 서비스 전환, 국내 콘텐츠 확보 및 외국인 관광객 대상 확장 방안을 정리함.

기준일2026.09.05작성 목적향후 개발 우선순위 결정문서 상태검토용 초안 v1.0
01 · EXECUTIVE SUMMARY

핵심 결론

화면을 추가하는 확장보다 현재 흐름이 실제 사용자 데이터로 작동하도록 전환하는 작업을 우선함.

PRODUCT

여행기를 중심으로 구성함

랜드마크 영상은 발견 수단으로 활용함. 글·사진·장소·동선이 결합된 실제 여행기를 최종 콘텐츠로 정의함.

SEQUENCE

국내 운영 기반을 먼저 완성함

국내 콘텐츠와 복사·완주 데이터를 확보함. 검증된 여행기부터 영어 번역과 외국인 현장 정보를 추가함.

PLATFORM

웹 본체와 앱 역할을 분리함

탐색·작성은 모바일웹을 유지함. 촬영·위치·오프라인·푸시·딥링크는 앱이 담당함.

02 · CURRENT STATUS

현재 구성 및 판단

현재 UI는 제품 기준선으로 유지함. 다중 사용자·운영 서비스에 필요한 서버 기반은 별도로 구축할 필요 있음.

KEEP

이미 구현한 흐름

  • 추천·여행자 일정이 롤링되는 메인 유지함
  • 지역·기간별 여행기 검색과 상세 열람 유지함
  • 영상·안내 목록에서 장소 저장 유지함
  • DAY·글·사진·장소 편집 유지함
  • 지도 경로·여행 복사·반응 UI 유지함
  • Expo WebView와 네이티브 브리지 재사용함
BUILD / REPLACE

상용화 전 필요한 기반

  • 회원·권한·여러 기기 동기화 필요함
  • 클라우드 미디어 업로드·CDN 필요함
  • 실제 조회·담김·댓글 서버 집계 필요함
  • 카카오 장소 검색 서버 연동 필요함
  • 원격 푸시·딥링크 필요함
  • 신고·차단·운영자 처리 기능 필요함
03 · CORE LOOP

핵심 사용자 흐름

콘텐츠 발견에서 실제 여행과 다음 여행기 생산까지 이어지는 반복 구조를 구축함.

STEP 1발견영상·사진·검색·추천 여행기 제공함
STEP 2빠른 저장목적지 지정 없이 장소 저장함
STEP 3여행별 분류지역·기간별 보관함으로 정리함
STEP 4일정 생성복사 또는 AI 초안 생성함
STEP 5실제 여행길찾기·완료·현장 기록 제공함
STEP 6여행기 발행글·사진·장소·동선을 결합함
STEP 7복사·반응담김·댓글·등급을 작성자에게 환류함
핵심 판단 · 조회수가 아닌 여행기 상세→복사 전환율, 저장 장소→일정 생성률, 실제 여행 완료 반응을 핵심 제품 지표로 사용함.
04 · CONTENT FORMAT

영상·사진·안내를 하나로 운영함

콘텐츠 형식은 다르지만 모두 동일한 장소를 발견하고 저장하게 하는 기능으로 통합함.

COMMON DATASpotlog Place ID

장소명·지역·한글 주소·좌표를 공통으로 연결함. 저장 버튼과 저장 결과를 모든 콘텐츠에서 동일하게 유지함.

풀영상

실제 움직임과 분위기를 전달함. 원본 영상 보유 시 우선 활용함.

사진 모션

사진만 확보한 장소를 줌·팬·교차 전환으로 영상화함.

사진 이야기

세로로 장소를 넘기고 한 게시물 안에서 사진과 평가를 좌우로 탐색함.

지역 안내

지역·키워드로 장소를 비교하고 검색하는 목록을 제공함.

장소가 연결되지 않은 분위기 영상은 공개 발견 피드에서 제외함. 풀영상과 사진 기반 콘텐츠를 동시에 운영함.
05 · SAVE & COLLECTION

처음에는 바로 담고
일정 생성 전에 분류함

발견 단계에서 목적지나 여행 선택을 강제하지 않음. 저장 이후 지역별로 자동 분류함.

01 · DISCOVERY빠른 저장함

영상·사진·검색에서 한 번의 탭으로 저장함. 서울과 제주를 섞어 담아도 저장을 막지 않음.

→
02 · ORGANIZE여행별 보관함

지역을 자동 분류함. 같은 지역이 3곳 이상 모이면 여행 묶음을 제안함. 장소를 여러 보관함에 저장 가능함.

→
03 · PLAN일정 생성

하나의 지역 또는 보관함을 선택함. 여행 기간·숙소·이동수단·동행 조건을 반영함.

06 · IMPLEMENTATION ROADMAP

단계별 추진 순서

개별 화면을 단독 추가하지 않음. 다음 기능이 의존할 수 있는 데이터 기반부터 순차 구축함.

P0

회원·DB·권한·미디어 기반

로그인, RLS, 서버 저장, 로컬 데이터 이전, 사진·영상 업로드 구성함.

최우선
P1

장소 검색 및 여행별 보관함

카카오 장소 검색, 한글명·주소·좌표 저장, 빠른 저장함과 컬렉션 도입함.

내부 알파
P2

편집·부분 복사·AI 완성

자동 저장, DAY 이동·복제, 전체·DAY·장소 복사, 검증 가능한 AI 구현함.

국내 베타
P3

소셜·푸시·운영 안전

실제 반응 집계, 목표 푸시, 신고·차단·운영자 처리 기능 구축함.

국내 공개 전
P4

앱 전용 실제 여행 모드

오프라인 일정, 현재 위치, 방문 완료, 사진·메모 대기열, 딥링크 제공함.

앱 심사 전
P5

영어 로컬 가이드 베타

검증된 여행기에 번역, 현장 정보, 지도 앱 선택, 긴급 안내 추가함.

국내 데이터 확보 후
07 · CONTENT ACQUISITION

전국보다 다섯 지역에 집중함

장소 수 확대보다 실제로 따라갈 수 있는 완성형 여행기 확보를 우선함.

서울

도심 산책·성수·궁·야간 코스 중심으로 구성함

부산

해안·시장·언덕 마을 이동 동선 중심으로 구성함

제주

동서 권역·날씨 대체 일정 중심으로 구성함

경주

역사·자전거·야간 유적 중심으로 구성함

강릉

바다·카페·당일·1박 코스 중심으로 구성함

초기 공개 목표 · 지역당 12~20개, 전체 60~100개의 완성형 여행기를 확보함. 당일치기·1박 2일·2박 3일 유형을 지역마다 확보함. 여행기별 원본 사진, 3곳 이상 장소, 이동 순서, 체류시간, 장점, 아쉬운 점을 포함함.
08 · CREATOR GROWTH

콘텐츠를 올릴 이유를
실제 반응으로 제공함

가짜 조회수보다 다른 사용자가 실제 여행에 사용한 결과를 작성자에게 환류함.

CONTENT SUPPLY

초기 수급 방식

  • 운영자가 지역별 대표 여행기를 먼저 제작함
  • 지역당 2~5명의 초기 창작자를 모집함
  • 월별 주제와 작성 템플릿을 제공함
  • 호텔·게스트하우스에는 주변 하루 동선 작성을 요청함
  • 샘플·일반 글·광고·협찬을 명확히 구분함
MOTIVATION & KPI

작성자 보상 신호

실제 담김 수여행기 완독률여행 완료 반응댓글·응원지역 가이드 배지홈 추천 노출

담김 전환율·완독률·신고율을 함께 반영하여 등급과 추천 노출을 결정함.

09 · GLOBAL EXPANSION

국내용을 유지한 채
외국인용으로 확장함

별도 콘텐츠 서비스를 새로 만들지 않음. 동일 여행기에 번역과 외국인 현장 정보 계층을 추가함.

DOMESTIC FIRST

한국어 원문과 실제 사용 데이터

국내에서 많이 담기고 신고가 적으며 완주 반응이 좋은 여행기를 선별함.

  • 한글 원명·주소·좌표 구조화함
  • 출구·이동·예약 정보를 분리 저장함
  • 원문과 수정 이력을 유지함
→
ENGLISH BETA

번역과 현장 사용 정보 추가

자동번역 초안을 작성자가 검수함. 번역명과 한글 원명·주소를 함께 제공함.

  • 지도 앱 선택과 좌표 우선 연결함
  • 한글 주소 크게 보기·복사 제공함
  • 오프라인 일정과 긴급 정보 제공함
10 · DATA PROVIDERS

한 공급자에 모든 정보를 의존하지 않음

장소 검색·관광 설명·사진·경로·사용자 경험·AI의 역할을 분리함.

PLACE SEARCHKakao Local

국내 업체명·주소·좌표·전화·카테고리를 제공함. 서버 함수에서 호출함.

TOUR CONTENT한국관광공사

다국어 관광 설명과 사용 허가 범위가 명확한 관광 이미지를 활용함.

GLOBAL SUPPORTGoogle Places

영어 검색과 사진이 꼭 필요한 경우에만 비용을 통제하여 선택 호출함.

EXPERIENCE사용자 입력

실제 평가·사진·숙소 선택 이유·이동 팁을 담당함. 공식 정보와 구분함.

ROUTE지도·경로 공급자

거리·예상 시간·경로선을 담당함. 실시간 교통 반영 여부를 명시함.

ASSISTANCE생성형 AI

일정 분배·번역 초안·글 구조화만 담당함. 가격과 영업정보를 생성하지 않음.

11 · HYBRID PLATFORM

모바일웹은 본체,
앱은 현장 여행 도구로 구성함

앱을 웹사이트를 여는 셸에 머물게 하지 않음. OS 기능이 필요한 부분을 앱이 담당함.

MOBILE WEB

콘텐츠 본체

링크로 바로 열리고 공유·검색되는 영역을 담당함.

  • 여행기 탐색·검색·공개 상세 제공함
  • 장소 검색과 보관함 관리 제공함
  • 여행 일정·여행기 편집 제공함
  • 영구 공유 URL과 웹 검색 노출 담당함
NATIVE APP

현장 기능

촬영·위치·오프라인·알림과 설치 앱 연결을 담당함.

  • 카메라 촬영과 미디어 업로드 담당함
  • 현재 위치와 실제 여행 모드 담당함
  • 저장 여행 오프라인 열람 담당함
  • 원격 푸시와 딥링크 담당함
  • OS 공유 시트와 지도 앱 선택 담당함
12 · FIRST 90 DAYS

90일 우선 실행안

화면 추가보다 실제 데이터가 생성·저장·조회되는 단일 완성 흐름을 우선함.

1~4주

서버 기준선 구축

  1. 개발·스테이징 환경 분리함
  2. 회원·여행·장소·보관함 DB 구성함
  3. RLS 허용·거부 테스트 작성함
  4. 로컬 데이터 1회 이전 구현함
  5. 사진 업로드 최소 기능 구축함
5~8주

장소→보관함 구축

  1. 카카오 Local 서버 검색 연결함
  2. 직접 등록과 중복 처리 구현함
  3. 빠른 저장함·여행별 보관함 구현함
  4. 저장 장소→일정 생성 연결함
  5. 한국어·영어 장소 필드 확정함
9~12주

내부 알파 검증

  1. 두 기기 동기화를 검증함
  2. 자동 저장과 작성 복구 구현함
  3. 전체·DAY·장소 복사 이벤트 기록함
  4. 5개 지역 콘텐츠 제작 시작함
  5. E2E 테스트와 비용 계측 적용함
13 · FINAL DECISION

국내에서 신뢰할 수 있는
여행기를 먼저 축적함.

현재 UI를 유지하면서 저장소와 공급자 연결을 상용 구조로 전환함. 검증된 국내 여행기부터 영어로 확장함.

다음 구현 단위 · Supabase 개발 환경과 권한 구성 → 로그인과 로컬 데이터 이전 → 카카오 장소 검색 → 여행별 보관함 저장 → 선택한 보관함으로 일정 생성까지 하나의 세로 기능으로 추진함.

호텔 가격 비교·내부 예약·전국 업체 자체 DB·자체 내비게이션·상시 위치 추적·모든 언어 동시 지원은 당분간 제외함.
