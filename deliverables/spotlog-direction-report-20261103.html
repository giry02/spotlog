핵심 판단 02

기능을 더 모으기보다,
한 번의 공동 이용을 끝까지 연결

일상과 지속 모임을 중심에 두고, 여행은 더 깊게 계획할 수 있는 활동 유형으로 유지

① 서비스 중심

식사·카페·산책·취미 모임부터 시작.
개인 저장 → 함께 선택 → 약속 → 다음 참여가 핵심 흐름.

② 화면 구조

하단은 홈·발견·내 모임·내 공간 4개. 대화와 준비는 모임 또는 개별 약속 안에서 접근.

③ 투자 순서

실제 두 사람이 함께 쓰는 인증·권한·공유·초대·알림을 먼저 연결. AI는 그 위에서 조율을 보조.

차별화 가설

“갈 곳을 추천하는 기능”보다 “각자 저장한 갈 곳을 함께 정하고, 준비하고, 다음에도 만나는 경험”에 집중.

유지할 가치

혼자 쓰는 관심 장소·폴더·개인 일정·여행기. 모임 가입 없이도 이용 가능.

줄일 신규 투자

자체 예약 판매·객실 재고·결제, 전국 동시 모집, 범용 메신저 전체 복제는 후순위.

발표 메모

개인·모임·여행을 모두 같은 비중으로 나열하던 방식에서 우선순위를 좁힌 제안. 기능의 독점성이나 성장 효과를 이미 입증한 것은 아님. 실제 반복 이용으로 검증해야 함.

기능 이름보다
사용자가 돌아오는 이유를 다르게

겹치는 기본 기능은 인정하되, 개발·운영의 중심을 공동 선택과 반복 만남에 배분

영역스팟로그의 선택첫 검증 질문
장소 탐색·저장혼자 저장해도 쓸모 있는 지역·종류·폴더 관리여행을 만들지 않아도 저장한 곳을 다시 찾는가
함께 정하기완성 일정 이전에 장소 한 곳을 모임에 제안후보·의견이 실제 약속 생성으로 이어지는가
지속 모임하나의 가족·친구·취미 모임에 여러 약속과 기록 축적한 번의 참여 뒤 같은 모임에서 다음 참여가 생기는가
AI근거 대화에서 준비·확인·공지 후보를 제시사용자가 원문을 확인하고 실제 준비에 쓰는가
여행·예약기존 여행 깊이는 보존, 예약 서비스 재구축은 후순위일상 흐름을 방해하지 않으면서 다일 여행을 수용하는가
선택할 포지션

개인의 관심 장소를 함께하는 약속과 지속적인 모임으로 연결하는 서비스

위 항목은 투자 우선순위 제안. 경쟁사에 같은 기능이 없다는 뜻이나 검증된 경쟁 우위를 의미하지 않음.

발표 메모

NOL이나 커뮤니티 앱의 기능 부재에 기대는 전략은 오래가기 어려움. 우리에게 남아야 할 자료는 개인의 취향과 모임의 결정·준비·기록. 이를 실제 반복 이용으로 연결하는지가 검증 과제.

서비스 설계 06

식당 한 곳에서 시작해도
모임과 다음 만남까지 이어지게

예시 · “저장해 둔 부산 식당, 이번 주 가족과 같이 갈까?”

  1. 01

    개인 저장

    식당·카페·호텔·레저·랜드마크를 독립 저장. 지역·종류·폴더로 다시 찾기.

  2. 02

    모임에 제안

    선택 장소만 가족 모임에 전달. 개인 폴더 전체와 비공개 메모는 전달하지 않기.

  3. 03

    함께 선택

    시간·장소 의견 확인. 담당자가 “약속 만들기”로 확정하고 참여자는 별도로 참석 선택.

  4. 04

    준비·만남

    약속 안에서 공지·챙길 일·대화·일정 확인. 여행이면 DAY·숙소·동선 편집을 확장.

  5. 05

    기록·다음 제안

    사진·후기·지난 약속이 모임에 남고, 다시 가고 싶은 곳을 다음 후보로 제안.

상태는 분리 긍정 의견 ≠ 약속 생성 ≠ 참석 신청 ≠ 실제 참석 ≠ 음식점·숙소 예약 완료.
발표 메모

일반 정모는 기존에도 있었음. 이번 변경의 중심은 새 정모 기능의 존재보다 개인 저장이 모임의 결정으로 이어지는 연결과 화면의 우선순위. 혼자 이용하는 사람에게 모임 가입을 강요하지 않음.

화면 변경 07

5개 메뉴의 기능은 보존하고
4개 목적지로 다시 배치

기존 앱은 아직 5탭. 아래 4탭은 새 독립 시안의 제안 구조

기존 하단 메뉴변경 메뉴·위치사용자가 하게 될 일
홈홈처음 온 사람은 모임 발견, 모임원은 다음 약속, 모임장은 가입 처리부터
둘러보기발견모임 / 약속 / 장소 / 공개 기록 중 하나씩 보기. 지역·관심사·종류로 필터
함께하기내 모임 + 발견의 모임 찾기가입한 모임과 공개 모집 분리. 모임 → 약속 → 대화·준비·기록
내 여행내 공간 → 내 일정·여행 / 내 기록개인 일정과 공개 여행기를 구분. 여행 계획·DAY·숙소·동선 유지
관심 장소내 공간 → 저장 장소·폴더저장 목록을 먼저 확인. 혼자 일정에 넣거나 특정 모임에 제안

우측 상단 전체 메뉴

알림·내 정보·설정·이용 안내 등 보조 기능. 기존 화면마다 주요 기능 버튼을 덧붙이는 방식 축소.

대화의 위치

독립 하단 채팅 탭을 만들지 않고 모임 전체방 / 개별 약속방 안에서 접근.

최종 메뉴 명칭과 알림 진입은 사용자 검수 후 확정. 기존 데이터의 ID·공개 범위·소유권은 메뉴 이동으로 변경하지 않음.

발표 메모

페이지를 그대로 합치는 재사용보다 목적별 탐색을 먼저 정리. 기존 내 여행과 관심 장소가 없어지는 것이 아니라 내 공간 안에서 명확하게 분리됨. 일반 약속과 다일 여행도 같은 입력폼으로 강제하지 않음.

화면 변경 08

기존 기능을 계속 쌓으면
다음 행동이 화면 아래로 밀림

10월 30일 로컬 관찰 · 색상보다 정보 순서와 정렬을 먼저 수정

① 첫 행동이 늦게 나옴

390 × 844 화면에서 첫 모집 카드 시작 약 695px. 상단 설명과 CTA가 누적돼 탐색이 늦어짐.

② 여백 기준이 섞임

일부 주요 버튼의 좌우 여백 18px, AI·로그인 카드 38px. 같은 화면에서 내용 폭이 달라 끼워 넣은 인상.

③ 역할과 맥락이 섞임

모임명 반복, 소개·대화·AI가 다음 약속보다 앞섬. 신규 방문자와 기존 모임원의 우선 행동도 같게 배치.

수정 기준 기존 스타일가이드 유지 + 좌우 기준 통일 + 한 화면의 주요 행동 우선 + 고급 기능은 해당 맥락 안으로 이동.
발표 메모

이 수치는 선택한 기존 로컬 화면에서 관찰한 값. 모든 기기·모든 상태의 평균값은 아님. 화면 폭 문제를 해결했다는 것과 실제 사용자가 이해했다는 것은 별도 검증이 필요함.

조회 수보다 먼저 볼 것:
실제로 함께 쓰고 다시 참여하는가

가설 검증 지표. 현재 실적이 아니며 서버 연결 전 항목은 “미측정”으로 표시

검증할 가설측정 단위잘못 해석하지 않을 것
개인 이용 가치저장 후 다시 찾기·지역/종류 필터 사용·제안 진입샘플 장소 수를 사용자 이용 성과로 집계하지 않기
첫 공동 이용서로 다른 실제 회원 2명 이상이 같은 모임에서 제안·의견·참석 등 성공한 사람이 검수 역할을 바꾼 테스트는 공동 이용 아님
모집 전환소개 열람 → 가입 신청 → 승인 → 첫 약속 참석 선택을 각각 측정가입 승인율을 정모 참석률로 해석하지 않기
반복 이용첫 참여 이후 같은 모임에서 다음 약속 참석 선택참석 선택과 실제 방문은 다름. 출석 확인 방식은 별도 합의
조율·운영 품질제안→약속 전환, AI 후보 적용·오답, 취소·신고·알림 실패·응답시간·비용AI 결과 수·메시지 수만으로 유용성 판정하지 않기
목표치는 베타 범위와 함께 합의 기간·대상·최소 표본·성공 기준을 정한 뒤 판단. 임의 MAU·매출·전환율 목표나 검증되지 않은 성장 수치 제시 제외.
발표 메모

최소 첫 공동 이용과 다음 참여를 분리해 확인해야 함. 실제 출석은 동의받은 확인 방식이 있어야 측정 가능. 지표 수집을 위해 고객 대화 원문과 개인 메모를 자동 수집하는 방식은 기본값에서 제외.

의사결정 19

이 방향에 합의한 뒤
실제 연결 범위를 좁혀 실행

승인 요청은 기능 전체가 아니라 중심 경험·검증 대상·권한·통과 기준

결정할 것권고안이 결정이 필요한 이유
① 서비스 중심·메뉴개인 발견→모임 제안→반복 만남. 4개 메뉴 채택기존 여행 UI에 새 기능을 계속 덧붙이는 방식 중단
② 첫 파일럿비공개 가족·친구 + 한 지역 취미 모임의 소규모 검증사적인 편의와 공개 모집은 유입·운영 난도가 다르므로 별도 관찰
③ MVP 투자 순서실제 공동 사용·권한·초대·알림·신고를 AI 고도화보다 먼저두 사람이 함께 쓸 수 있어야 서비스 가치 검증 가능
④ 결정 권한·모임 생성멤버 제안·의견 허용, 확정·공개 권한 결정. 개인 초대 첫 수락 시 활성화와 모임 먼저 만들기 구분시안의 멤버 생성 허용·초대 방식과 운영 정책을 혼동하지 않기
⑤ 통과·확대 기준다른 계정·기기의 전체 흐름 + 다음 참여 + 운영 복구 확인화면 수나 기능 목록이 아닌 이용 성공으로 확대 여부 판단
보고 제안 문장

여행 기능은 유지하면서, 개인의 장소 저장을 함께 정하는 약속과 지속 모임으로 연결하는 방향으로 우선순위를 바꾸고 실제 공동 이용부터 검증.

발표 메모

예약 제휴나 운영자 유료 도구 같은 수익 모델은 반복 이용과 운영 가치를 확인한 뒤 실험. 자체 결제나 예약 재고 확보를 지금 MVP 완료 조건에 넣지 않음.

1분 설명

기존 스팟로그는 장소를 찾고 개인 여행을 만드는 데 중심이 있었음. 새 방향은 개인이 저장한 식당·카페·산책 장소를 모임에 제안하고, 함께 약속을 정하고, 준비와 기록을 다음 만남으로 잇는 서비스.

NOL도 이미 AI 일정과 일상형 발견을 제공하므로 추천이나 AI 생성 자체로는 구분이 약함. 우리는 개인의 저장과 지속 모임의 결정·준비 연결에 집중. 이를 위해 메뉴를 4개로 재설계한 독립 로컬 시안을 만들었고, 다음 단계는 실제 두 계정의 공동 이용과 재참여 검증.

질문답변 요지
여행 앱을 버리는 건가?아님. 개인 여행과 여행기를 보존하고, 여행을 일상 약속보다 깊은 계획 유형으로 수용.
소모임·카카오와 뭐가 다른가?그룹·요약 기능 존재만으로는 구분 불가. 개인 저장→함께 선택→준비→다음 만남의 연결을 검증할 계획.
지금 출시 가능한가?독립 시안 검토 단계. 실제 인증·공동 자료·실시간·알림·AI·운영 연결과 제한 베타 필요.
수익화는?반복 이용 확인 뒤 운영자 편의·가이드 콘텐츠·외부 예약 연결 등을 검토. 가격·제휴·수익은 미확정.
