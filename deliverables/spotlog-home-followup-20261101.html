01 확인 결과

“전체적으로 부족하다”는 느낌의 원인

장소·모임·여행을 분리한 방향은 유효. 각 영역의 조건·결과·진입 경로가 달라 이용 흐름이 이어지지 않는 상태.

우선·구분실제로 확인한 현상수정할 방향
P1 · 경로 불일치모임 홈 지역을 서울로 선택. 상단 “동네·취미 모임 찾기”는 전체 지역으로 이동, 아래 “공개 모임 전체 보기”는 서울 유지.어느 버튼으로 진입해도 현재 지역·관심사 조건을 전달. 제목과 결과의 범위를 일치.
P1 · 검색 결함새 시안 정모 목록에 “주말 보드게임 한 판”이 있음. “주말 보드게임”으로 검색하면 0건. 모임 이름으로 먼저 거르는 구조.모임은 모임명·소개, 정모는 정모명·모임명·장소, 장소는 이름·주소를 검색. 유형별로 대상을 분리.
P1 · 찾기 흐름기존 장소 홈은 종류만 선택 가능. 지역 선택은 별도 둘러보기에 있음. 거기서 부산을 선택하고 홈으로 와도 제주 예시 3곳이 표시됨.공개 탐색의 지역 → 종류 → 결과를 한 흐름으로. 지역 변경 시 결과·건수·더보기 조건을 함께 변경.
P2 · 정보 순서390×844에서 장소 홈 첫 카드가 약555px, 별도 장소 탐색의 첫 장소 제목은 약906px. 안내·버튼·지역 목록을 먼저 지나야 함.긴 안내 축소. 지역은 현재값 한 줄, 상세 선택은 눌러 열기. 주요 결과를 첫 화면 안에 보이게.
P2 · 개인·모임 균형새 신규 홈의 주요 행동은 “가까운 모임 찾기”. 개인 관심 장소 진입은 하단 작은 화살표이며 약702px 위치.신규 홈에서도 개인 장소 찾기·저장을 명확히 보이기. 주요 행동을 여러 큰 버튼으로 중복하지 않기.
P2 · 콘텐츠·분류기존 장소 자료는 많아도 홈은 고정 앞3곳. 새 시안 장소는 전체4곳이며 독서·음악 같은 관심사가 장소 종류와 섞임.지역별 음식점·카페·숙소·레저 비교 샘플 보강. 장소 종류와 모임 관심사는 별도 분류.
유지할 것 현재 홈 탭별 스크롤·장소 종류·모임 지역·여행 카드 위치 기억, 수동 카드 넘김은 이미 있음. 전체 초기화나 자동 롤링을 새 문제로 보고하지 않음.

위 좌표는 해당 로컬 자료·390px 검수 상태에서 관찰한 값. 모든 계정·폭의 평균이나 실제 사용자 이탈률이 아님. 추가 점검은 전체 기능 재검증이 아닌 요청된 메인·탐색 흐름 중심.

02 화면 비교

기존 메인과 새 시안 모두 보완 필요

기존 구조

조건을 고르려면 다시 이동. “지역·종류로 찾기”와 “전체 장소 보기”가 같은 탐색으로 반복 연결. 홈의 자료 선정 기준도 보이지 않음.

새 구조

모임의 다음 행동은 단순해졌으나 혼자 장소를 찾으려는 사람에게는 첫 화면의 목적이 불명확. 시안을 최종안으로 취급하지 않고 개인 발견을 보강할 필요.

03 수정안

홈과 발견의 역할부터 나누기

권고 · 4개 메뉴 방향 유지

홈은 내가 이어할 일과 지역의 발견 진입.
발견은 지역·대상·조건을 고르고 비교하는 곳.
내 모임은 소속 관계, 내 공간은 개인 원본.

기존 3영역을 당장 유지한다면

장소·모임·여행 위에 공개 탐색의 지역을 표시. 주제별로 종류·관심사·기간을 다르게 제공하고, 상세 탐색에 같은 조건 전달.

단순히 탭을 3개 더 만드는 것으로 해결하지 않기.

  1. 지역은 바로 보이게

    선택값은 상단 한 줄. 17개 지역 전체를 첫 화면에 항상 펼치지 않기. 위치 권한을 요구하기 전에 직접 선택 가능.

  2. 내 일과 공개 탐색을 분리

    지역 필터로 내 모임·내 약속을 숨기지 않기. 기존 약속·일정이 있으면 새 생성보다 먼저 이어가기.

  3. 대상마다 알맞은 조건

    장소는 종류, 모임은 관심사, 약속은 날짜·활동. “독서”를 숙소와 같은 장소 종류로 취급하지 않기.

  4. 실제 결과가 화면의 중심

    긴 소개·AI 안내·로그인 유도보다 카드 우선. 사진·동네·종류·한 줄 설명·저장으로 비교. 반복 설명 축소.

  5. 다음 화면에서도 조건 유지

    더보기·검색·상세·뒤로가기에서 지역과 해당 주제 조건 유지. 초기화는 명시적 버튼으로 실행.

오른쪽 설명을 위한 정적 배치안. 실제 제품 기능·데이터·카드 수를 뜻하지 않음. 홈에 전체 탐색 UI를 모두 복제하기보다 발견으로 자연스럽게 이어지는 규모로 조정.

04 적용 순서·검수

버그부터 고치고, 충분한 자료로 배치를 비교

순서작업통과 기준
1 · 경로·검색모임 홈 지역 전달 통일, 정모 제목 검색 분리서울 선택 후 어느 버튼이든 서울. 존재하는 정모를 제목으로 검색 가능.
2 · 조건·화면메인 지역 노출, 중복 CTA 정리, 이어가기 우선, 개인 발견 진입 보강신규 사용자와 모임원이 각각 첫 화면에서 시작할 행동을 이해. 지역→조건→결과가 일치.
3 · 자료·예외부산 중심 종류별 샘플·사진·긴 이름·빈 결과·미연결·실패 상태음식점/숙소도 독립 저장. 샘플·실제 집계 구분. 없는 종류는 빈 결과 안내.
4 · 화면 검수320·390·460 및 PC 폭, 가로 칩8px 간격·터치44px+·본문/입력16px페이지 가로 넘침 없음. 칩만 수동 스크롤. 하단 메뉴·키보드가 주요 행동을 가리지 않음.
5 · 사용성 확인처음 쓰는 사람에게 장소 찾기·저장·제안·가입을 직접 수행하게 관찰설명 없이 성공하는지, 막힌 위치와 되돌아가기를 기록. 숫자 목표는 관찰 범위와 함께 합의.

이번 점검에서 개인 저장·여행·회원 자료를 수정하거나 가입·게시·실제 메시지 전송을 실행하지 않음. 앱 코드 수정은 아직 미반영. 근거: App.tsx 1033·1103·1164~1216, GroupDiscovery.tsx 88·104, zero-direction-review.tsx 147~150.

05 PC까지 확장

모임 운영은 큰 화면에서도 이어가기

당근 공식 안내는 PC 웹 채팅과 모바일 앱 QR 인증을 제공. 모임 운영 전체 지원은 별도 확인 필요.

권고 순서 모바일·PC 공통 서버 → PC 반응형 웹 → 설치형 웹앱(PWA) → 상주·트레이 등 필요 시 전용 PC 패키지.

설치형 웹앱은 앱 창·작업표시줄 진입이 가능하지만, 설치만으로 실제 동기화·푸시가 완성되지는 않음. 알림 허용·기기별 세션·재접속·탈퇴 뒤 차단 등 검수 필요.
