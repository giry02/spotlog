01 · 진단

현재 디자인이 새 방향에 충분히 맞는가? 아직 아닙니다.

색과 폰트보다, 화면이 강조하는 대상이 뒤처져 있습니다.

기존은 개인이 장소를 감상하고 여행을 만드는 흐름입니다. 앞으로는 개인이 장소를 모으고, 사람을 초대하고, 약속을 실행하고, 관계와 기록을 이어가는 흐름이 중심이어야 합니다.

현재 어색한 이유

  • 장소·여행 중심의 큰 사진 카드가 모임 목록에도 반복됩니다.
  • ‘함께하기’ 안에 공개 모집, 내 모임, 개별 약속이 섞여 역할이 흐립니다.
  • 상단 탭·종류·지역·보기 방식이 겹쳐 결과를 보기 전 조작이 많습니다.
  • 모임 전체와 특정 약속을 오갈 때 대화·공지의 소속이 분명하지 않습니다.
  • 개인 여행을 이어가는 요소가 공개 정보 발견보다 먼저 보이는 화면이 남아 있습니다.

다시 잡을 중심

  • 공개 발견과 내가 실행할 약속을 분리합니다.
  • 목록은 비교, 상세는 이해, 대화는 소통, 준비는 실행에 맞게 다르게 구성합니다.
  • 친구 저녁은 가볍게, 가족여행은 DAY·숙소까지 확장합니다.
  • 영구 모임 없이도 초대와 약속을 시작할 수 있어야 합니다.
  • 기존 관심 장소·개인 일정·여행기·동선 공유는 이 흐름의 자산으로 유지합니다.
발견·직접 제안→초대·참석→장소·준비→만남→기록·다음 약속

이 진단은 이전 로컬 검수 결과와 이번 벤치마킹을 연결한 설계 판단입니다. 경쟁 서비스가 모두 작은 목록을 쓰거나, 동일한 통합 기능을 제공한다는 뜻은 아닙니다.

04 · 구조 제안

1

큰 사진의 역할을 한정합니다.

모임·장소 목록은 64~80px 썸네일과 반복 행으로 비교하게 합니다. 큰 사진은 상세 표지·사진 감상·동선 소개처럼 필요한 화면에 둡니다. 모든 카드를 일괄 축소하지 않습니다.

2

공통 상단은 한 벌, 내부 탭은 공간마다 한 줄입니다.

모임은 홈 / 약속 / 게시판 / 앨범 / 대화. 개별 약속은 일정 / 준비 / 기록 / 대화. 방의 이름·소속이 계속 보이게 하고 공지·멤버·설정을 별도 상위 탭으로 늘리지 않습니다.

3

지역·종류·보기 방식의 중복을 줄입니다.

발견 상단에는 활동 지역과 검색, 아래에는 목적 한 줄을 둡니다. 상세 필터는 하나의 패널에서 조정합니다. 장소·사진·영상 화면마다 다시 시작하는 헤더와 중복 탐색 탭을 쌓지 않습니다.

4

구성은 내용의 종류를 따라갑니다.

약속은 날짜순 목록, 게시판은 짧은 고정 공지＋글 목록, 앨범은 3열 미디어, 대화는 말풍선＋입력창, 준비는 담당·기한이 있는 체크 항목으로 만듭니다.

5

개인과 모임, 가입과 참석을 구분합니다.

개인 일정은 가입 없이 작성합니다. 친구 약속의 초대 수락이 영구 모임을 강제로 만들지 않게 합니다. 공개 모임 가입 승인은 해당 약속의 참석·예약·공개 동의가 아닙니다.

6

글씨보다 정보의 중복과 여백을 먼저 줄입니다.

목록 제목 16px, 본문 14px, 보조 12px, 입력 16px, 터치 영역 44px를 기본으로 검토합니다. 인스타그램의 실측값으로 주장하지 않으며 긴 이름·지역·접근성 글자 확대도 함께 검수합니다.

05 · 모바일 배치 제안

같은 스타일 안에서도 화면의 역할은 달라야 합니다.

아래 네 화면은 배치를 비교하는 별도 설계 예시입니다. 이름·내용은 가상이며 실제 모임·회원 수치나 처리 결과가 아닙니다. 위 버튼으로 구성을 전환할 수 있습니다.

  1. 지역: 활동할 지역을 선택합니다. 현재 위치 허용은 선택이며 지역 직접 선택도 유지합니다.

  5. 추천 홈: 공개 약속과 모임을 짧은 구역으로 구분하고, 장소 추천은 그 아래 독립 구역으로 이어집니다.

참고: 당근·소모임의 지역/목록, Meetup의 모임/행사 구분, Timeleft의 구체적인 만남 목적. 복합 적용안이며 어느 한 서비스의 복제 화면이 아닙니다.

약속을 실행하는 목록

  1. 응답할 초대: 안내 확인 → 참석/불참/미정. 자동 가입·참석은 없습니다.
  2. 약속 추가: 제목·날짜 또는 날짜 후보·장소만으로 시작. 모임 연결은 선택입니다.
  3. 짧은 만남: 일시·장소·참가자·준비를 간단하게 봅니다.
  4. 가족여행: 같은 약속 안에서 DAY·숙소·여러 장소·동선을 펼칩니다. 여행기 작성이 선행되지 않습니다.
  5. 지난 약속: 대화와 기록은 보존하되 새 약속으로 복사할 때 참석·예약·완료 상태는 초기화합니다.

참고: Partiful의 짧은 제안, Luma의 상태 구분, Cozi의 가족 일정·준비 협업. 개인정보와 공개 범위는 각 사용자의 명시적 설정을 따릅니다.

가입한 뒤의 모임 공간

  1. 홈: 공지 → 다음 약속 → 최근 글/사진. 소개를 길게 반복하지 않습니다.
  2. 약속: 이 모임의 다가오는·지난 약속. 특정 약속을 누르면 그 약속 안의 일정·준비·대화로 들어갑니다.
  3. 게시판: 공지·질문·후기 필터, 제목과 짧은 미리보기. 글은 댓글·답글·신고를 유지합니다.
  4. 앨범: 사진·영상을 3열로, 약속별로 묶습니다. 사진 추가가 외부 공개를 뜻하지 않습니다.
  5. 대화: 모임 전체 대화. 개별 약속의 준비 대화와 합치지 않습니다.
  6. 메뉴: 멤버·초대·알림·운영·신고·나가기. 가족 모임은 모집 버튼보다 다음 일정과 사진이 먼저입니다.

참고: 소모임의 일관된 내부 탭, BAND의 기록 연결, WhatsApp의 전체 공지/작은 대화, BFF의 공개 소개/내부 구분.

대화가 많아도 핵심을 잃지 않게

  1. 상단: 모임과 정확한 약속 소속을 표시합니다. 뒤로 가면 약속 상세로 돌아갑니다.
  2. 공지: 현재 확정 안내 한 줄. 길면 펼쳐 읽고 다시 접습니다. 스크롤 중에도 진입점을 유지합니다.
  3. 대화 정리: 안 읽은 대화·변경점·준비 요청을 작은 패널로 확인하고 근거 메시지로 이동합니다.
  4. 답장/반응: 메시지 선택 시 아이콘을 노출합니다. 읽기 전부터 ‘답장·반응’ 글자를 모든 말풍선에 붙이지 않습니다.
  5. 최신 대화: 아래로 내려갈 수 있을 때만 아래 화살표를 표시합니다.
  6. 제안 ≠ 확정: 3시라는 대화가 나와도 약속은 현재 2시를 유지합니다. 주최자의 명시적 변경과 참석자 확인을 거칩니다.

참고: 카카오의 낮은 조작 부담, Discord의 주제/원문 연결, WhatsApp의 개인 요약. 변경표·준비 전환은 Spotlog의 제안입니다.

06 · AI 활용 제안

요약하는 AI에서, 만남이 실제로 성사되게 돕는 AI로

아래 여덟 가지는 경쟁사에 모두 있다고 주장하는 기능이 아니라 Spotlog의 장소·동선·약속·모임 자산을 연결한 제안입니다. 새 AI 메뉴를 늘리기보다 사용자가 막히는 순간에 작은 결과와 다음 행동을 제시합니다.

01 · 차별화 우선

“우리 모두 가고 싶던 곳이네?”

이번 모임에 각자가 공유하기로 고른 관심 장소에서 겹치거나 가까운 후보를 찾습니다. ‘우리가 함께 가고 싶은 이유’가 있는 다음 약속을 만듭니다.

예: 한 사람은 카페, 다른 사람은 근처 전시를 제안 → ‘전시＋카페’ 후보와 필요한 이동 확인 항목을 제시 → 의견 받기 → 약속 만들기.

위치: 모임의 장소 제안 / 다음 약속 만들기

필요: 공유된 placeId·종류·좌표. 개인 관심 장소 전체·집·직장 위치는 자동 열람하지 않음.

02 · 차별화 우선

“언제, 어디면 다 같이 될까?”

사람들이 직접 알려준 시간·지역·예산·걷기·음식 조건을 카드로 모읍니다. 후보별로 충족 / 충돌 / 정보 없음을 비교해 남은 질문을 줄입니다.

예: 친구 저녁은 퇴근 시간과 예산, 가족여행은 직접 선택한 보행 선호와 숙소 위치를 비교. 조건이 안 맞으면 ‘최적’이라고 우기지 않고 선택할 타협을 보여줍니다.

위치: 날짜 미정 약속 / 장소 후보 비교

시간 교집합·거리 계산은 일반 로직. AI는 대화 조건 정리와 이유 설명. 운영 정보가 없으면 확인 필요로 유지.

03 · 먼저 작게 검증

“나 없는 사이 뭐가 바뀌었지?”

긴 대화를 다시 읽는 대신 현재 확정 / 새 제안 / 아직 안 정한 것을 비교합니다. 단순한 최신 메시지가 아니라 실제 약속 상태를 기준으로 봅니다.

예: 현재 오후 2시 → 대화에 3시 제안 → ‘시간 변경 의견이 있지만 아직 적용 전’. 원문을 확인하고 주최자가 변경합니다.

위치: 약속 재진입 / 대화 상단 / 알림 상세

현재 약속 revision·근거 메시지. “어때요?”를 확정으로 취급하지 않으며 예약·참석을 자동 변경하지 않음.

04 · 먼저 작게 검증

“그 얘기, 준비물로 남겨둘까요?”

대화에 흘러간 준비물·확인 요청·자원한 일을 찾아 항목으로 제안합니다. 부탁한 사람과 실제 맡은 사람을 구분합니다.

예: ‘민수님 돗자리 부탁해요’ → 담당 요청 카드 → 항목 등록 → 민수가 맡을게요를 눌러야 담당 확정. ‘제가 사진 찍을게요’도 원문 근거와 함께 등록 후보로 둡니다.

위치: 약속 대화 → 준비 탭

개별 항목 선택·담당자 수락·기한 확인. 외부 발송이나 예약 실행까지 자동 연결하지 않음.

05 · 첫 참여를 돕는 기능

“처음 가는 사람 모드”

승인된 소개·공지·현재 약속에서 처음 오는 사람이 알아야 할 것만 정리합니다. 개인적인 불안·성격을 추론하지 않습니다.

예: 혼자 가도 되는지, 만나는 표식, 준비물, 예상 비용, 확인할 질문. 근거가 없으면 질문 초안을 만들고 사용자가 보냅니다.

위치: 모임 가입 후 / 첫 약속 상세

공개·멤버 권한에 맞는 안내만 사용. 비공개 옛 대화를 새 멤버에게 요약해 우회 공개하지 않음.

06 · 데이터 연결 후 확장

“비 오면 이 안으로”

비·휴무·지각처럼 사용자가 선택하거나 확인된 상황에 맞춰 기존 안과 바뀌는 부분만 비교하는 대안을 만듭니다.

예: 야외 산책 대신 이미 공유한 실내 장소 후보. 고정 숙소·예약은 보호하고, 불확실한 영업·경로 정보는 확인 전 적용하지 않습니다.

위치: 약속 일정 → 대안 비교

지도·영업·날씨 연결 또는 사용자의 직접 확인. 방문 수 자동 축소·무단 삭제 기능을 되살리는 방향이 아님.

07 · 다시 모이게 하는 기능

“지난번 좋았던 방식으로 또 만날까?”

사용자가 남긴 후기·다음에 하고 싶은 것에서 다음 약속 초안을 만듭니다. 좋은 기록이 다음 만남의 소재가 됩니다.

예: ‘다음엔 덜 걷고 카페를 오래’라는 후기 → 이전 동선의 형식과 선택한 장소를 재사용 → 새 날짜 후보. 지난 참석·예약·준비 완료는 복사하지 않습니다.

위치: 지난 약속 / 후기 작성 후 / 모임 홈

명시적 후기와 공유된 기록. 오래된 정보 확인, 새 회차 초대·참석 재확인.

08 · 글로벌 운영

“언어는 달라도 같은 약속”

다국어 대화의 날짜·시간대·장소명·준비 요청을 같은 약속 카드에 연결하고 원문을 함께 둡니다.

예: 해외 참가자의 ‘Saturday afternoon’을 정확한 날짜·현지 시간대로 확인. 말투 번역만으로 예약·참석 의사를 단정하지 않습니다.

위치: 대화 번역 / 약속 안내 / 초대 링크

언어·시간대·지명 ID 확인. 뜻이 애매하면 되묻고 건강·관계·성향을 추론해 저장하지 않음.

대표 기능으로는 ‘우리 모두 가고 싶던 곳’과 ‘합의 카드’를 권합니다.

요약은 대화가 많은 서비스의 기본 편의로 두고, 관심 장소가 함께 갈 약속으로 바뀌는 순간을 Spotlog의 핵심 경험으로 만드는 제안입니다. 초기 구현은 검증이 쉬운 ‘변경점’과 ‘준비 항목 제안’부터 시작합니다.

07 · AI 결과를 판단할 수 있는 예시

채팅을 그냥 줄이는 것과, 실제 할 일을 돕는 것은 다릅니다.

가상 대화와 직접 작성한 결과 예시입니다. 실제 AI 실행·회원 분석·일정 변경은 없습니다. 아래 선택은 결과 표현만 전환합니다.

레이아웃 완료 기준

  • 내가 어느 모임·약속 안에 있는지 계속 알 수 있음.
  • 뒤로 가기를 반복하지 않고 같은 공간의 탭으로 이동.
  • 공지·대화 정리·입력에 스크롤 중에도 접근 가능.
  • 목록 출처는 제거하고 필요한 상세·사진에서는 확인 가능.

처음 출시 범위에 넣지 않을 것

  • 결제·티켓 판매·예약 대행·자동 참가 확정.
  • AI가 개인 장소 목록·일정 전체를 무단 분석하는 기능.
  • 성격·건강·관계 평가로 멤버를 점수화하는 기능.

  • 각 서비스의 모든 채널·클래스·피드를 합치는 구조.

현재 산출물은 조사·설계 검토본입니다. 고객/관리자 소스와 사용자 저장 자료는 수정하지 않았으며 Git 업로드·배포도 하지 않았습니다. 실제 앱 구현은 이 구조 검토 뒤 별도 진행합니다.

09 · 근거와 범위

무엇을 직접 봤고, 무엇을 문서로 확인했는가
